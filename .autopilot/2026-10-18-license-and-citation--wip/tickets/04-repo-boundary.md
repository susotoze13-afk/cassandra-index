# 04 — Граница публичного ядра и коммерческого модуля

**Требования:** R08, R08i, R08ii
**Зависит от:** 01
**Зона:** `docs/adr/0056-*.md` · `docs/repo-boundaries.md`
**Волна:** 2
**Ревью:** нет
**Модель:** обычная

## Что должно заработать

У владельца есть записанное решение: этот репозиторий — публичное ядро, коммерческий модуль
живёт отдельно, и есть процедура, по которой он уезжает туда, когда появится. Любой
следующий агент или человек, открывший репозиторий, не принесёт закрытый код сюда.

## Из брифа, дословно

> «Развести public core и будущий commercial module по разным репозиториям.»

## Разделы спецификации

Истории 23–25; «Решения по реализации» (абзац про ADR 0056); `interfaces.md` §7.

## Критерии приёмки

- [ ] `docs/adr/0056-repository-boundary-public-core.md` существует, номер свободен
      (следующий после 0055), структура как у соседних ADR (контекст / решение /
      почему / последствия)
- [ ] ADR фиксирует: публичное ядро = сайт, расчётный пайплайн, данные, тесты и
      документация в этом репозитории под Apache-2.0 / CC BY 4.0; коммерческий модуль =
      отдельный репозиторий; направление зависимости — закрытое зависит от открытого,
      не наоборот
- [ ] `docs/repo-boundaries.md` содержит два списка: что остаётся здесь (расчёт, данные,
      сайт, публичный экспорт, тесты, governance) и что обязано уехать (платные функции,
      приватные интеграции, бизнес-правила, ключи и клиентские данные)
- [ ] В документе есть процедура переноса из четырёх шагов: создать приватный
      репозиторий → перенести только закрытые части (не копируя `calc/`, `js/`, `data/`) →
      подключить публичное ядро как зависимость (копия релиза или подмодуль на тег
      `v<VERSION>`) → проверить, что закрытый репозиторий собирается без правок в публичном
- [ ] Документ не противоречит ADR 0028/0050 (таксономия и публичная схема остаются здесь)
      и ссылается на них
- [ ] `node --test` зелёный (правка только документации)

## Подсказки

- Стиль: `docs/adr/0055-digest-subscription-via-existing-form.md` — короткие разделы,
  без воды.
- Не создавать никаких каталогов вроде `commercial/` — их запрещает тест таска 01.
