# Спецификация: Предпродакшен — решения по открытым вопросам (Cassandra Index)

## Задача

Владелец сервиса должен перед продакшеном закрыть Go/No-Go блокеры: журнал калибровки на
исторических якорях, жёсткий порог «недостаточно данных», утверждённая таксономия и RACI,
приватность по IP и исправленные формулы. Без этого запуск запрещён самим решением заказчика,
а текущий сайт расходится с методологией v0.7: не реализованы ореол неопределённости, статус
глобального фона слепых регионов, severity-веса, новая схема источников, согласие на регион,
а в одном из демо-текстов региона есть слово «вероятность».

## Решение

Закрыты все шесть блокеров B1–B6 как артефакты репозитория: расширенный журнал калибровки
на 8 якорях с новым k (публично на сайте), пороги покрытия в движке и публикации,
governance-документ с ролями/RACI/кластерами/провайдером, протокол приватности в privacy.html
и согласие на регион, патчи формул доведены до конца (severity в схеме входа и детекторе
Flash-триггеров). Сайт честно показывает неопределённость: бейдж качества данных, пометка
«Предварительная оценка», исторический снапшот вместо замаскированной инерции. Учтено, что
три демо-недели при покрытии 5/45 критериев попадают в `insufficient` — hero покажет
последний валидный снапшот (08-23), а не пересчитанные 60/58/57.

## Контекст, обнаруженный при чтении репо (меняет форму работ, не требования)

- METHODODOLOGY.md в репо — **v0.7**, а не v0.5, как предполагал бриф: патчи 7.1 (Д8 вне
  знаменателя, §5 шаг 2), 7.2 (потолок Д9 с U_abs при S=0, §4.3.5), 7.4 (региональная модель
  отклонения, §7) уже в методологии и движке дословно в форме брифа. Патч 7.3 (severity
  ∈ {0.2, 0.5, 1.0, 2.0}) описан в методологии (§4.1), но во входной схеме отдельного поля
  нет — severity свёрнут в нормированное value. R64–R67 закрываются верификацией тестами
  + достройкой severity; расхождения форм чинятся.
- §9 методологии уже содержит все 8 исторических якорей из брифа; в `calc/input/anchors/`
  смоделированы только 6 профилей (нет able-archer-1983, kargil-1999, yom-kippur-1973,
  iraq-2003). R02–R04 = 4 новых профиля + перекалибровка + журнал.
- Формула брифа 7.2 `min(ρ/(1−ρ)·S + U_abs, U_abs)` вырождается; реализованная в движке
  форма `U = min(U_raw, ρ/(1−ρ)·S + U_abs)` — осмысленна и соответствует интенту
  «Д9 не обнуляется при S=0». Зафиксировано как принятое решение (ASSUMPTION A2), U_abs
  остаётся калибруемым параметром (сейчас 0.025 в единицах сырого скора).
- Сайт расходится с методологией v0.7 (ореол 1−q §5.3, статус фона §7, Precursor §4.3.6,
  Flash Alert §2.1, тип источника §3.1 — не реализованы) — это и есть объем сайтовой части.
- В тексте `data/.../region-europe.js` есть слово «вероятность» — будет исправлено (R06).

## Решения по реализации

Стек не меняется: чистый HTML/CSS/JS, ноль зависимостей, Node ≥ 18, ESM (сборщик CommonJS).
Все новые числа — в params (единственный источник параметров). Все новые строки — в словаре i18n.

1. **Пороги покрытия и insufficient** (R11–R15). Движок уже считает q по весам×уверенность;
   `nullWeight = 1 − q`. Классификация публикации: `nullWeight > 0.4` или null Д1/Д2 →
   `dataState='insufficient'`, индекс не публикуется (global=null, контракт допускает null при
   insufficient); `0.2–0.4` → published с `confidence='reduced'`; `<0.2` → полная. Пороги —
   в params (`dataCoverage`), помечены breaking. Инерция: insufficient-неделя не рвёт цепочку —
   следующая валидная считает от последнего валидного internal (состояние несёт CLI-обвязка).
   Прогноз по текущим входам: покрытие 5/45 → три пересчитанные недели станут insufficient,
   hero покажет 08-23 как Historical snapshot — это требуемое брифом поведение, фиксируется
   в спеке осознанно.
2. **Severity** (R66). Счётные критерии входа могут нести `events: [0.2, 0.5, 1.0, 2.0]` вместо
   готового `value`; движок нормирует `value = min(1, Σsev/CAP)` (CAP=5 из params), старые входы
   с `value` — как раньше. Детектор Flash: событие sev=2.0 на Д1.4/Д2.4 или Д7.3=1 → запись
   в audit log, снапшот не меняется.
3. **Аудит** (R35–R37). Новый модуль аудита: append-only JSONL, каждая запись — 9 обязательных
   полей + `prev_hash`/`hash` (sha256). Три типа записей: recalc (пересчёт недели), flash
   (триггер алерта), methodology (смена версии). verify-проход пересчитывает цепочку.
   Метаданные recalc (дата, причина, прежнее значение, версии до/после) дублируются в снапшот —
   сайт показывает справку по клику на «Historical snapshot». Файл журнала живёт в data/,
   версионируется в git (baseline+delta: сам журнал и есть последовательность дельт).
4. **Источники** (R55–R57, R21–R23). Схема источника: обязательные `id, title{ru,en}, domain,
   url, publication_date, accessed_date, source_type(primary|secondary|OSINT), cluster_id(A–F),
   state_affiliated(bool)`; опциональные `author, archive_url, archive_date, confidence, notes`.
   Вход может нести top-level `sources` с полными записями — валидация строгая, отсутствие
   обязательного поля = ошибка пайплайна; без top-level sources снапшот сохраняет существующие
   (ручные демо). Все демо-снапшоты мигрируются на новую схему. Сортировка тип→дата→домен —
   в обоих местах вывода (история, аккордеоны драйверов); свёрнутость — sessionStorage с
   30-минутным expiry.
5. **Кластеры** (R21–R23). Whitelist: A=mainstream (Reuters/AP/Bloomberg), B=state-media,
   C=registries, D=satellite-osint, E=field-osint, F=financial. Критерий входа хранит
   `cluster` из whitelist; иное — ошибка валидации. state_affiliated=true — правило
   независимости в governance и предупреждение валидации при короборации одним кластером.
6. **ICU-плюрализация** (R62). Собственное подмножество ICU MessageFormat в i18n: интерполяция
   `{var}`, `{n, plural, one{…} few{…} many{…} other{…}}`, `{x, select, …}`; CLDR-правила RU
   (one/few/many, дробные → other) и EN (one/other). Все `;`-строки мигрируются. Старый split(';')
   удаляется. Обоснование: react-i18next несовместим с нулевыми зависимостями; интент брифа —
   ICU-синтаксис и тесты форм — сохранён (ASSUMPTION A3).
7. **Регионы и согласие** (R31–R34, R38, R48–R51). Версионированный справочник (JSON в data/,
   читается сайтом): 6 макрорегионов → списки ISO 3166-2, админцентры, политика спорных
   территорий (нейтральная формулировка), версия методологии. Источник городских данных —
   GeoNames (координаты/население/иерархия), маппинг город→регион через `admin1_code`,
   приведённый к ISO 3166-2; полный импорт городов — при подключении edge-слоя, сейчас —
   админцентры 6 регионов, формат справочника под импорт готов. Часовой пояс остаётся
   единственным детектом (сайт статический); лестница уверенности — чистая функция с тестами,
   готовая к edge-слою, две оси: город (cityConf ≥80% город; 50–80% админцентр; <50% без
   города) и регион (regionConf ≥90% регион; <90% только страна; страна не определена или
   любая ось <50% → глобальный индекс). Согласие: до region_consent регион не определяется и
   не сохраняется; toast с «Изменить» → пикер; opt-in для всех (A4 — без бэкенда нельзя
   отличить EU от US; это строже opt-out брифа). Ветка opt-out для US/остального мира
   фиксируется в governance как обязательное поведение будущего edge-слоя: при определении
   юрисдикции не из EU/UK/РФ регион определяется автоматически с возможностью отключить.
8. **Качество данных** (R59–R61). Бейдж в hero из q (пороги 0.8/0.6 в params-словаре сайта);
   клик открывает модалку: q, покрытие по 9 драйверам, формула словами. При q<0.6 — пометка
   «Предварительная оценка». При insufficient — состояние из баннера, hero на last valid.
9. **Тренд** (R58, R63, R28). Точки несут methodology; разрыв серии при смене версии.
   Desktop: hover/focus tooltip (без автоскрытия при фокусе); touch: bottom sheet
   (focus-trap, Escape, возврат фокуса). aria-label «Дата: X, Индекс: Y, Состояние: Z»,
   aria-describedby со сводкой, sr-only таблица, aria-live при навигации точками.
10. **Breaking-баннер** (R26–R28). Снапшоты несут methodology-версию; при смене между неделями
    — баннер со ссылкой на changelog-раздел methodology-секции; журнал калибровки — публичный
    артефакт на сайте (новый блок methodology-секции, данные из data/, чтобы попасть в деплой).
11. **Лексика** (R05–R10, R53). Новый тест лексики: словарь i18n + тексты демо-снапшотов
    сканируются на «вероятность», «шанс», «процент риска», «обратный отсчёт» (+существующий
    avoid-список: «на пороге», «на грани», метафоры часов). H1 hero — утвердительный;
    дисклеймер «Оценка состояния, а не прогноз даты» в hero-legal. Текст region-europe
    исправляется. Методология: §1.1 дополнить сноской про CDF; §11/§13 закрыть открытый
    вопрос порога покрытия.
12. **Калибровка** (R02–R04). 4 новых якорных профиля по образцу существующих (тип, target,
    rollingOrigin, note с обоснованием). calibrate.js: сетка по 8 select-якорям (verify —
    проверка), выбор k максиминным запасом, sensitivity ±20 %, журнал переписывается:
    8 якорей × (роль, тип кризиса, источник данных, целевой диапазон, обоснование, итог).
    Подбор итеративный до выполнения ВСЕХ попаданий (R04): итерация 1 — k по сетке;
    при промахах — итерации по весам/порогам в пределах §10.1 методологии (rolling-origin,
    критерий — максиминный запас), каждая итерация фиксируется в журнале. Если после
    исчерпания сетки §10.1 попадания не достигнуты — фиксация промахов в журнале и эскалация
    на Review Board (открытый вопрос, не тихий компромисс). После выбора параметров —
    пересчёт цепочки недель и запись снапшотов (недели станут insufficient — см. п.1).
13. **Governance** (R17, R30, R33, R39–R41, R52, R54, R68i). docs/preproduction-decisions.md —
    текст брифа дословно. docs/governance.md — роли (Editor-in-Chief Accountable, Methodology
    Editor, Data Governance Lead, Review Board, расчётная команда), RACI Flash Alert + SLA 2 ч,
    правило отзыва 24 ч, whitelist кластеров, провайдер гео (MaxMind GeoIP2 Ent, fallback
    IP2Location, SLA 99.9%/<50 мс), пороги IP как breaking, политика спорных территорий,
    протоколы приватности (сырой IP не логируется; хэш с солью; region-код только; 24 ч),
    критерий брака копирайта (>20% «время/осталось/таймер»), термин «Cassandra Index: Global
    Conflict Anomaly Score», обязательность юрэкспертизы 152-ФЗ (открытый блокер — в отчёт).
14. **Версия методологии.** Патчи severity/пороги/8 якорей + новое k = ломающие изменения
    (§10 v0.7): версия поднимается до «2.0», история версий дополняется, список breaking
    дополняется новыми пунктами (пороги покрытия, схема источников, severity-поле, кластеры
    A–F как whitelist).

## Границы и швы

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `engine` (calc) | формулы §4–§7, validate входа | `driverScore, d8Strength, aggregateD9, aggregateDrivers, applyInertia, detectStructuralBreak, regionalIndex, stateOf, validate, CRITERIA` + новое `normalizeCriterion` (events→value) | нормировки, кривую, hash-цепочку |
| `params` (calc) | все числа | `PARAMS, list()` + новые поля (dataCoverage, severityValues, capCount, qualityThresholds, ipConfidenceLadder, clusters, flashTriggers) | — |
| `audit` (calc, новый) | append-only журнал | `append(record) -> {id, hash}`, `verify() -> {ok, brokenAt}`, `read()` | sha256-цепочку, формат JSONL |
| `calibrate` (calc) | калибровка k | `buildDrivers, runAnchor, evaluateGrid, selectK, sensitivity` (без смены сигнатур — расширение якорей данными) | сетку |
| `calc-cli` | прогон недель | цепочка RECALC_WEEKS, запись снапшотов, классификация публикации, вызовы audit | состояние цепочки |
| `data-contract` (js) | контракт снапшота | `validate, week, latest, listWeeks` — расширено: global nullable при insufficient, sources по новой схеме, recalc-метаданные, q/confidence | дефолты |
| `i18n` (js) | словарь, ICU-плюрализация | `t(lang, key, vars)` с ICU, `plural` (CLDR RU/EN), `date` | парсинг ICU |
| `region` (js) | детект региона, согласие, справочник | `detect, search, current, choose, consent state (grant/dismiss/status), representative(confidence, region)` (новое), `reference` (новое) | storage-ключи |
| `sections/*` (js) | рендер 7 секций | существующие чистые швы + новые: `qualityBadge(q)`, `trendPointLabel`, сортировка источников | DOM |
| `lexicon-test` (tests, новый) | контент-ревью строк | сканер словаря и снапшотов | список запрещённых слов |

Швы для тестов (явно): `engine` (чистые функции — основной шов), `data-contract.validate`,
`i18n` (t/plural ICU), `region` (consent + representative), `audit` (append/verify). Идеал —
engine; новые швы добавлены только где требование это прямо предполагает (ICU, лестница,
аудит). Сайт vs calc не сцеплены напрямую: сайт читает только data/.
