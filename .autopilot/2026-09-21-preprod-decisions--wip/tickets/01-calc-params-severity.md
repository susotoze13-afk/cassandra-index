**Требования:** R15, R20, R21, R22, R23, R55 (часть — схема/валидация), R64, R65, R66, R67

## Что должно заработать

Вход недели может нести счётные критерии списком событий с severity-весами,
движок нормирует их по CAP; валидация входа проверяет источники по новой обязательной
схеме и whitelist кластеров A–F; в PARAMS появляются новые параметры (пороги покрытия,
severity, кластеры, flash-триггеры); детектор Flash-триггеров — чистая функция движка.
Патчи 7.1/7.2/7.4 из брифа **уже реализованы** в engine — задача таска: тесты, доказывающие
соответствие формулам, и достройка severity (7.3 во входе).

## Из брифа, дословно

> «7.3: вклад = Σ sev_i / CAP, sev_i ∈ {0.2, 0.5, 1.0, 2.0}»
> «JSON Schema с валидацией при ingestion. Отсутствие обязательного поля — ошибка пайплайна»
> «2 источника считаются независимыми, только если они из разных кластеров»
> «Триггеры: Д1.4, Д2.4 (severity 2.0), Д7.3»
> «Порог 40% и условия по Д1/Д2 фиксируются в методологии как breaking-параметры»

## Разделы спецификации

Истории 1–6, 14–15, 17–18, 20–21, 49–50; Решения §1, §2, §5, §14.

## Детали

- `params.js`: новые поля — `capCount: 5`, `severityValues: [0.2, 0.5, 1.0, 2.0]`,
  `dataCoverage: { insufficient: 0.4, reduced: 0.2, d1d2Required: true }`,
  `clusters: ['A-mainstream','B-state-media','C-registries','D-satellite-osint','E-field-osint','F-financial']`,
  `flashTriggers: { criteria: ['D1.4','D2.4'], severity: 2.0, d7Value: 1 }`,
  `qualityThresholds: { high: 0.8, medium: 0.6 }`, `ipConfidenceLadder` (city 80/50, region 90, floor 50).
  Все с комментарием «breaking-параметр» где применимо.
- `engine.js`: новый экспорт `normalizeCriterion(entry, params)` — из `events: [sev…]`
  считает `value = min(1, Σsev/CAP)`; события вне severityValues → ошибка валидации.
  Новый экспорт `detectFlashTriggers(criteria, params)` — true при событии sev=2.0 на
  Д1.4/Д2.4 или value=1 по Д7.3 (для бинарного критерия — сам критерий, событий нет).
- `validate(input)`: criteria-источники — обязательные `url, date, cluster` (как раньше)
  плюс опциональные `type ('primary'|'secondary'|'OSINT')`, `state_affiliated (bool)`;
  `cluster` проверяется против whitelist из params-кластеров (существующие входы/якоря
  используют старые имена — мигрировать ВСЕ файлы calc/input/**/*.json на новые id
  кластеров в этом таске); критерий может нести `flash_origin: bool`; счётный критерий —
  либо `value`, либо `events` (не оба, не ни одного); `events` — массив чисел из
  severityValues, длина ≤ capCount*2.
- Тесты: ручной пересчёт w′ (формула §5 шаг 2, Д8 вне знаменателя); S=0 + ≥2 сигналящих
  подгрупп Д9 → I_agg>0 (U_abs), 1 подгруппа → U_abs не применяется; severity:
  events [0.5,2.0] → 0.5, [2,2,2] → min(1, 1.2)=1.0; normalizeCriterion для всех
  четырёх severity; детектор: Д1.4 events [2.0] → true, [1.0] → false; Д7.3 value=1 → true;
  валидация: отсутствие обязательного поля источника → ошибка с путём; кластер вне
  whitelist → ошибка; flash_origin не bool → ошибка; старые входы (без events/type) —
  валидны (обратная совместимость).
- КРАСНЫЕ ТЕСТЫ: любое поведение движка, расходящееся с формулами §5/§4.3.5/§7 v0.7,
  чинится в этом таске и фиксируется тестом.
