# Спецификация: публичный слой — как читать, забрать данные, получить дайджест

## Задача

Человек впервые попадает на cassindex.ru и видит число 64 и слово «очень опасно».
Он не понимает, что означает это число, чего оно не означает, откуда взялось и можно ли
на него сослаться в статье. Аналитик хочет забрать ряд в свою таблицу — ему нечего
скачать. Читатель, который уже понял индекс, не возвращается: у проекта нет недельного
ритуала. Журналист ищет «индекс конфликтного риска» и «отличие от ACLED» — и находит
конкурентов, а не этот проект.

## Решение

На сайте появляется четыре новых поверхности, и у каждой один и тот же смысл — сделать
индекс **читаемым, забираемым и цитируемым** без единого нового сервера:

1. **«Как читать индекс»** — одна страница, которая за пять секунд отвечает: что это
   за число, что изменилось, почему, чего оно не значит, как его цитировать.
2. **Публичные данные** — `index.json` / `latest.json` / `cassandra-index.csv` по
   стабильным адресам, с версией схемы в самом файле, и **changelog** — что и когда
   менялось в методологии, таксономии и полях.
3. **Недельный дайджест** — «что изменилось за неделю»: 5 пунктов, 3 региона, ссылка на
   кривую; уходит в Telegram-канал и на email; у каждого выпуска есть публичный архив.
4. **Страницы сравнения** — честное «чем Cassandra отличается от War Monitor / ACLED /
   CrisisWatch», плюс `sitemap.xml` и `robots.txt`, чтобы эти страницы вообще нашлись.

Ничего не отправляется и не публикуется в этой сборке: доставка собирается с
`--dry-run` по умолчанию, живой выпуск — отдельное действие владельца.

## Решения по реализации

- **Экспорт — производная от `data/<week>/week.js`**, не второй расчёт: `calc/public-export.js`
  читает части через существующий `loadWeekParts` и проецирует. Почему: единственный
  источник чисел, R16i становится проверяемым одним тестом.
- **Проекция узкая и документированная**: `week, published, through, methodology,
  regions_taxonomy, data_state, index, delta, state, q, confidence, coverage_criteria,
  regions[{id,index,delta,background}], precursor|null, drivers[{label,contribution}],
  sources{count,clusters,state_affiliated}, trend[12]`. Почему: полный `week.js` уже
  публичен, но не пригоден для машинного чтения; источники — счётчиками, чтобы не
  публиковать вторую копию 82 записей.
- **`state` считается `engine.stateOf(index)`** — одна шкала для сайта и данных
  (запрещено дублировать пороги).
- **CSV — один файл, строки = неделя × область** (`scope` = `global` | id региона),
  колонки фиксированы и перечислены в шапке; разделитель `,`, UTF-8 без BOM, `\n`.
  Почему: одна ссылка для таблиц, без двух форматов.
- **Changelog — курируемый список** `calc/changelog-entries.js` + сериализация в
  `data/public/changelog.json`; страница `changelog.html` статическая, тест сверяет
  даты/версии с JSON. Почему: `data/audit.jsonl` — внутренний журнал (в выкат не идёт)
  и говорит про пересчёты, а не про смысл изменений.
- **Дайджест — чистый `buildDigest(snapshot, opts)`** → `{subject, text, html, telegram,
  meta}`; доставка отдельным `calc/digest-send.js` с инъекцией `fetchImpl`. Почему:
  текст проверяется без сети, отправка — без правок текста.
- **Провайдер email — HTTP-эндпоинт** (`DIGEST_EMAIL_ENDPOINT`, `DIGEST_EMAIL_TOKEN`,
  `DIGEST_EMAIL_FROM`, `DIGEST_EMAIL_TO`): SMTP-клиента в stdlib нет, зависимостей не
  заводим. Провайдер не выбран — это заглушка, см. «Открытые места».
- **Telegram — Bot API** (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`), `parse_mode: HTML`,
  текст экранируется. Канал/бот не заведены — заглушка.
- **Подписка без бэкенда**: тема «дайджест» в существующей форме (`FEEDBACK_TOPICS` +
  ключи), владелец вручную добавляет адрес в секрет `DIGEST_EMAIL_TO`. Почему: сбор
  адресов на статике без сервиса невозможен, а выдумывать бэкенд нельзя.
- **Страницы сравнения и «Как читать» — статический HTML с текстом в разметке**, без
  i18n-рантайма и без бандла: иначе краулер без JS и читатель без JS не увидят текста.
  Это осознанное исключение из правила «вся строка — через `js/i18n.js`» (правило
  остаётся для приложения). Слова проходят `tests/lexicon.test.js` (страницы
  добавляются в его скан).
- **Никакого JSON-LD**: meta-CSP страниц без inline-скриптов (`script-src 'self'`),
  структурированные данные не стоят ослабления CSP. Вместо них — `meta description`,
  OG-теги, семантическая разметка и видимый FAQ.
- **`latest.json`** — тот же объект последней недели, один файл для встраивания:
  `https://cassindex.ru/data/public/latest.json`.
- **`changelog.html` и `digest.html` генерируются** из данных при `--write`; руками не
  правятся (как `week.js`), тест паритета ловит расхождение.
- **Публикация**: новые страницы, `robots.txt`, `sitemap.xml` добавляются в
  `cp`-список `deploy.yml`; тест сверяет корневые `*.html` с этим списком.

## Вне рамок

| Требование | Почему не сейчас |
|---|---|
| Самостоятельная подписка с подтверждением (double opt-in) и отпиской | нужен бэкенд или сервис рассылки; сейчас заявка через форму и ручное добавление |
| Английская версия страниц и дайджеста | отдельная сборка (P1 дорожной карты) |
| Бэктест против ACLED/GPR и публикация расхождений | P1, 2–4 недели, отдельный прогон |
| Pro-API с алертами и SLA | P2; публичный JSON — статический файл, не API |
| RSS/Atom лента | не просили; JSON-архив выпусков закрывает машинное чтение |
| Отдельные URL под недели и регионы (HTML) | сейчас `?week=`; SPA-роутинг статики не даёт честных страниц |
