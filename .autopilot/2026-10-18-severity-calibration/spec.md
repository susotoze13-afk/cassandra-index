# Спецификация: калибровка severity-весов (грид severity-наборов)

## Задача
Веса severity-уровней событий §7.3 (`severityValues = [0.2, 0.5, 1.0, 2.0]`
в `calc/params.js`) — эвристические: не прошли
через калибровочную машину, которую прошёл k (грид, rolling-origin,
verify-якоря, чувствительность, журнал). Нужна оценка той же машиной
с честным выводом: «набор подтверждён» или «выбран более устойчивый
кандидат».

## Решение
- Прогон weeklists-consolidation упомянут в брифе как уже сданный
  (коммит `ccaf356`) — в этой сборке не повторяется; задача этой спеки —
  только severity.

Калибровка severity работает по реальной цепочке недель (решение
пользователя — ветка 1; якоря severity не дифференцируют: все 10
`calc/input/anchors/*.json` заданы `{value}` без `events[]`). Прогон:
грид кандидатов severity-наборов → in-memory прогон цепочки 08-30…10-18
каждого кандидата → метрика max|ΔI| против базового прогона → выбор.
Роль verify-якорей переинтерпретирована осознанно (Дополнение ↓, ветка 1):
на якорях грид не дифференцируется, поэтому якоря — severity-инвариантная
проверка при выбранном наборе, а не источник выбора.

- Выбранный набор применяется в `PARAMS.severityValues` (решение
  пользователя — «примени выбранный»). Если выбран базовый — числа
  не сдвигаются, пины не трогаются, журнал фиксирует подтверждение.
  Если выбран не-базовый — пересчёт цепочки `--write` и актуализация
  пинов `tests/data.test.js` / `tests/sensitivity.test.js` (R06i).

### Уточнения по факту сборки (D01–D03)
- **D01** (T01): метрика выбора — не maxDrift (у базового структурно 0),
  а устойчивость кандидата к своей ±20 %-пертурбации (`sens`); maxDrift
  остаётся информационной колонкой. Порог применения 5 п.п. и tie-break
  базовый — без изменений.
- **D02** (T01): у якорей нет `events[]` — подтверждено кодом; severity
  на якорях инвариантна (проверка 10/10), k = 1.95.
- **D03** (F1, ревью): шаг недели копировался в calibrate.js — выделяется
  в `calc/week-step.js` и вызывается из обоих; цепочка импортов
  calc.js ↔ calibrate.js снимается выносом `buildDrivers` в engine.js.

## Решения по реализации
- Грид «небольшая сетка соседних пар» (решение пользователя): сдвиг пары
  масштабирует оба члена множителем; защиты — строгая монотонность и
  сохранение 2.0 на этапе генерации.
- Оценка кандидата: ремап событий по порядковой позиции уровня базового
  набора, прогон цепочки шаблоном calc.js без записи, метрика против
  базового, tie-break — базовый.
- Если во входах есть веса вне базового набора — отчёт печатает это как
  находку; кандидаты, чей ремап не покрывает все события, отбраковываются
  явно.
- Бандл не пересобирается: `js/**` не трогаются (сайт severity не читает).
- CLI: `node calc/calibrate.js --severity` печатает таблицу для журнала;
  дефолтный прогон без аргумента сохраняет образцу k-only (не ломает
  привычный вывод и CI-расписание).
