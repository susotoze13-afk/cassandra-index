# 02 — Метрика чувствительности недели (sensitivity)

**Требования:** R02
**Blocked by:** 01 (ворота должны уже стоять — пересчёт уходит в тот же `runWeek`)
**Зона:** `calc/engine.js` (или новый `calc/sensitivity.js`) · `calc/calc.js` · `js/data.js` · `tests/`
**Волна:** 1
**Status:** ready

## Что должно заработать

Чистая функция: пересчёт индекса недели (а) при исключении каждого домена
по очереди, (б) при исключении каждого кластера по очереди; выход — одно число
`sensitivity` = max|ΔI| в процентных пунктах из двух тестов. Критерий, лишившийся
всех источников, становится непокрытым (как при ручной правке входа). Считается в
`calc.js` при `--write` (без сети), пишется как **опциональное** поле quality-блока
снапшота; `validateQuality` в `js/data.js` принимает поле как необязательное —
старые недели без него валидны (A3).

## Из брифа, дословно

> «у тебя нет достоверной выборки» — численный ответ: выкидывание любого домена/кластера двигает индекс ≤ порога

## Разделы спецификации

Протокол Q5, Q11, Q17, Q21; ADR 0019.

## Критерии приёмки

- [ ] функция детерминирована, ноль зависимостей, шов для тестов
- [ ] неделя с доменом-монополией (тестовый вход) даёт большой `sensitivity` — проверено тестом
- [ ] поле опционально: `validate`/`validateQuality` без поля — ок, с полем — ок
- [ ] `calc.js --write` кладёт `sensitivity` в снапшот; печать без `--write` показывает расчётное значение
- [ ] тесты добавлены, `node --test` зелёный
- [ ] НЕ коммитить — коммит за оркестратором; правки только в «Зоне»
