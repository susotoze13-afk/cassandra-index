## Что должно заработать

Ревью ветки нашло два дефекта. Первый: исключение подгруппы Д9 с пересечением
выполняется дважды — сначала фильтром, потом мёртвым вторым проходом `counted`,
который делает вид, что работает. Второй: METHODOLOGY §4.1.5 утверждает, что запись
пересечения «не может обнулить скор драйвера», а код при всех покрытых критериях
с флагом даёт 0 у Д1–Д8 и `null` у Д9 — документ и код расходятся в граничном случае.

Итог: исключение пересечения из Д9 происходит ровно в одном месте, а граничный случай
«все покрытые наблюдения — пересечения» назван в документе и ведёт себя одинаково:
нет нового сигнала → 0 (не `null`: данные собраны, слепым критерий не стал).

## Критерии приёмки

- [ ] В `aggregateD9` нет второго фильтра по `intersection`: пересечения выбывают в одной
      точке, недостижимой ветки `counted.length ? … : 0` больше нет
- [ ] Прогон с подгруппой Д9, помеченной пересечением, даёт тот же результат, что прогон
      с `score: null` у этой подгруппы (тест уже есть — должен остаться зелёным)
- [ ] Все покрытые критерии драйвера — пересечения → скор драйвера 0 (Д1–Д8);
      все покрытые подгруппы Д9 — пересечения → `{score: 0, signaling: 0}`; это
      закреплено тестом
- [ ] METHODOLOGY §4.1.5 называет граничный случай одним предложением и не утверждает,
      что обнуление невозможно
- [ ] `node --test` зелёный целиком; существующие пины не двигаются
