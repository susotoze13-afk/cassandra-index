# Спецификация: Витрина доверия и ступени уровней (ADR 0033)

## Задача

Читатель смотрит на индекс глобального риска и не доверяет ему: непонятно, из чего
сложилось число, кто выбирал источники и насколько им можно верить. Часть механик
доверия в проекте уже есть (кластеры источников A–F, `state_affiliated`, ворота
независимости, короборация Д9, `sensitivity`), но **на сайте их не видно** — показан
только итоговый индекс. Плюс у продукта нет ответа на «индекс вырос — и что с этим
делать?». АDR 0033 лечит это по четырём каналам; этот прогон реализует **фазу 1
«Доверие»** (низкий риск, без правок формул) и откладывает контентную фазу 2.

## Решение

Прямо под первым экраном появится короткая «панель прозрачности»: одна строка фактов
о том, на чём стоит индекс — сколько критериев, сколько источников, сколько
независимых кластеров, сколько регионов остались слепыми и какая методология. Клик
раскрывает честные детали: распределение источников по кластерам, долю
гос/госфинансируемых СМИ («помечены честно», не как обвинение), сколько критериев не
покрыто сигналами недели («нет подтверждающих сигналов в окне недели») и — только
если значение заметно — предупреждение о чувствительности индекса. Числа берутся
из уже существующего снапшота недели; единственное, чего в нём не хватает, —
покрытие критериев, и оно добавляется в пайплайн.

Карточка «Поделиться» уже несёт уровень и недельную дельту — это закрепляется
регрессионным тестом. Контентная секция «Ступени» уровням (фаза 2) и три открытых
вопроса O7–O9 не строятся в этом прогоне.

## Решения по реализации

Стек не меняется: чистый HTML/CSS/JS, ноль зависимостей, ESM в `js/`, CommonJS
`build.js`; правки `js/**` требуют `node build.js`.

- **Новая секция `js/sections/trust.js`** по образцу существующих секций. Регистрируется
  в `js/render.js` (массив `SECTIONS` + импорт + `registerSection`). Секция экспортирует
  **чистый шов** `trustFacts(snapshot)` и `render(appState)`. Почему так: остальные
  секции устроены так же (единственный вход — `appState`, DOM через `el()`/`textContent`),
  а чистый шов `trustFacts` даёт тестируемость без DOM.
- **`trustFacts(snapshot) → объект | null`**. Возвращает:
  `{ criteriaTotal, sources, clusters, blindRegions, methodology, coverage: {covered,total}|null,
  sensitivity: number|null, clusterCounts: [[cluster_id,count]...], affiliated: {count,total} }`.
  `null` — если снапшота/глобала нет. `criteriaTotal` — из статического `js/criteria.js`
  (`CRITERIA_LIST.length`, сейчас 46) — сайт и так его знает, поэтому «46» не тянется из
  снапшота. `coverage` — из `snapshot.coverageCriteria` (нет поля → `null`). `clusters` —
  число различных `cluster_id` среди `snapshot.sources`. `blindRegions` — число записей
  `snapshot.regions` с `background === true` из набора `regionForTaxonomy(snapshot.regions_taxonomy)`.
  `affiliated.count` — источники с `state_affiliated === true`, `affiliated.total` — все источники.
- **Порог чувствительности.** В `trust.js` — константа `TRUST_SENSITIVITY_THRESHOLD = 5`
  с комментарием «= PARAMS.sensitivityThreshold» (как уже сделано в `js/sections/states.js`:
  сайт не читает `calc/`). Паритет с `PARAMS.sensitivityThreshold` пиннится тестом.
- **Покрытие критериев в пайплайне.** `calc/calc.js` уже считает `res.coverage.criteria`
  (число критериев с `covered:true`) и `res.coverage.totalCriteria` (число критериев движка).
  В `writeWeek` эти два числа кладутся в `meta.coverageCriteria = { covered, total }`;
  `renderGlobal` сериализует `s.coverageCriteria` (опционально, только если задано).
  Почему не отдельный расчёт: числа уже посчитаны и сейчас уходят только в строку аудита.
- **Контракт `js/data.js`.** `validateQuality` получает ветку проверки
  `coverageCriteria`: если поле задано — это объект с целыми `covered ≥ 0` и `total > 0`
  (и `covered ≤ total`); иначе ошибка. Поле опционально → старые недели без него валидны.
  `insufficient`-пакет не меняется.
- **Разметка `index.html`.** Между `</section>` hero и критической панелью —
  `<section class="section trust-section" aria-labelledby="trust-title">` с
  `<h2 id="trust-title" class="sr-only" data-i18n="trust.title">` и
  `<div class="section-body" data-section="trust"></div>`. Почему h2 sr-only: строка —
  визуально компактная, но секция остаётся в структуре заголовков для скринридера.
- **Тексты** — только через `js/i18n.js`, ключи `trust.*` (+ переиспользование
  `statusLower.*`), формулировки дословно из ADR 0033. Числа — не «только цветом»,
  тона — через существующие CSS-токены.
- **Раскрытие деталей** — `button` с `aria-expanded`, блок деталей с `hidden`; CSS-класс
  по образцу `.quality-badge` (нейтральная рамка/фон, не риск-тон). Почему `button`:
  секция содержит действие (раскрыть), а не ссылку на другой ресурс.
- **Share.** `cardLayout` уже несёт уровень (`status`/`statusLower`) и дельту. Правка —
  минимальная: закрепить контракт тестом; если формулировку приводим к ADR §5 —
  использовать `statusLower.<id>` без изменения визуального регистра.

## Границы и швы

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `js/sections/trust.js` | представление панели доверия | `trustFacts(snapshot)` (чистый) · `render(appState)` | построение DOM, i18n-ключи, порог, форматирование чисел |
| `js/render.js` | реестр секций | `SECTIONS`, `registerSection(name,fn)`, `renderSection`, `renderAll` | порядок и обвязку вызовов |
| `js/data.js` | контракт снапшота | `validate` (в т.ч. `coverageCriteria`), `week/latest/listWeeks` | правила формы полей |
| `calc/calc.js` | запись снапшотов | `renderGlobal(week,snap,globalOut,meta)`, `loadSnapshotPart(week,file)` | сборку `meta` и расчёт чисел |
| `js/share.js` | карточку share | `cardLayout(lang,snapshot,regionId)`, `drawCard`, `CARD_W/CARD_H` | Canvas-отрисовку |

**Швы для тестов (подмножество границ; предпочитаем существующие):**

1. `trustFacts(snapshot)` — новый чистый шов; всё поведение панели проверяется здесь.
2. `validate(snapshot)` в `js/data.js` — существующий шов контракта (проверка `coverageCriteria`).
3. `loadSnapshotPart(week, file)` из `calc/calc.js` — существующий шов чтения дисковых снапшотов.
4. `cardLayout(lang, snapshot, regionId)` из `js/share.js` — существующий чистый шов (пин уровня и дельты).

Иные модули публичных подписей не получают: панель строит один субагент,
ей не нужен новый внешний API.

## Примечания к покрытию

- **Три документа — это и есть задача, а не ссылки «на потом».** Бриф перечисляет
  `docs/adr/0033-trust-panel-and-levels.md`, `docs/preproduction-decisions.md` (v1.3) и
  `docs/metrics-journal.md` как источник конкретных правок; их содержание разложено
  в R01–R23 выше. Отдельного «переписать эти документы» в брифе нет: ADR и журнал метрик
  уже в дереве, preprod v1.3 — тоже; в этом прогоне они фиксируются как есть (R23i), а их
  открытые пункты (O7–O9) сознательно остаются открытыми (R14–R16).
- **Строка о режимах запуска** (`full/semi/interview/manual`, модификаторы
  `strict/deep/polish`, путь к брифу) — это конфигурация самого автопилота, а не требование
  к продукту; она записана в `.autopilot/state.js` (режим `full`, глубина обычная) и
  в манифест как продуктовое требование не попадает.
- **Разделение на фазы 1/2** и запрет на тему инфошума (R11) — не произвол спецификации,
  а прямые следствия ADR 0033 (§«Последствия», §4, §6); они перенесены из источника.
