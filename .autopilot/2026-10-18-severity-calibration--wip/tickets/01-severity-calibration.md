## Что должно заработать

`node calc/calibrate.js --severity` печатает для журнала: грид кандидатов
severity-наборов (базовый + сдвиги соседних пар ×0.8/×1.2 с защитами
монотонности/2.0), для каждого in-memory прогон реальной цепочки
08-30…10-18 без записи на диск, метрику max|δI| против базового прогона,
итог выбора (базовый при ничьей / лучший кандидат при отрыве ≥ порога
5 п.п.), severity-инвариантную проверку 10 якорей (7 select / 3 verify)
и таблицу чувствительности ±20 %. Если выбран не-базовый кандидат —
`PARAMS.severityValues` получает его, цепочка пересчитывается `--write`,
пины актуализируются.

## Из брифа, дословно

> «расширь `calc/calibrate.js` гридом severity-наборов (rolling-origin
> 7 select / 3 verify, verify-якоря, чувствительность ±20 %, журнал
> `docs/calibration-journal.md`)»; «примени выбранный — иначе прогон
> чисто демонстративный»; «вектора со сдвигами соседних уровней…
> маленькая сетка: сдвиги только соседних пар»; «1» (оценка по реальной
> цепочке недель без целевых индексов).

## Критерии приёмки

- [ ] `severityCandidates(PARAMS.severityValues)` возвращает базовый + корректных кандидатов; пары, теряющие 2.0 или монотонность, отбракованы с пометкой
- [ ] вес вне базового набора в ремапе даёт явную ошибку, не тишину; событие получает вес той же порядковой позиции
- [ ] in-memory прогон кандидата по цепочке не пишет ничего на диск; расхождение от базового прогона считается по всем неделям
- [ ] tie-break: при равной устойчивости остаётся базовый; не-базовый применяется только при отрыве ≥ 5 п.п.
- [ ] отчёт `--severity` включает проверку якорей (10/10, k остаётся 1.95) и таблицу ±20 %; дефолтный прогон без флага не меняется (k-only)
- [ ] `docs/calibration-journal.md`: третий блок по формату прошлых прогонов с точными числами прогона
- [ ] `node --test` 0 fail; при выборе базового пины `tests/data.test.js`/`tests/sensitivity.test.js` не тронуты
- [ ] в diff нет файлов вне зоны: никакие `js/**`, никакие коммиты/пуши от исполнителя
