# Спецификация: ADR 0069 — региональное отклонение по драйверам, дробная точность слоя, методология 4.0

## Задача

Владелец открыл таблицу регионов за неделю 2026-11-01 и увидел: девять регионов
из двенадцати показывают одинаковые «73 из 100» при разных дельтах. Читается это
как ошибка методологии — «все регионы одинаковые». Разбор показал два реальных
дефекта: мера отклонения `iWith − iWithout` измеряет разрежённость подмножества,
а не отклонение региона (у региона с одним сигналом `iWith` — индекс из одного
критерия), и целочисленное округление слипает реальные 72.4…80.0 в «73». Владелец
хочет честный разброс региональных индексов, дробную точность слоя и переход
методологии на 4.0 с пересчётом опубликованной цепочки — не оставлять известную
кривизну в опубликованных неделях.

## Решение

- Региональное отклонение считается **по драйверам**: вклад каждого допустимого
  драйвера (Д1, Д3, Д5–Д8, Д9 только D9.3) — вес × надёжностная доля покрытия ×
  разность регионального и глобального скоров, на постоянном знаменателе; один
  сигнал больше не двигает регион на 10 п.п.
- Объёмное сжатие `m = n/(n+n0)` снято, `PARAMS.n0` удалён; экспозиция `e_r`
  (`eStruct = 0.5` открыто) остаётся множителем.
- Индексы и дельты регионов и стран публикуются **с одной десятичной**
  (73.4, +1.4); глобальный индекс остаётся целым; `delta` без float-артефактов.
- У каждого региона видно поле `signals: n`; регион с `signals < 2` помечен в UI
  как «мало региональных сигналов» — отклонение раскрывается, а не маскируется.
- Секция регионов сортируется по индексу убыванию (личный регион — первой строкой),
  а не по |Δ| — список читается как «где выше риск», а не «где сильнее изменилось».
- Методология 4.0: вся цепочка 08-30…11-01 (10 недель) пересчитана, глобальные
  числа не меняются, публичный слой переходит на `PUBLIC_SCHEMA_VERSION = 2`
  (схемы `integer → number`, каталог `schema/v2/`), в changelog — запись о переходе.

## Решения по реализации

- **Формула** — дословно ADR 0069 §1: допустимые драйверы, `shrink_d` как доля
  покрытых критериев, знаменатель вычисляется из `PARAMS.weights` (сумма весов
  допустимых драйверов = 0.765), обе ноги с epsilon-порогом, clamp ±40.
  Альтернативы (нормировка, `e_r = 1`, самостоятельный индекс, интенсивность,
  целые, forward-only) отклонены в ADR и здесь не пересматриваются.
- **`deltaRegion` считается внутри `attributedSignals`** (там есть полная карта
  критериев, whitelist и неделя), `attributedIndex` читает `r.deltaRegion`.
  Обе функции остаются размерностно-нейтральными — страны наследуют меру и
  дробную точность автоматически (ADR 0067).
- **`round1(x) = Math.round(x * 10) / 10`** в `engine.js` с экспортом; `delta`
  считается от округлённого индекса. Глобальный слой — `roundHalfUp`, без изменений.
- **`stateOf` становится gapless** (`index <= s.max`): это паритет с `js/risk.js
  status()` и устранение дыр на дробях (80.4 → `null`); целочисленное поведение
  не меняется, `PARAMS.states` не меняется.
- **Сортировка:** регионы — по индексу убыванию, при равенстве — по id; личный
  регион переставляется первой строкой в DOM. Страны и `topRegions` дайджеста
  остаются по |Δ| — в брифе менялись только «регионы» (Q2/Q14).
- **Формат** — строго из данных, без `toFixed(1)`; `.0` не навязывается.
- **Тренд:** дефолт версии `'3.0' → '4.0'` в `selectMethodology`/`summaryTextV2`
  (иначе после пересчёта ряд пуст) + обновление пинов. `article-build.js`
  (дефолт фронтматтера статей) не трогается — статьи вне рамок.
- **Публичная версия:** `PUBLIC_SCHEMA_VERSION = 2`, каталог `schema/v2/`
  вместо `v1` (правило `docs/api.md`: смена типа = новая папка), `v1` удаляется
  при регенерации. Это явное решение владельца Q7b, пересматривающее
  «Договорились» прошлой сборки (см. `interfaces.md`).
- **`signals` — опциональное поле** в контракте сайта и в `WEEK_SCHEMA`
  (демо-недели его не имеют); в странах поле уже есть — образец.
- **Аудит:** `recalculation_method` собирается из `PARAMS.methodology`.
- **Схема аудита/статей:** `changelog` — новая запись в начало курируемого
  списка; история записей `3.0` не переписывается.
- **Порядок пересчёта** (R12): `calc.js --write` по цепочке (ворота quotes →
  linkcheck → validate) → `public-export --write` → `digest-export --write` →
  `backtest --write` → `ledger --write` → `build.js` → `node --test` → коммит
  оркестратора. Прерывание — повторным запуском (идемпотентно).

## Вне рамок

| Требование | Почему не сейчас |
|---|---|
| Квартальный реестр `eStruct` | остаётся плейсхолдером 0.5; отдельный ADR (ADR 0069, «Что не входит») |
| Расширение региональных драйверов Д2/Д4 | меняет смысл слоя; ADR 0022 сохраняется |
| Бэкфилл региональных источников ради дифференциации | работа с данными (`docs/source-proposals/**`), не с формулой |
| Дробная точность глобального индекса | ломает сопоставимость ряда без причины (ADR §1) |
| Блог-статьи `docs/articles/**` (кроме структурированного выпуска 2026-10-18) | описывают опубликованные выпуски; правка — редакционное решение отдельно. **Отступление (D01, показано тикетом 01):** структурированный выпуск 2026-10-18 (`data/<неделя>/article.js` + черновик) жёстко связан со снапшотом воротом `tests/article.test.js` — при переиздании недели под 4.0 его числа обновляются в этом прогоне (тикет 02), как раньше обновлялись разборы после пересчётов |
| Пуш в `master` и выкат `deploy.yml` | внешнее действие владельца (carried) |
| `calc/live-check.js` против боевого сайта | после выката; в билде — только офлайн-тест на поддельном fetch |
