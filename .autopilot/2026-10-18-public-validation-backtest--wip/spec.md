# Спецификация: публичная валидация индекса и журнал прогнозов

## Задача

Читатель (исследователь, журналист, скептик) видит на сайте число индекса и не может
проверить, значит ли оно что-нибудь. Он не знает, сходится ли индекс с независимыми
измерениями конфликтности, опережает ли он их, где расходится и почему. Отдельно он не
может проверить, сбываются ли заявленные ожидания: журнала «обещали — получилось» нет
ни у нас, ни у конкурентов.

## Решение

Появляется страница `validation.html`: на ней — сравнение индекса с тремя независимыми
рядами (GPR, ACLED, CrisisWatch), таблица метрик (уровни, дельты, направление, лаг),
список расхождений по периодам и честный раздел «что это не доказывает». Рядом —
публичный журнал прогнозов: ожидание, факт, попадание или промах, промахи показаны
наравне с попаданиями. Всё это пересобирается одной командой из офлайн-фикстур, поэтому
цифры на странице воспроизводимы, а не набраны руками.

## Решения по реализации

- **Язык и стек.** Чистый Node ESM, ноль зависимостей (правило репозитория). Метрики —
  собственные функции, без статистических пакетов: Пирсон, Спирмен, перестановочный тест
  на детерминированном ГПСЧ (LCG с фиксированным seed), согласие знаков, кросс-корреляция.
- **Выравнивание.** Недельный ряд индекса — только недели методологии `3.0`
  (`PARAMS.methodology`), демо-недели 1.0 исключены: сравнение несопоставимых методик
  запрещено. GPR дневной → среднее за окно недели `[W−6, W]`. Месячные ряды (ACLED,
  CrisisWatch) сравниваются с месячным средним индекса по неделям этого месяца; месяц
  без единой недели 3.0 в пересечение не входит.
- **Порог выборки.** `MIN_PAIRS = 6` — ниже него коэффициент не считается и не
  публикуется (в JSON `status:'insufficient'`, `value:null`). `PRELIMINARY_BELOW = 20` —
  от 6 до 19 пар значение публикуется с `status:'preliminary'`. Явная граница лучше
  красивого числа из двух точек.
- **Направление.** Совпадение знаков первых разностей; нулевые изменения не входят в
  знаменатель и считаются отдельно (`skipped`). Для журнала прогнозов другая шкала —
  мёртвая зона ±2 пункта индекса (`DIRECTION_DEADBAND = 2`), это правило прогноза, а не
  метрика сравнения.
- **Lead/lag.** Кросс-корреляция первых разностей при сдвигах −2…+2; на каждом сдвиге
  своё `n`; если максимум `n` меньше `MIN_PAIRS` — `status:'insufficient'`, `best:null`.
- **Расхождения.** Пары, где знаки разошлись (и обе дельты ненулевые), с обоими
  значениями; порядок — по дате по убыванию; ограничение `MAX_DISCREPANCIES = 12`.
- **Фикстуры.** `calc/backtest-fixtures/{gpr,acled,crisiswatch}.json` — только значения
  и провенанс, без логики. Формат — в `calc/backtest-fixtures/README.md`. Тесты не ходят
  в сеть; обновление фикстур — ручное действие редактора.
- **Журнал.** `calc/ledger.js`: `baseline` (ожидание = прошлый кластер, направление
  «flat» по построению) по всем опубликованным неделям цепочки, начиная со второй;
  `editor` — из `calc/input/anchors/forward-<неделя>.json` через `validateForwardAnchor`;
  запись без опубликованного факта — `pending`. Git-проверка: коммит, добавивший файл
  якоря, должен быть раньше коммита, добавившего `data/<week>/week.js`; при недоступной
  истории — `verified:false`.
- **Страница.** Генерируется `calc/validation-page.js` в стиле `digest-page.js`:
  статический HTML, `STATIC_CSP`, `body.doc-page`, классы `.doc-*`, без скриптов.
  Русский текст зашит в генератор (как у `digest.html`), i18n-ключи для неё не заводятся.
- **Публикация.** `validation.html` добавляется в `cp`-строку `deploy.yml`, в футер
  главной, в `renderLlms` (`blog-build.js`); `sitemap.xml` подхватывает её сам через
  `staticRootPages`. Атрибуция внешних рядов — в `NOTICE` и в блоке источников страницы.
- **Детерминизм.** Никаких дат генерации внутри файлов; порядок ключей фиксирован; LF;
  повторный `--write` даёт побайтно те же файлы.
- **Иммутабельность журнала.** Требование «запись фиксируется в git до публикации
  недели» относится к **редакционным** записям: файл `calc/input/anchors/forward-<неделя>.json`
  попадает в git раньше, чем `data/<неделя>/week.js`, и это проверяется по истории git
  (`verified`, R21.1). **Baseline** — не прогноз, а наивный benchmark (A01): он
  детерминированно восстанавливается из предыдущей опубликованной недели, поэтому
  задним числом его нельзя «подкрутить», но и записью в git до публикации он не является.
  На странице baseline и редакционные записи стоят в разных блоках и по-разному
  подписаны; промахи baseline не выдаются за промахи проекта.

## Вне рамок

| Требование | Почему не сейчас |
|---|---|
| R03 — сравнение именно с композитом ACLED Conflict Index | индекс публикуется раз в полгода по странам, машинного доступа нет (403), пересечения с неделями 3.0 нет; сравнение ведётся по недельным/месячным данным ACLED о событиях, подмена раскрыта на странице (D01) |
| R08 — lead/lag по месячным рядам | при n ≤ 3 пар сдвиг неинформативен; механизм есть, результат честно «не рассчитывается» |
| Ежедневная сверка и автоматическое обновление фикстур | сеть в пайплайне запрещена; фикстуры обновляет редактор (как вход недели и корпус цитат) |
| Обновление `docs/calibration-journal.md` машинной таблицей | журнал — редакционный документ; туда добавляется только ссылка на публичный журнал |

## Открытые места

- **Фикстура ACLED.** Значения снимаются с HDX-зеркала ACLED на дату `as_of`; если
  редактор захочет сравнивать с другим срезом — правит фикстуру и `as_of`.
- **Фикстура CrisisWatch.** Считается по страницам месячных выпусков; проверка
  согласованности — сентябрьский счёт должен совпасть с числом из сводки («five
  deteriorations»). Если страница изменит разметку, число в фикстуре остаётся, а
  инструкция по пересборке — в `calc/backtest-fixtures/README.md`.
- **Редакционные якоря.** Журнал редакционных прогнозов пуст до первого
  `calc/input/anchors/forward-<неделя>.json`; страница это говорит прямо, baseline
  показывается отдельной строкой сводки.
