# Спецификация: Страновой слой индекса (Россия и Украина, с недели 2026-10-25)

## Задача

Редактор Индекса Кассандры написал аудит двенадцати индексов риска, где собственный проект
получил 58 баллов и шестое место: максимум по открытости и воспроизводимости, ноль по истории,
независимости и **страновому разрешению** — читателю из России или Украины индекс отвечает
только «твой регион». Читатель задаёт вопрос «а что у меня в стране?» — и проект молчит.
Нужно честно закрыть этот разрыв: настоящий страновой ряд, с первой недели ближайшей
публикации, без подгонки чисел и без переписывания истории.

## Решение

С недели 2026-10-25 проект публикует страновой слой: значение и дельту по странам России
и Украине, посчитанные из страновой атрибуции критериев той же формулой §7, что и регионы, —
глобальный индекс плюс отклонение от атрибутированных сигналов. Слой не влияет на глобальный
индекс и регионы, история до гейта не пересчитывается. Каждое значение страны несёт
покрытие, факт-основания и ссылки на источники недели; слепая страна помечается честно.
На сайте появляется блок «По странам» в секции регионов; в публичном API — новый файл
`data/public/countries/<неделя>.json` со схемой. Матрица аудита обновляется по факту
публикации: клетка «страновой уровень» открывается, балл пересчитывает генератор.

## Решения по реализации

- Оверлей отдельным файлом — вход недели 2026-10-25 принадлежит параллельной сессии, перезаписывать нельзя; атрибуция как редакционный оверлей даёт тот же аудиторский след (основание + url источника недели). Почему: изоляция чужой работы и forward-only естественным образом.
- Ядро §7 обобщается в `attributedSignals/attributedIndex`, регионы — тонкая обёртка — чтобы формула не дублировалась и регионы гарантированно не сдвинулись (байт-пин). Почему: одна формула, две размерности.
- `prevIndex` страны: прошлая неделя страны → иначе индекс её региона → иначе `prevGlobal`. Почему: первая неделя слоя обязана дать дельту (ADR 0038 по аналогии), иначе контракт ломается.
- Часть `countries.js` опциональна и presence-gated, набор частей по версии таксономии не меняется. Почему: история и пины `weekPartFiles` (v1=11, v2=17) не трогаются.
- Публичный слой — новый файл, не новое поле. Почему: договорённость «PUBLIC_SCHEMA_VERSION = 1, новых полей нет».
- Имена стран в снапшот из `data/geo/countries.js` (vm, кэш) — единый источник имён. Почему: не плодить второй справочник.
- Кластеры независимости: на каждую страну ≥2 кластера источников в атрибуции (ворота независимости недели их уже гарантируют глобально; страна без них не публикуется — предупреждение). Почему: честность клетки Ст.
- Неделя 2026-10-25: слой дописывается аддитивно (`countries.js` + пересборка `week.js`), чужие части не перезаписываются. Почему: правило прогона.

## Вне рамок

| Требование | Почему не сейчас |
|---|---|
| R07 — «full» | это режим прогона (сколько вопросов задаёт оркестратор), а не свойство продукта — в билд не входит |
| Страны кроме RU/UA | бриф ограничивает старт; расширение — оверлеем без правки кода |
| Бэкфилл стран в историю 08-30…10-18 | forward-only гейт, история не пересчитывается (R11i) |
| Изменения hero, дайджеста, RSS | минимальный честный срез; блок живёт в секции регионов |
| Внешнее рецензирование (клетка Р) и история (И) | не входят в бриф: до 4-го места (цель брифа) хватает клетки Ст; И — календарь, не раньше 2031; Р — отдельная внешняя работа. Обе остаются нулями балла осознанно — фиксируется здесь, чтобы не выглядело упущением |
| Страновая чувствительность (leave-one-domain на страну) | вместо неё — наследование чувствительности недели, раскрыто в API |
