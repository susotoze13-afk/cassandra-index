# 02 — Встройка проверки в пайплайн: calc.js и check-sources

**Требования:** R03, R06i
**Blocked by:** 01
**Зона:** `calc/calc.js`, `calc/check-sources.js`
**Волна:** 2
**Status:** ready

## Что должно заработать

`node calc/calc.js --write <неделя>` перед записью на диск проверяет все URL
источников собранного снапшота (`sources` + `drivers[].sources[]`) через
`linkcheck.checkSources`; при любом битом URL печатает перечень (where, url,
статус) и умирает с кодом 1, не трогая диск. Рядом — самостоятельная команда
`node calc/check-sources.js [YYYY-MM-DD …]`: без аргументов проверяет все
недели из `data/`, печатает построчный отчёт и итог, код выхода 0/1. Режим
`calc.js` без `--write` ссылки не проверяет (остаётся офлайн и быстрым).

## Из брифа, дословно

> «Необходимо проверять работоспособность ссылок-источников»

## Критерии приёмки

- [ ] `--write` с битой ссылкой: понятная ошибка с перечнем URL и код 1, файлы недели на диске не изменены
- [ ] `--write` с рабочими ссылками: проходит как раньше (существующие снапшоты не перезаписывать ради проверки — для этого есть check-sources)
- [ ] Проверка идёт ДО существующей самопроверки validate и до любой записи
- [ ] `check-sources.js` без аргументов проверяет все недели `data/`, с аргументами — перечисленные; отчёт построчный + итог, код 0/1
- [ ] Снапшоты читаются тем же механизмом, что в calc.js (без дублирования парсинга window.CI_DATA)
- [ ] `node --test` (весь набор) зелёный
