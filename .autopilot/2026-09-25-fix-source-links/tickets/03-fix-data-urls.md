# 03 — Замена вымышленных URL на реальные статьи во всех снапшотах

**Требования:** R01, R02, R04i
**Blocked by:** —
**Зона:** `data/`
**Волна:** 1
**Status:** ready

## Что должно заработать

Во всех 7 неделях `data/2026-08-02 … 2026-09-13` каждый URL в `sources.js` и
`drivers.js` ведёт на реальную, открывающуюся страницу. Замена — реальная
статья того же домена (reuters.com, apnews.com, dw.com, un.org, sipri.org,
crisisgroup.org), максимально близкая по теме заявленного заголовка и дате
снапшота; `title{ru,en}`, `date` и `domain` каждой записи приводятся в
соответствие реальной странице. Число записей и структура полей не меняются.

## Разделы спецификации

Решения §1–2, Истории 1–2, 6.

## Критерии приёмки

- [ ] Каждый новый URL физически проверен (HTTP 2xx/3xx) на момент правки — не одна ссылка не осталась на «доверии к поисковой выдаче»
- [ ] Каждая правка: домен сохранён, тема статьи соответствует прежнему заголовку записи, date в разумном окне дат снапшота
- [ ] Затронуты оба файла каждой недели: `sources.js` и `drivers.js` (дубликаты URL внутри недели заменяются согласованно)
- [ ] Структура записей не изменилась: `{ title: {ru, en}, url, domain, date }`
- [ ] `node -e "…validate…"` (валидация снапшотов из js/data.js) зелёная на всех 7 неделях — контракт данных не сломан
- [ ] Поля снапшотов, не относящиеся к источникам (global/regions/trend), не тронуты
