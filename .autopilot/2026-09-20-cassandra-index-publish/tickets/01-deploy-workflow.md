# 01 — Выкатная обвязка: GitHub Actions workflow + инструкция обновления

**Blocked by:** —

**Волна:** 1
**Status:** ready

## Что должно заработать

Каждый push в `master` автоматически выкатывает сайт на GitHub Pages:
workflow собирает artifact из явного списка путей (`index.html`,
`privacy.html`, `css/`, `js/`, `data/`) и публикует его через
`actions/deploy-pages`. Наружу не попадает ничего лишнего — в частности
`.autopilot/` (брифы, таски, внутренние записи) и служебные файлы. Плюс в
`AGENTS.md` появляется раздел «Публикация»: как выкатывается сайт и что делать
при еженедельном обновлении данных.

## Критерии приёмки

- [ ] `.github/workflows/deploy.yml` существует: trigger — push в `master`;
      permissions `pages: write`, `id-token: write`; artifact — только
      `index.html`, `privacy.html`, `css/`, `js/`, `data/`; публикация через
      `actions/deploy-pages`
- [ ] YAML валиден (парсится без ошибок)
- [ ] В сайте нет абсолютных путей, ломающих подкаталог Pages: проверить
      `index.html` и `privacy.html` (нет `href="/…"`/`src="/…"` ведущих в корень)
- [ ] Локально подтверждена работа под префиксом пути: сайт отдан статическим
      сервером из подкаталога `/<имя-репозитория>/`, страницы и ресурсы грузятся
- [ ] `node --test` — зелёный (ничего не сломано)
- [ ] В `AGENTS.md` раздел «Публикация»: сайт выкатывается Actions при push в
      `master`; обновление недели = commit новых данных + push; URL будет
      дописан после первого выката
