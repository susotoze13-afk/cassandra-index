# Спецификация: Публикация сервиса Индекс Кассандры

## Задача

Сервис Индекс Кассандры готов и работает локально (12/12 тасков сдано, 91 тест
зелёный), но до него никто не может дойти: у репозитория нет удалённого адреса,
сайт лежит только на диске автора. Нужно, чтобы любой человек по публичной
ссылке открывал работающий сервис.

## Решение

Сервис опубликован на GitHub Pages: публичный репозиторий `cassandra-index`,
сборка и выкат — через GitHub Actions при push в `master`. Сайт доступен по
HTTPS-URL вида `https://<аккаунт>.github.io/cassandra-index/`, полностью
функционален (все семь секций, смена региона, смена недели, демо-режим,
share-карточка), повторная публикация при еженедельном обновлении данных —
одним push.

## Решения по реализации

1. **Хостинг — GitHub Pages.** Проект — чистая статика (ноль зависимостей,
   работает с file://), Pages даёт бесплатный HTTPS без серверной части; `gh`
   в машине уже авторизован. Почему так: любой другой хостинг требует либо
   аккаунт/токен, либо upload-инструмент, Pages требует только git push.
2. **Выкат — GitHub Actions** (workflow `.github/workflows/deploy.yml`):
   trigger push в `master`, artifact собирается явным списком путей
   (`index.html`, `privacy.html`, `css/`, `js/`, `data/`), публикация через
   `actions/deploy-pages`. Почему так: публикация из корня ветки отдала бы
   наружу `.autopilot/` (брифы, таски, внутренние записи) — недопустимо;
   явный список путей публикует только сайт.
3. **Репозиторий** — публичный `cassandra-index` в аккаунте пользователя,
   источник — текущий локальный `master`. Создание репозитория и первый push —
   действие наружу, выполняется один раз после подтверждения пользователя
   в финальной фазе.
4. **Контроль качества до выката** — существующий ритуал проекта: `node --test`
   (91 тест), `node build.js` (бандлы коммитятся), headless-проверка страницы
   (как в таске 10 предыдущего прогона).
5. **Base path** — сайт ходит только относительными путями, подкаталог
   `/<repo>/` на Pages не требует правок. Проверяется headless-прогоном на
   локальном сервере с префиксом пути перед выкатом.

## Границы и швы

Единицы работы этого прогона — не код сайта (он готов и заморожен), а обвязка
публикации:

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `deploy workflow` | `.github/workflows/deploy.yml` | trigger push→опубликовано | детали artifact/deploy actions |
| `publish-docs` | инструкция обновления в `AGENTS.md` | шаги «новая неделя → опубликовано» | — |
| `site` *(существующий, не меняется)* | весь пользовательский функционал | `node --test`, `node build.js` | — |

Швы для тестов: существующие — `node --test` (91 тест) и headless-проверка
страницы. Новых модулей с логикой нет, новых швов не вводим.
