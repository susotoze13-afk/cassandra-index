# Спецификация: неделя 2026-11-08 (02.11–08.11.2026)

> Режим прогона: **full** (полный автомат), глубина **обычная**. Состояние —
> в `.autopilot/` (`state.js`, дашборд). Вопросов по ходу нет; единственный
> вопрос — safety-gate перед выкатом в master (это не пошаговое согласование).

## Задача

Владелец публичного индекса Cassandra Index публикует каждую неделю уровень и
направление риска глобального конфликта по открытым данным. Последняя неделя —
`2026-11-01`. Нужна следующая: **02.11–08.11.2026**, с расчётом так, чтобы **ни
один из 12 регионов не был слепым** и **слепых критериев было как можно меньше**.
Сейчас этой недели нет вовсе: ни входа `calc/input/2026-11-08.json`, ни сидов
`data/2026-11-08/`, ни строки на сайте.

## Решение

К концу сборки в репозитории появляется посчитанная неделя `2026-11-08`:

- вход недели из 46 критериев (слепые — с записанной причиной `blindReasons`),
  R55-источники только из окна 02.11–08.11.2026 и только реальные страницы;
- глобальный индекс + дельта + `q` посчитаны движком методологии 4.0;
- **12 регионов таксономии v2 — все с сигналами** (`background:false`), по
  возможности `signals ≥ 2` у каждого (планка правки 11-01, коммит `6ebd089`);
- страновой слой «По странам» (RU/UA) — блок на месте, как на 10-25 и 11-01;
- публичный слой, CSV, тренд, дайджест и бандл пересобраны; `node --test`
  зелёный; пины тестов обновлены вместе с неделей.

Выкат на `cassindex.ru` (push в master) — отдельный вопрос перед пушем, не
автоматика (правило безопасности).

## Решения по реализации

- **Окно недели — W−6…W = 02.11–08.11.2026** (7 календарных дней, `accessed_date`
  = 2026-11-08). Проверено по прошлым неделям: 11-01 = 10-26…11-01, 10-25 =
  10-19…10-25. Бриф пользователя («02.11 по 08.11») совпадает с этой конвенцией;
  `docs/source-discovery.md` и старый AGENTS писали «W−7…W» — расхождение
  документации, следуем фактической конвенции данных.
- **Источники — только реальные страницы**, открывающиеся сейчас (Bing RSS
  `&format=rss`, реестр лент `calc/input/discovery/feeds.json`, RSS издателей,
  прямые страницы). Каждый URL проверяется (curl): `broken` (404/410) —
  заменяется, `blocked` (401/403/406/таймаут) — допустим (так у reuters/apnews).
  Выдуманных URL, заголовков и дат нет.
- **Сборка — фрагментами, затем слияние.** Четыре коллекционера пишут
  `calc/input/drafts/2026-11-08/part-<группа>.json`
  (`{week, criteria, sources, blindReasons, rejected}`), затем один таск
  сливает фрагменты в `calc/input/2026-11-08.json` (дедуп R55 по `id`,
  все 46 ключей) и пишет страновой оверлей.
- **Региональная атрибуция** — `regions[]` на критериях допустимых драйверов
  (Д1, Д3, Д5–Д8, Д9 только D9.3), id — 12 из таксономии v2. Цель: каждый
  регион ≥1 сигнал (не слепой), приоритет — ≥2. Значения/`events[]` при
  расширении атрибуции не меняются (шаблон `6ebd089`).
- **Сиды** — по образцу `calc/input/drafts/seeds-2026-11-01.mjs` (он писал
  global/trend/drivers/12 region-*): 3 глобальные истории драйверов по свежим
  событиям недели, 12 региональных по 2 драйвера; источники сидов — verbatim
  по `id` из входа недели.
- **Порядок записи** (проверен по `weekly-calc.yml` и прошлым прогонам):
  вход → сиды → `node calc/prepare-week.js --write 2026-11-08` → сухой
  `calc.js 2026-11-08` → `calc.js --write 2026-11-08` → производные → пины →
  `node --test`.
- **Пуш в master = выкат** — вопрос перед пушем (`ap.py ask action`).
- **Производные `backtest`/`ledger`/`blog-build`** — не отдельное требование, а
  часть «неделя как предыдущие» (R04i): реестр прогнозов и `validation.json` не
  должны отставать от опубликованного ряда; в workflow они/`blog-build`
  запускаются, `ledger` запускался на 11-01.

## Границы и швы

См. `interfaces.md`: фрагменты → вход → оверлей → сиды → генератор →
производные → пины; что каждый таск владеет и что не трогает.

**Tier — T3** (7 тасков): сбор источников распараллелен на 4 независимых
редакционных домена с изолированными файлами (разные наборы критериев, разный
поиск, разные поверхности записи) — это не дробление ради счёта; последовательно
это удвоило бы календарное время сбора. Остальное — цепочка «слияние → сиды →
запись → пины», по одному таску на шаг.
