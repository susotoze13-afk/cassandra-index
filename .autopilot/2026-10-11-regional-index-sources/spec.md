# Спецификация: Расширение источников региональных индексов + ввод методологии 3.0

## Задача

На сайте Кассандры все шесть регионов всех недель помечены «Индекс отражает
глобальный фон; региональных данных недостаточно» — потому что ни один вход
недели не несёт региональной атрибуции (`regions[]`), а механизм её обработки
(`engine.regionalSignals`, ADR 0022) построен, но голоден. Одновременно
зафиксирован (ADR 0021), но не внедрён 46-й критерий — состояние фондового
рынка, — без которого методология остаётся версии 2.0.

## Решение

Прогон методологии 3.0 по цепочке 08-30…10-11 (все 6 пересчитываемых недель),
как предписывает ADR 0021 «Механизм внедрения»:

1. В движок добавляется критерий **D4.6 «Стресс на финансовых и сырьевых
   рынках»** (драйвер Д4 «Экономические индикаторы конфликта», направление
   esc, шкала ordinal) — к методологии 3.0 по ADR 0021.
2. Агент исследует открытые источники и размечает входы всех 6 недель:
   региональная атрибуция `regions[]` на критериях (только драйверы, которые
   региональная агрегация принимает: Д1, Д3, Д5, Д6, Д7, Д8, Д9.3 — Д2, Д4
   и Д9, кроме D9.3, игнорируются агрегацией по ADR 0022) + новые
   региональные источники в R55-списках + покрытие D4.6 по каждой неделе.
   **Итоговый набор утверждает пользователь до записи** (его решение на
   брифинге).
3. k перекалибруется на 10 якорях (в каждый якорь добавляется D4.6) —
   сетка, выбор, verify-якоря, чувствительность ±20 %, запись в журнал.
4. Цепочка пересчитывается (`calc.js --write`): methodology «2.0» → «3.0»,
   регионы с сигналами перестают быть слепыми, записи в audit.jsonl.
5. Сайт, тесты и документы приводятся в согласие: 46 критериев, тренд
   показывает точки 3.0, фикстуры пересчёта актуализированы.

Демо-недели 08-02…08-23 (методология 1.0) не трогаются.

## Решения по реализации

- **D4.6, а не новый драйвер.** Таксономия: финансовые рынки — экономический
  индикатор конфликта (Д4). Новый драйвер сломал бы 9-драйверную структуру
  весов, калибровку и сквозные тесты. Ordinal esc: «0» — рынки спокойны,
  «1» — выраженный стресс (обвал индексов, скачок нефти/золота, разрыв
  спредов); описание — в METHODOLOGY.md (read-only снимается в этом прогоне
  по ADR 0021). D4.6 — глобальный критерий: по ADR 0022 атрибуция Д4 в
  региональной агрегации игнорируется, региональный эффект рынков идёт через
  eStruct/eDyn — противоречия с ADR нет, это сказано прямо.
- **Кноб методологии — `PARAMS.methodology = '3.0'`.** Сейчас renderGlobal
  carry-over'ит methodology из прежнего снапшота, кода пути для смены нет.
  renderGlobal/writeWeek берут methodology из PARAMS; published по-прежнему
  из снапшота (защита не снимается). Осознанная смена — одна строка в
  params.js, видимая в diff.
- **Аудит.** recalculation_method: 'aggregateDrivers v3.0',
  version_before — из снапшота, version_after — из PARAMS.
- **Тренд.** selectMethodology(points, version = '3.0') — точное совпадение
  '2.0' после перевыпуска скрыло бы всю серию; summaryTextV2 и подпись
  считают точки текущей версии; trendSegments (маркер смены методологии)
  версионно-агностичен и не меняется.
- **Порог покрытия не меняется** (PARAMS.coverageThreshold = 0.5 на драйвер):
  Д4 станет 5/6; неделя без покрытого D4.6 рискует уйти в insufficient —
  это редакционное требование к входу, а не новый порог.
- **Порядок прогона:** (1) код-дизайн D4.6 + кноб методологии + warning об
  игноре атрибуции, тесты зелёные без данных; (2) исследование: D4.6 в 10
  якорях → перекалибровка k → **утверждение пользователем** (дизайн критерия,
  значения якорей, новый k); (3) исследование 6 недель: региональные
  источники, regions[], D4.6 по неделям → **утверждение пользователем**
  (набор источников и атрибуции); (4) пересчёт цепочки --write по одной неделе
  с linkcheck; (5) фикстуры тестов, бандлы (node build.js), документы
  (METHODOLOGY.md, PRD — правка в этом прогоне разрешена ADR 0021,
  calibration-journal, AGENTS.md — в Phase 9).
- **Конвенция репо сохраняется:** фикстура tests/data.test.js актуализируется
  после пересчёта (пин 09-13: index 41, delta -1 и пр. сменятся); пин
  sensitivity (10-04: 11.8) пересчитывается; commit — только оркестратор;
  push/deploy — внешнее действие, вопрос пользователю в конце.

### Правила отбора региональных источников (§6)

Каждый добавляемый источник — полноценная R55-запись: `id, title{ru,en},
domain, url, publication_date` (в окне недели W−7…W), `accessed_date,
source_type (primary|secondary|OSINT), cluster_id` (из whitelist
`PARAMS.clusters`), `state_affiliated` (честно, по канонической
классификации доменов репо). Правила:

1. На каждый покрываемый региональный критерий — ≥2 независимых источника
   (≥2 кластера ИЛИ ≥1 primary|OSINT) — зеркало ворот
   `validateSourceIndependence`, применяемого как редакционное требование
   ко всем 6 неделям (кодовый gate формально действует с 2026-10-11).
2. Атрибуция `regions[]` — только критериям драйверов Д1, Д3, Д5, Д6, Д7,
   Д8, Д9.3; запись с нормированным значением 0 допустима («событий не было»
   — фиксация наблюдения, не отсутствие данных).
3. Кандидат без публикации в окне недели или без соответствия критерию —
   отбрасывается до показа пользователю (ворота правила 9 пилота Jev по
   духу: дословная цитата-обоснование обязательна).

### Формат утверждения пользователем

Артефакт — один файл на неделю:
`.autopilot/<dir>/proposals/<неделя>-regions.md`: таблица «регион →
критерий → R55-записи (url, дата, кластер, type) → цитата-обоснование →
новый/существующий источник», плюс покрытие D4.6 недели и сводка
«было покрыто X/45 → станет Y/46; регионов с сигналами: N/6». В чат —
сводная таблица по 6 неделям. Пользователь отвечает «ок» или с
правками; без «ок» --write не запускается. То же для якорей: отдельный
файл `proposals/anchors-d46.md` (значение D4.6 по 10 якорям с
обоснованием) — утверждается вместе с новым k.

## Границы и швы

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `engine` | CRITERIA (45→46), формулы | `CRITERIA`, `buildDriversCore`, `regionalSignals`, `regionalIndex`, `validate` — сигнатуры без изменений | маппинг D4.6 в buildDriversCore (жёсткие циклы драйверов — расширить) |
| `params` | все числа + версия методологии | `PARAMS.methodology`, `PARAMS.k` | — |
| `calc.js` | цепочка, ворота, рендер снапшотов | runWeek/renderGlobal/renderRegionFile — сигнатуры без изменений | откуда methodology попадает в снапшот |
| входы (данные) | 6 файлов недель + 10 якорей | JSON-схемы, существующие | редакционные решения разметки |
| сайт (js/) | подача версии и 46 критериев | `selectMethodology`, `summaryTextV2`, `criteriaModel` — швы без изменения сигнатур (меняются дефолты/данные) | — |

Швы для тестов — существующие чистые модули: engine, regional-signals,
calibrate, data (validate), trend, methodology-criteria. Новых швов нет.
