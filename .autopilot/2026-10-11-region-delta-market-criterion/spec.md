# Спецификация: Региональная динамика + критерий фондового рынка

## Задача

Читатель сайта видит в списке регионов у каждого региона одинаковое «изменение за неделю» — и это выглядит как баг: у регионов разные события, динамика не может быть вся одинаковой. Автор методологии additionally замечает, что среди критериев нет состояния фондового рынка (сырьевые биржи, облигации, ценные бумаги), хотя рынки реагируют раньше всех.

## Решение

1. **Диагностика зафиксирована**: у слепых регионов (нет числовой региональной атрибуции во входах — все 6 регионов всех пересчитываемых недель) дельта по построению равна глобальной: `delta = gInternal − prevGlobal`. Индексы различаются сохранённым отклонением, дельты — никогда.
2. **Честная подача на сайте**: регион без региональных данных больше не показывает дельту как региональную — вместо неё пометка «Индекс отражает глобальный фон; региональных данных недостаточно» (формулировка соответствует §7 METHODOLOGY.md, где такой UI-статус описан, но не был реализован). Флаг `background` из движка доводится до данных и до UI.
3. **Задел под будущие недели**: вход недели уже допускает `regions?: string[]` у критерия (валидация есть, потребителя нет). Появляется чистая функция агрегации региональных сигналов; calc.js проводит её в `regionalIndex` (ветка nReg > 0 уже реализована в движке). Недели без атрибуции считаются байт-в-байт как сейчас.
4. **Критерий фондового рынка** принят как архитектурное решение к методологии 3.0: ADR 0021 + открытый вопрос O6 в preproduction-decisions.md. Расчёт, калибровка и опубликованные недели не меняются.

## Решения по реализации

- **Диагностика не требует кода.** Причина следует из формулы слепого региона (engine.js regionalIndex, ветка nReg≤0): `delta = index − prevIndex = gInternal − prevGlobal` — константа по всем регионам. Исправление касается подачи, а не формулы: формула осознанная (сохраняет последнее отклонение), ложь — в том, что сайт показывает её результат как региональную динамику.
- **Флаг `background` в данных.** Движок уже возвращает его (`background: true` для слепых). `renderRegions` и `renderRegionFile` доводят его до `regions.js` и `region-*.js`; `js/data.js` validate принимает опциональный `background: boolean` (дефолт при отсутствии — false, обратная совместимость со всеми старыми данными без миграции). Числовой `delta` в контракте остаётся обязательным — контрактный риск минимален, неделя в unavailable не уходит.
- **Сайт**: ranked-лист (js/sections/regions.js), hero (js/sections/hero.js) и раскрытая карточка при `background:true` не рендерят дельту как региональную; показывают пометку из словаря i18n (новый ключ `region.background`, RU). Тон — `--text-muted`, лексика без метафор часов и Avoid-списка. Регион остаётся в списке и сортируется как раньше.
- **Задел — чистая функция агрегации** (новый шов в calc, рядом с engine): по критериям с `regions[]` строит для каждого региона вход regionalIndex `{nReg, eStruct, eDyn, hasDeescSignals, iWith, iWithout}` строго по §7 METHODOLOGY.md. Если §7 не определяет какой-то из входов однозначно, трактовка фиксируется в ADR 0022 (задел — см. ниже) и пинится тестами; изменение трактовки потом — отдельное решение.
- **calc.js**: если вход несёт хоть одну региональную атрибуцию — считать этот регион по сигналам (nReg>0, `background:false`); регионы без атрибуции — слепыми, как сейчас. Смешанная неделя допустима и осмысленна.
- **Ничего не пересчитывается.** Опубликованные недели (08-30…10-04) не трогаем: ни числа, ни файлы. Новая неделя 2026-10-11 в этот прогон не входит (её расчёт — отдельный редакционный процесс по расписанию).
- **Критерий фондового рынка — только документация**: ADR 0021 (следующий свободный номер, единый ряд после 0020; формат `NNNN-slug.md`), вопрос O6 в §1 preproduction-decisions.md по формату таблицы (`# | Вопрос | Владелец | Что уже зафиксировано`). METHODOLOGY.md и PRD не трогаем (read-only по конвенции репо); снятие read-only — часть будущего прогона методологии 3.0.
- **Стек и конвенции без изменений**: ноль зависимостей, ESM, DOM через createElement/textContent (в новом коде; соседние секции с их шаблонами не переписываются), все пользовательские строки — через js/i18n.js, цвета — CSS-токены, после правки js/** — `node build.js` (бандлы коммитятся).

## Границы и швы

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `engine.regionalIndex` (существующий) | формула регионального индекса, ветки слепой/сигнальный | `regionalIndex(global, region, params) -> {index, state, delta, internal, background, mirrored}` | клэмп, зеркалирование шока |
| `engine.regionalSignals` (новый) | агрегация `regions[]` критериев в сигналы региона | `regionalSignals(criteria, regionIds, params) -> { [regionId]: {nReg, eStruct, eDyn, hasDeescSignals, iWith, iWithout} }` (только для регионов с атрибуцией) | трактовку шкал §7, whitelist REGION_IDS |
| `calc.js runWeek` | выбор ветки региона (сигналы есть → nReg>0, нет → слепая) | без новых публичных сигнатур (CLI-обвязка) | проводку сигналов в regionalIndex |
| `renderRegions` / `renderRegionFile` (calc.js) | сериализация regions.js / region-*.js | флаг `background` в обоих файлах | перенос drivers verbatim |
| `js/data.js` | контракт снапшота | validate с опциональным `regions.<id>.background: boolean` | дефолт false |
| `js/sections/regions.js`, `hero.js` | подача региона и его динамики | без новых публичных сигнатур (зарегистрированные секции) | верстку пометки |

Швы для тестов (меньше = лучше, используем существующие):
1. `engine.regionalSignals` — синтетические критерии, без диска и сети (новый тест-файл).
2. `engine.regionalIndex` — существующий шов, дополняется случаем «сигнальный регион» (тесты уже есть).
3. `renderRegions` / `renderRegionFile` / validate из calc.js и js/data.js — существующие шов-функции, пин формы файлов с флагом.
4. `rankedRegions` и форматтеры дельты (`formatDelta`/`deltaArrow`) — существующие чистые швы сайта.
