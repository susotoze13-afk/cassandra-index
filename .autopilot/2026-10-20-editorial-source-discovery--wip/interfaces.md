# Interfaces — editorial-source-discovery

## Стек, команды и проверки (для исполнителя, не выводится из кода)

- Стек: Node ≥ 18, ESM, ноль зависимостей (только stdlib); Python не нужен (только `.autopilot/ap.py` — оркестратора).
- Одна команда проверки (тесты целиком, из корня репозитория): `node --test` (без аргументов; базовый бейзлайн 769 passed).
  Один файл: `node --test tests/<имя>.test.js`.
- Линтера/сборщика типов в проекте нет — «линт» = держать `node --test` зелёным и стиль соседних модулей.
- `node build.js` обязателен только после правок `js/**` — этот прогон `js/**` не трогает, сборка не нужна.
- Git: коммитит только оркестратор; DCO — подпись `git commit -s`; в рабочем дереве есть чужие незакоммиченные
  файлы (см. ниже) — их не трогать и не коммитить.

## Границы, решённые в спецификации

- **Не менять**: `calc/params.js` (числа, k, methodology), `calc/engine.js` (формулы), `calc/input/*.json`
  (входы недель), `data/<week>/**` (снапшоты), `data/public/**` (публичный слой), `js/**` и HTML-страницы
  (сайт), `.autopilot/` кроме файлов своего запуска.
- **Писать можно**: `calc/source-discovery.js` (новый), `calc/input/discovery/*` (пул кандидатов/реестр,
  если машиночитаемый), `docs/source-discovery.md`, `docs/source-proposals/2026-10-18.md`,
  `docs/adr/0065-*.md`, `data/discovery/**` (только через `--write` инструмента), `tests/source-discovery.test.js`,
  точечная правка `docs/governance.md` §10.1 и одна строка в `AGENTS.md`.
- **Только чтение**: `docs/regional-source-pool.md`, `docs/adr/0026-*`, `docs/governance.md` (кроме §10.1),
  файлы из carried.md «Не коммитить» (`index.html`, `how-to-read.html`, `sitemap.xml`,
  `.github/workflows/deploy.yml`, `about.html`, `docs/competitive-analysis.md`, `docs/regional-source-pool.md`).
- **Сетевой доступ**: только через CLI инструмента/прогон примера; чистые функции — мок `fetchImpl`.
  Результаты проверок фиксируются в артефактах (таблица/JSON), чтобы тесты не ходили в сеть.
- **Смысловая граница (R01/R05)**: инструмент предлагает, редактор выбирает; ни один код в этом прогоне
  не изменяет опубликованную неделю 2026-10-18 и не вызывает `calc.js --write` для неё.
- **Граница входа (R03)**: кандидат предлагается только для критерия, слепого в неделе
  (`criteria[id] === null` во входе), и только если публикация в окне 2026-10-11…2026-10-18.
- **Формат артефакта (R04)**: человекочитаемый Markdown-список + машинный JSON; оба несут полный
  набор обязательных R55-полей, чтобы редактор переносил записи без доделки.
- **Ворота кандидата (R07i/R08i)**: живой URL (linkcheck), схема R55, cluster_id ∈ PARAMS.clusters,
  регион ∈ taxonomy недели, ≥2 кластера на критерий как порог независимости (ADR 0026);
  blocked ≠ broken (сетевые особенности — предупреждение).
- **Пересечение с методологией (R06)**: корректируется только процедурный текст (governance §10.1)
  + новый ADR 0065 + строка AGENTS.md; численная методология не затрагивается.

## Договорились (из carried.md — правила, действующие для проекта)

- Методология numeric read-only в этом прогоне; откат по ASSUMPTION при расхождении с текстом §10.1/ADR 0026.
- Публичные URLs не генерировать; зафиксировать 5 измеримых фактов по ссылкам с датами за 12 мес.
- Расширение 0019/0020 +5/−5 — по явному решению.
- После `js/**` — `node build.js`; фикстуры тестов чинить вслед за пересчётом (здесь пересчёта нет —
  пины `tests/data.test.js`/`tests/sensitivity.test.js` не должны измениться).
- Верификация на живом приложении обязательна (здесь: прогон CLI и `node --test`, сеть — реальные URL).
- Ошибки фиксировать в PROGRESS.md каждые ≤30 мин; чужие файлы не коммитить; линт перед фиксацией.
- Каждый фикс — свежий форк; форк с >2 фиксами, все зелёные → слить; ревью-агент не коммитит.
