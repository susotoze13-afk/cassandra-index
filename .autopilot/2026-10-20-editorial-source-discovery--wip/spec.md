# Spec — editorial-source-discovery (неделя 2026-10-18)

Поле «Открытые места» заполняется только вопросами, на которые нельзя ответить чтением репозитория.

## Задача

Дать редактору инструмент и документированный порядок, при которых модель ищет в открытном интернете /
сканирует ленты и **предлагает** редактору список готовых URL публикаций с заполненными R55-атрибутами для
конкретной опубликованной недели (в этом прогоне — 2026-10-18, окно 2026-10-11…2026-10-18), а редактор сам
выбирает, что войдёт во вход недели. Плюс корректировка текста методологии проекта так, чтобы эта
процедура стала легитимной частью процесса.

Бриф: `2026-10-20-brief.md` (нормативный, не редактируется). Требования — `manifest.md` (R01…R09i).

## Решение

### 1. Документированная процедура (R01, R02)

Новый документ `docs/source-discovery.md`:

- Роли: модель = поисковик и подготовитель (собирает кандидатов, заполняет атрибуты, проверяет URL);
  редактор = единственный, кто выбирает и применяет записи к неделе (governance §10.1, ADR 0026/0065).
- Реестр точек входа: таблица «регион/тема → источник → URL (RSS-лента или HTML-страница)» — seed-реестр на
  основе `docs/regional-source-pool.md` (перенести существующие URL, не читая его с сайта) + общие
  международные ленты. Единственный машинный источник реестра — `calc/input/discovery/feeds.json`
  (пополняется редактором); `docs/source-discovery.md` несёт ту же таблицу для человека,
  паритет «документ ↔ feeds.json» пинится тестом.
- Алгоритм недели: (а) взять слепые критерии недели (`criteria[id] = null` во входе) и их драйверы;
  (б) для каждого — окно W−7…W и допустимые драйверы региональной атрибуции (D1/D3/D5/D6/D7/D8/D9.3);
  (в) пройти ленты/поиск, отобрать публикации; (г) проверить URL воротами linkcheck; (д) заполнить R55-атрибуты
  и предложить редактору список; (е) редактор выбирает и вносит записи во вход сам.
- Порог независимости кандидата к моменту предложения: ≥2 кластера `PARAMS.clusters` на критерий —
  как в ADR 0026 (это порог ворот, а не мнение модели).

### 2. CLI обнаружения `calc/source-discovery.js` (R02, R03, R04, R07i, R08i)

Консольный инструмент (тонкая обвязка + чистые экспорты, как `calc/check-sources.js`):

- Вход: неделя (`--week`, дефолт последняя опубликованная), пул кандидатов. Пул по умолчанию —
  `calc/input/discovery/<week>.json` (готовые кандидаты с URL, как их собрала модель/редактор);
  опционально `--feeds` — пройти реестр `calc/input/discovery/feeds.json` (RSS-ленты и HTML-страницы
  источников) через fetch и извлечь ссылки на статьи в окне.
- Для каждого кандидата модуль проверяет: URL живой (`linkcheck.checkUrl`, чистый шов с `fetchImpl`);
  дата публикации в окне W−7…W; критерий — из слепых критериев недели (по входу недели);
  драйвер критерия допустим для `regions[]` (eligible-набор), если кандидат несёт регион;
  регион из whitelist таксономии недели (`regionIdsFor(taxonomyForWeek(week))`);
  cluster_id из `PARAMS.clusters`; source_type из {primary, secondary, OSINT};
  обязательные R55-поля заполнены (id, title{ru,en}, domain, url, publication_date, accessed_date,
  source_type, cluster_id, state_affiliated); `quotes[]` — если есть, форма {criterion, text} и
  criterion из 46; дословность через `quoteFound` — предупреждение, если корпус `texts-<week>/` отсутствует.
- Выход: человекочитаемая таблица (кандидат → вердикт OK/проблема с причиной) + машинный JSON
  в `data/discovery/<week>.json` **только с `--write`** (сухой прогон по умолчанию): у каждой записи
  вердикт, список блокеров и полный R55-объект для копирования редактором.
- Ворота модуля (exit 1): невалидный кандидат (схема/окно/критерий не слепой/cluster вне whitelist) —
  он не попадает в предложение; мёртвый URL (broken) — кандидат отбрасывается с пометкой; blocked —
  предупреждение, не отказ (сетевые особенности среды).
- Неделя в цепочку `RECALC_WEEKS` не добавляется, `--write` **не** вызывает `calc/calc.js` и не пишет в
  `data/<week>/` (R05 — пересчёт/применение вне рамок).

### 3. Артефакт для редактора (R04)

`docs/source-proposals/2026-10-18.md` — конкретный пример для этой недели, генерируется/пишется в этом
прогоне (содержимое — по данным инструмента):

- Шапка: неделя, окно, слепые критерии (12 шт.: D1.3, D2.1, D3.1, D3.4, D4.1, D5.1, D5.4, D6.1, D6.4,
  D7.1, D7.5, D9.5), сколько кандидатов прошло ворота.
- На каждого кандидата: таблица R55-атрибутов (все обязательные + заполненные опциональные), вердикт
  ворот, регион(ы) если атрибутируется, цитата если есть.
- Инструкция: что редактор делает дальше (выбирает, переносит во вход, при необходимости — прогоняет
  `node calc/calc.js --write 2026-10-18` уже со своим выбором). **В этом прогоне эта команда
  не выполняется** — строка описывает следующий шаг редактора после его отбора, а не часть задания
  (см. «Вне рамок»).
- Машиночитаемая копия списка — в `data/discovery/2026-10-18.json` (продукт CLI `--write`).

### 4. Корректировка методологии (R06, не числа)

- `docs/governance.md` §10.1 — отредактировать абзац «Отбор источников остаётся ручным… LLM не ищет и не
  добавляет источники самостоятельно»: LLM **не выбирает и не применяет**, но может **искать и предлагать**
  список кандидатов с проверенными URL и R55-атрибутами; выбор и применение — редактор; ссылка на
  `docs/source-discovery.md` и ADR 0065. Текст согласовать по духу с существующим разделом (не ломать
  соседние правила).
- Новый ADR `docs/adr/0065-llm-source-discovery-proposal.md` (формат: `# 0065. Title`, секции
  Контекст/Решение/Почему/Последствия): модель предлагает — редактор выбирает; ворота валидации
  кандидата; что НЕ меняется (скорость, вес, автоматическое применение, пересчёт недели без редактора).
- `AGENTS.md` — одна строка-указатель на процедуру (раздел «Структура»/«Ключевые файлы» — по месту),
  чтобы агенты знали про `calc/source-discovery.js` и `docs/source-discovery.md`.

### 5. Тесты (R09i)

`tests/source-discovery.test.js` (чистые функции, без сети — мок `fetchImpl` по образцу
`tests/linkcheck.test.js`): валидация кандидата (окно, слепость критерия, whitelist региона/кластера,
обязательные поля), вердикты и exit-коды, форма `data/discovery/<week>.json`, наличие реестра лент и
прохождение валидации кандидатов примера `docs/source-proposals/2026-10-18.md`. Прогон `node --test`
из корня должен остаться зелёным (базовый бейзлайн 769 passed).

## Истории (порядок исполнения)

1. **S1. Модуль + CLI discovery**: чистые функции валидации и `calc/source-discovery.js` (сухой прогон,
   `--write` → `data/discovery/<week>.json`), переиспользование `linkcheck`/`classify`/`params`.
2. **S2. Процедура и реестр лент**: `docs/source-discovery.md` с реестром (seed из regional-source-pool.md).
3. **S3. Предложение для 2026-10-18**: прогон инструмента, `docs/source-proposals/2026-10-18.md` +
   `data/discovery/2026-10-18.json`; каждый URL — живой (прошёл checkUrl в этой среде).
4. **S4. Методология**: правка governance §10.1 + ADR 0065 + строка в AGENTS.md.
5. **S5. Тесты и финал**: `tests/source-discovery.test.js`, полный `node --test` зелёный.

## Решения по реализации

- Инструмент ничего не пишет в `data/<week>/` и не вызывает цепочку расчёта — предложение и есть
  артефакт (ASSUMPTION 2 из манифеста).
- Сеть — только в CLI и в прогоне S3; сами чистые функции тестируются моком `fetchImpl`.
- «Слепой критерий» = `criteria[id] === null` во входе недели (форм `covered:false` во входах нет).
- Источник истины по кластерам/окну/цитатам: `PARAMS` + ADR 0026; по списку критериев — `engine.CRITERIA`.
- Реестр лент: машинный источник один — `calc/input/discovery/feeds.json` (см. §1); Markdown-таблица в
  `docs/source-discovery.md` — человекочитаемое зеркало, их паритет проверяется тестом.
- `data/discovery/**` — производный продукт инструмента (не сайт, не публичный слой `data/public/*`);
  в deploy-whitelist не входит, наружу не уходит.

## Вне рамок

- Пересчёт/изменение недели 2026-10-18 и любых недель; правка `calc/input/2026-10-18.json`; `--write` в
  цепочку calc.js (R05, ASSUMPTION 2).
- Числовая методология: `calc/params.js`, веса, пороги, k — не трогать.
- Платные/ключевые поисковые API (NEWSAPI и т.п.) — только открытые ленты/HTTP (ASSUMPTION 3); адаптер
  под ключ — отдельная работа.
- Правка незакоммиченных файлов чужой сессии (см. `carried.md`): `index.html`, `how-to-read.html`,
  `sitemap.xml`, `.github/workflows/deploy.yml`, `about.html`, `docs/competitive-analysis.md`,
  `docs/regional-source-pool.md` — только чтение последнего как seed.
- Сайт (`js/**`, `index.html`) и публичный слой `data/public/**` — без изменений (если не потребуется
  сборка — `node build.js` не нужен).
