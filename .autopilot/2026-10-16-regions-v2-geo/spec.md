# Спецификация: Регионы v2 и справочник городов/стран (ADR 0028 + 0029)

## Задача

Читатель из Белграда или Тбилиси открывает индекс и не находит себя: в списке
шесть регионов, где вся Европа — одна строка «Европа» на 45 стран (в ней
растворены Украина, Беларусь, Балтия, Балканы, Северная Европа), а Кавказ и
Средняя Азия не отнесены ни к какому региону вовсе. Он не может выбрать «свой»
регион и не понимает, к чему относить его дельту. Хуже того — он пробует найти
свой город в поиске и не находит: ищутся только 34 вшитых города, а по странам
поиска нет вообще.

## Решение

Список регионов расширяется до двенадцати: единая `europe` расщепляется на семь
осмысленных для читателя областей («Россия и Беларусь», «Украина и Молдова»,
«Балтия», «Балканы», «Европа (ЕС и Север)», «Южный Кавказ», «Средняя Азия»),
пять мировых макрорегионов остаются как есть. Разбиение строгое: одна страна —
ровно один регион, спорные клетки сняты явными приоритетами. Таксономия
**версионируется отдельно от методологии** (глобальная математика не меняется):
старые недели показывают свою шестёрку, новые — двенадцать, а разрыв сеток
честно раскрывается заметкой.

Поиск перестаёт быть списком из 34 городов: подключается статический справочник
городов и стран (GeoNames, CC BY 4.0) — города от 50 000 жителей плюс все
столицы и административные центры регионов, с русскими именами. Справочник
подгружается лениво, только когда читатель открывает выбор региона, поэтому
стартовая страница не тяжелеет; поиск идёт от двух символов, а если города нет —
можно выбрать страну, которая даёт тот же регион.

## Решения по реализации

### Таксономия

- **Версионирование таксономии — поле `regions_taxonomy`** (`'1.0'` | `'2.0'`) в
  снапшоте и в справочнике; отсутствие поля = `'1.0'`. `PARAMS.methodology`
  остаётся `'3.0'` — глобальный ряд тренда непрерывен. *Почему:* ре-кат не
  меняет формулы, а бамп методологии выкинул бы новые недели из серии тренда.
- **Граница переключения — неделя пилота `2026-10-18`.** Константа
  `PARAMS.taxonomyV2From = '2026-10-18'`; функция `taxonomyForWeek(week)` →
  `'2.0'` для `week >= taxonomyV2From`, иначе `'1.0'`. Недели ≤ 2026-10-11
  (демо 1.0 и цепочка 3.0) остаются v1. *Почему:* forward-only, ретро-пересчёт
  и переписывание серии отвергнуты ADR 0028. *(ASSUMPTION — принято за
  пользователя: граница = дата пилота.)*
- **Источник правды — `data/regions/reference.json`** (уже приведён к структуре
  `taxonomies:{'1.0','2.0'}` + `taxonomy_version:'2.0'`); зеркало
  `data/regions/reference.js` (`window.CI_REGION_REF`). `js/region.js`
  зеркалит оба набора (`REGIONS_V1`, `REGIONS_V2`) — уже сделано.
- **Резолвер наборов — `js/data.js`**: `REGION_TAXONOMIES = {'1.0':[6 id],
  '2.0':[12 id]}`, `regionIdsFor(taxonomy = '1.0')`, `CURRENT_TAXONOMY = '2.0'`.
  `REGION_IDS` сохраняется как псевдоним текущего набора (обратная
  совместимость), но контракт и расчёт переходят на резолвер. Тест пинит
  тройное равенство: `regionIdsFor(v)` ↔ `regionForTaxonomy(v).map(id)` ↔
  `reference.json taxonomies[v].regions[].id`.

### Контракт снапшота (`js/data.js`)

- **`validate(snapshot)`** читает `snapshot.regions_taxonomy ?? '1.0'` и требует
  ровно `regionIdsFor(taxonomy)` — не единственную шестёрку. Поле
  `regions_taxonomy` опционально (старые недели его не несут), но если есть —
  непустая строка `'1.0'|'2.0'`. `background:boolean` без изменений.
- **Сайт берёт набор недели** через `regionForTaxonomy(snapshot.regions_taxonomy)`.

### Расчёт (`calc/`)

- **`engine.validate(input, params, regionIds)`** — новый третий параметр
  (whitelist регионов входа по версии недели); дефолт — текущий набор. Проверка
  `entry.regions[]` идёт по переданному whitelist, ошибка называет его.
- **`engine.regionalSignals(criteria, regionIds, params)`** уже принимает
  whitelist — calc.js передаёт набор недели.
- **Слепой новый регион без якоря → offset 0** (индекс = глобальный фон):
  ветка `nReg = 0` в `regionalIndex` при отсутствии `prevIndex` даёт нулевой
  офсет. Смещение старой `europe` новым регионам **не наследуется** — в
  `prevRegions` для новых id значения нет. После первой недели с атрибуцией
  якорь появляется сам (`nextChainState`).
- **`calc.js`** проводит неделю набором `regionIdsFor(taxonomyForWeek(week))`:
  `runWeek`, `nextChainState`, `writeWeek` (region-файлы), `main` (сид
  `prevRegions`) — по набору недели, а не по `REGION_IDS`.
- **Список частей недели — по версии.** `weekPartFiles(taxonomy)` →
  `['global','regions', ...regionIdsFor(taxonomy).map(id=>'region-'+id),
  'trend','drivers','sources']`; `WEEK_PART_FILES` сохраняется как
  `weekPartFiles('1.0')` (обратная совместимость с v1-парити). `loadWeekParts(week)`
  читает сначала `global.js`, узнаёт `regions_taxonomy`, затем читает части
  своего набора. `renderWeekCombined(week, parts)` не меняет контракт.
- **Новые `region-*.js` для v2-недели** пишет `renderRegionFile` (числа движка +
  `drivers`/`confidence` из прежнего файла-сида); для семи новых регионов
  редакционные сиды кладутся ДО `--write` — **ровно по 2 драйвера на каждый
  `region-*.js`** (та же конвенция, что для существующих регионов). `renderGlobal`
  пишет `regions_taxonomy`. `--write` сохраняет обе ворот (linkcheck + validate).
- **Частичный вход с пустыми Балканами не публикуется.** Балканы — цель пилота
  и не должны быть слепыми (`background:true`); если по ним нет R55-корпуса
  (≥2 независимых кластера на покрытый критерий) и водительских сидов —
  неделя не публикуется, а `weekly-calc` её тихо пропускает (редакционные ворота,
  держатся человеком; см. §Вне рамок).
- **Пайплайн** (`prepare-week.js`) не знает про регионы — правок не требует;
  `data/latest.js` грузит только `week.js` — правок не требует.

### Справочник городов и стран (`data/geo/`, ADR 0029)

- **Сеть — только на генерации.** Скрипт `data/geo/generate.js` (Node stdlib,
  ноль зависимостей) скачивает дамп GeoNames `cities15000.zip` **однократно**,
  распаковывает его встроенным минимальным zip-ридером (`node:zlib`
  `inflateRawSync` + разбор local file header, ~40 строк; zip полноценным
  stdlib не поддержан). Сырой дамп в репозиторий не едет; коммитятся вывод и
  генератор.
- **Состав городов:** население **≥ 50 000** + все столицы суверенных стран
  (ISO 3166-1) + 12 административных центров регионов (из `reference.json`
  `taxonomies['2.0'].regions[].adminCenter`) — независимо от населения.
- **Русские имена — из колонки `alternatenames` дампа** (перечень вариантов,
  среди которых есть кириллица): `name.ru` = первый кириллический вариант,
  иначе первичное имя; `name.en` = первичное. *(Трактовка `alternateNames`
  «язык ru» из ADR: дамп `cities15000` несёт смешанный список без языковых
  тегов; `alternateNamesV2.zip` (~80 МБ) выбран как несоразмерный. Качество
  русских вариантов неодинаково — риск ADR принят, добиваем точечно.)*
- **Страны — `countryInfo.txt` (ISO + EN) + курируемая таблица русских имён**
  в генераторе (объективные данные, не факт о пользователе — ~200 ISO→RU).
  Регион на страну — маппинг из `reference.json` обеих версий.
- **Вывод — два классических скрипта:**
  - `data/geo/cities.js` → `window.CI_GEO_CITIES` = массив
    `{ name:{ru,en}, country, region_v2, region_v1, pop }`;
  - `data/geo/countries.js` → `window.CI_GEO_COUNTRIES` = объект
    ISO2→`{ name:{ru,en}, region_v2, region_v1 }`.
  Страна вне разбиения (напр. `GL`, `AQ`) несёт `region_*: null`.
- **Ленивая загрузка — `js/geo.js`** (site-only ESM): `loadGeo()` при первом
  вызове вставляет `<script src="data/geo/cities.js">` и `.../countries.js`
  (классические скрипты, работает и с `file://`), ждёт загрузку, кэширует в
  памяти сессии и резолвит промис; повторный вызов отдаёт кэш. `data/geo/*` не
  собирается `build.js` и не подключается статически в `index.html`.
- **Поиск — `js/region.js search(q, catalog)`:** при переданном `catalog`
  (ленивый справочник) ищет префиксно по `name.ru`/`name.en` городов, по именам
  стран и регионов; минимум 2 символа; широкий запрос → топ-20 по `pop` +
  подсказка «уточните запрос». Без `catalog` — текущее поведение по `CITIES`
  (graceful fallback, тесты без сети). Найденный город/страна даёт `region_v2`
  (текущая таксономия). Fallback: города нет → страна → регион; страна без
  региона → пометка «регион не определён».
- **Атрибуция:** i18n-ключ `footer.geo` = «© GeoNames, CC BY 4.0» в футере
  (`js/sections/history.js`, `[data-role="footer-next"]`); ссылка на лицензию —
  в `privacy.html`.
- **Имена городов/стран — данные, не UI-строки** (словарное правило касается
  интерфейса).

### Сайт (регионы)

- **`js/sections/regions.js`** перебирает не `region.REGIONS`, а набор недели
  `regionForTaxonomy(snapshot.regions_taxonomy)` — 6 строк на v1-неделе, 12 на
  v2. `rankedRegions(snapshot)` возвращает те же строки.
- **`js/sections/hero.js`**: чипы и персональная карточка — по набору недели;
  личный регион подсвечивается, только если он есть в наборе отображаемой
  недели. `COORD_BOXES`/`refineRegionFromCoords` переточены на v2-идентификаторы.
  Пикер подключён к ленивому `js/geo.js` (первое открытие → подгрузка справочника)
  и к `region.search(q, catalog)`.
- **Забывание `'europe'`:** `current()`/`choose()` уже игнорируют значение вне
  текущего набора; при явном ручном выборе — одноразовый тост (i18n-ключ).
- **Заметка о смене сетки** — чистый шов `regionalGridNote(lang, viewed, current)`
  рядом с `methodologyNote` в `js/sections/history.js`; ключ i18n
  `history.taxonomy.note` («Региональная сетка обновлена с {date}»); показывается
  только при расхождении версии. Дата берётся из константы `TAXONOMY_V2_FROM`
  (`js/data.js`). *(Секция истории скрыта — заметка, как и `methodologyNote`,
  дормантна; отражено в Открытых местах.)*
- **`node build.js` обязателен** после правки `js/**`; бандлы коммитятся.

### Личный регион

- **Порядок `detect`** (уже в `js/region.js`): специфичные пояса раньше
  catch-all; российские `Asia/*` — **явным списком выше центральноазиатских**
  (иначе Алматы/Астана перехватывались бы раньше российских поясов); `Europe/` —
  последним, в `eu-north-europe`.
- **Тихий откат при неудаче `detect`:** если пояс не распознан, регион не
  подсвечивается и сайт показывает глобальное без сообщения (тот же путь, что
  «нет личного региона»); одноразовый тост даётся **только** при явном ручном
  выборе устаревшего/недоступного значения.
- **Узкие экраны:** витрина — 12 строк; чтобы список не вытеснил остальное,
  личный регион **пинится** вверху (класс-модификатор строки), остальные
  скроллятся. *(Риск ADR 0028 «при провале Балкан вниз — вернуться к пину
  личного региона»; решаем пином сразу.)*
- **`CITIES` переточен под v2** (уже в `js/region.js`): существующие города
  размечены v2-id, добавлены города новых регионов; `CITIES` остаётся
  офлайн-fallback поиска, когда ленивый справочник не загружен.

## Границы и швы

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `js/data.js` | контракт снапшота, наборы id по версии | `regionIdsFor(taxonomy)`, `CURRENT_TAXONOMY`, `REGION_IDS`, `TAXONOMY_V2_FROM`, `validate(snapshot)`, `week/latest/listWeeks` | разбор версии, схему полей |
| `js/region.js` | реестр двух таксономий, личный регион, согласие | `REGIONS_V1`, `REGIONS_V2`, `REGIONS`, `regionForTaxonomy(v)`, `detect/current/choose/isCurrent/get`, `search(q, catalog?)` | storage-ключи, consent, порядок префиксов |
| `js/geo.js` *(новый)* | ленивая загрузка `data/geo/*` | `loadGeo() -> Promise<{cities,countries}>`, `geoSearch(q, catalog)`, `resolveRegion(countryOrCity, catalog)` | инъекцию `<script>`, кэш, разбор `window.CI_GEO_*` |
| `js/sections/regions.js` | ранжированный список недели | `rankedRegions(snapshot)`, `render(appState)` | порядок и разметку строк |
| `js/sections/hero.js` | пикер (чипы + поиск), персональная карточка | `isBackgroundRegion`, `refineRegionFromCoords`, `render` | DOM панели, тосты, геолокацию |
| `js/sections/history.js` | футер, заметки о версии | `methodologyNote`, `regionalGridNote(lang, viewed, current)`, `nextPublication` | разметку секции |
| `calc/engine.js` | формулы §5/§7, whitelist входа | `regionalSignals(criteria, regionIds, params)`, `regionalIndex(global, region, params)`, `validate(input, params, regionIds)`, `buildDriversCore`, `CRITERIA` | внутреннюю математику |
| `calc/calc.js` | прогон недели, файлы снапшота | `runWeek`, `writeWeek`, `renderWeekCombined`, `loadWeekParts`, `weekPartFiles(taxonomy)`, `renderGlobal`, `renderRegionFile`, `renderRegions`, `nextChainState` | правит части недели на диске |
| `data/geo/generate.js` *(новый)* | генерацию справочника | CLI `node data/geo/generate.js` → `data/geo/cities.js`, `data/geo/countries.js` | скачивание, zip-разбор, эвристику RU-имён |

**Швы для тестов** (поведение проверяется только здесь, чистые функции без DOM/сети):
`regionIdsFor` + `validate` (data.js), `regionForTaxonomy`/`detect`/`search` с
инъекцией `catalog` (region.js), `geoSearch`/`resolveRegion` над инъекцией каталога
(geo.js), `regionalGridNote` (history.js), `rankedRegions` (regions.js),
`weekPartFiles`/`renderWeekCombined`/`loadWeekParts`/`regionalSignals`/`validate`
(calc). Ленивый загрузчик `loadGeo` тестируется с подменённым `document`/заглушкой
инъекции — без сети.

## Вне рамок

| Требование | Почему не сейчас |
|---|---|
| R12 (R55-корпус по Балканам), R13 (публикация недели 10-18) | редакционная работа человека: вход и семь сидов (по 2 драйвера на `region-*.js`) кладёт редактор (§10.1); Балканы не должны быть слепыми, частичный вход с пустыми Балканами не публикуется. Этот прогон готовит только код/пайплайн; `weekly-calc` тихо пропустит неготовую неделю |
| ре-кат Китая/Турции/Индии | прямо отложено ADR 0028 отдельным прогоном |
| транслитерация латиница↔кириллица, fuzzy-поиск | отложено ADR 0029 (следующий шаг по факту обращений) |
| admin1-центры (десятки тысяч строк) | отложено ADR 0029 (поднимаем при подтверждённой нужде) |
| R08.1 (заметка) в видимом месте | секция истории скрыта из `index.html`; шов реализуется, но дормантен (Открытые места) |
