# Спецификация: API-контракт и справочники публичного слоя

## Задача

Тому, кто хочет брать данные Cassandra Index не глазами, а кодом, сейчас приходится
угадывать: какие файлы публичны, что в них за поля, какая версия и можно ли на них
ссылаться. Шесть путей описаны, а `validation.json`, `forecast-ledger.json`,
`changelog.json` и `digest/*` лежат рядом — публичные, но вне контракта. «Источник
данных» получается неполным, и любой новый публичный файл снова окажется вне его.

## Решение

У публичного слоя `data/public/**` появляется один полный машинный контракт:
JSON Schema на каждый публичный JSON (включая `validation`, `forecast-ledger`,
`changelog`, `digest`), `docs/api.md` с эндпоинтами, полями, версией, лицензией и
примерами — по всем файлам, и тест-сторож, который падает, если на диске появился
публичный JSON без схемы или без строки в документации. Справочники `regions`,
`criteria`, `methodology` и понедельные `weeks/<date>.json` остаются как есть; новых
полей, новой математики и новых зависимостей нет. Сайт не меняется: `api.html` не
заводится, документ живёт в репозитории.

Режим запуска — `semi`, глубина — `normal` (аргументы задачи не задавали режим;
пользователь отдельно попросил не спрашивать разрешения на каждом шаге).

| 16 | R13i | Как потребитель, я получаю файлы с CORS, ETag и cache, как раньше | HTTP-поведение GitHub Pages не меняется; `docs/api.md` фиксирует `Access-Control-Allow-Origin: *`, ETag и cache |

Глубина (`normal`): проработаны «неверный вход» (невалидный публичный файл → тест
называет файл и путь), «сбой» (битый/отсутствующий файл → явная ошибка теста, а не
молчаливый пропуск), «рост» (новый публичный артефакт → сторож), «последствия»
(пересборка идемпотентна). «Первый запуск»/«пусто»/«прерывание»/«границы доступа» к
статистическому слою не применимы — данных до первой недели нет, а доступ публичный.

## Решения по реализации

- **Где живут схемы.** `calc/public-contract.js` — единственный источник. В
  `SCHEMA_NAMES` добавляются `changelog`, `digestIndex`, `digestWeek`, `validation`,
  `forecastLedger`; `schemaDocs()` начинает возвращать 11 файлов. Почему: схемы уже
  собираются здесь, а `writePublicData` уже пишет их циклом.
- **Без импорта генераторов.** `public-contract.js` не импортирует `backtest.js`,
  `ledger.js`, `digest-export.js`: это тяжёлые модули с сетью/диском и потенциальные
  циклы. Формы описаны статически, а расхождение ловит тест на реальных файлах.
- **Только поддерживаемые ключевые слова.** Минимальный валидатор в тестах понимает
  `type`/`const`/`enum`/`required`/`properties`/`additionalProperties`/`items`/
  `minItems`/`maxItems`/`minimum`/`maximum`/`minLength`/`pattern`/`$ref`. Nullable — через
  массив типов (`['number','null']`), не через `anyOf`. Почему: не тащить валидатор.
- **Версия схемы не растёт.** `PUBLIC_SCHEMA_VERSION` остаётся `1`: новых полей в
  существующих файлах нет, добавлены только описания ранее бесхозных файлов.
- **Сторож — тест, а не генератор.** Проверка «все публичные JSON покрыты» живёт в
  `tests/public-contract.test.js` (обходит `data/public/**` и сверяет с `schemaDocs()`
  и текстом `docs/api.md`). Почему: генератор не должен падать на чужом артефакте.
- **Документ — в репозитории.** `docs/api.md`, без `api.html` и без правок
  `index.html`/навигации.
- **ADR 0062 дополняется** датированной записью «контракт покрывает весь публичный
  слой», без нового номера: решение не меняется, меняется охват.

## Вне рамок

| Требование | Почему не сейчас |
|---|---|
| Хвосты прошлой сборки (ACLED, lead/lag, фикстуры, `calc/backtest.js` в `AGENTS.md`, баги `calc/ledger.js`) | пользователь: «задача про API-контракт, хвосты к нему не относятся» |
| Страница `api.html` на сайте | пользователь: «оставить в репозитории: бриф называет именно файл, а сайт — витрина, не справочник» |
| Новые публичные поля или метрики | R08: данные уже есть, новых расчётов нет |
| JSON Schema на CSV/SVG | это не JSON; описаны в `docs/api.md` текстом |
| Машиночитаемый каталог эндпоинтов (index of indexes) | не просили; таблица в `docs/api.md` закрывает потребность |
