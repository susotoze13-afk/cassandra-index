# Спецификация: Расчёт индекса за 3 недели + калибровка

## Задача

Редактор сервиса Cassandra Index сейчас ставит недельные значения индекса
вручную — «на глаз», по ощущению от наблюдений. Это не воспроизводимо,
не защищено от ошибки и не объяснимо читателю: никто не может ответить,
почему на этой неделе 72, а не 65. Параметры модели при этом остаются
стартовыми «до калибровки», хотя методология требует их подобрать
и зафиксировать с аудиторским следом.

## Решение

В репозитории появляется расчётный пайплайн по METHODOLOGY.md §4–§5:
закодированные сигналы критериев за неделю → скоры драйверов → глобальный
индекс с инерцией → региональные индексы. Три последние недели ряда
(2026-08-30, 2026-09-06, 2026-09-13) пересчитаны этим пайплайном, их
глобальные и региональные значения в `data/` заменены расчётными.
Параметр насыщающей кривой k (и проверка весов/порогов) подобраны на
якорных исторических сценариях §9, результат зафиксирован в журнале
калибровки с анализом чувствительности ±20 %.

## Решения по реализации

1. **Стек — Node ≥ 18, ноль зависимостей** — как весь репозиторий
   (AGENTS.md: любой импорт npm ошибка). Пайплайн — обычные скрипты
   `node calc/…`, не ES-модули сайта.
2. **Каталог `calc/`** — расчётное ядро и входные данные. Не публикуется
   (в выкат идут только index.html, privacy.html, css/, js/, data/).
3. **Входные сигналы — `calc/input/<неделя>.json`**: по каждому критерию
   Д1–Д9 — значение шкалы, покрытость (сколько независимых источников /
   кластеров), уверенность драйвера с причиной. Непокрытый критерий —
   `null`. Файл несёт снапшот численных параметров (веса, α, λ, ρ, U_abs,
   k, β↑/β↓, пороги покрытия) — требование §10 о воспроизводимости.
4. **Формулы — один модуль ядра** (`calc/engine.js`), побитово по §4.2–§5.4
   и §7: скор драйвера, короборация Д9 (включая пониженную для Д9.6b),
   агрегация §5 шаги 1–8, региональная модель отклонения с e_struct/e_dyn,
   зеркалирование шока, слепые регионы.
5. **Стартовые недели ряда (08-02…08-23) не трогаем** — это опубликованная
   «история» демо-ряда; инерция для пересчёта 08-30 берётся из опубликованного
   значения 08-23, как и предписывает §5.4 (округление только при публикации,
   внутреннее float-значение для демо-ряда реконструируем из опубликованного).
6. **Калибровка — `calc/calibrate.js`**: якорные сценарии как входные
   профили, перебор k по сетке, проверка попаданий в кластеры §9,
   таблица чувствительности (k ±20 %, веса ±20 %) в журнал.
   Экспертно-фиксированные параметры (α, λ, ρ, U_abs, β, γ, κ — §10.1) не
   калибруются, только проверяются на устойчивость.
7. **Кодирование сигналов 3 недель** — из наблюдений и источников, уже
   лежащих в снапшотах, дополнено открытым веб-поиском по событиям окон;
   каждый непустой сигнал ссылается на источники из `sources.js` недели
   либо на найденные открытые публикации.
8. **Пересчитанные снапшоты** — правятся `global.js`, `regions.js`,
   `region-*.js` (значения и Δ) трёх недель; `trend.js` трёх недель
   пересобирается из обновлённого хвоста ряда; наблюдения/источники
   драйверов (drivers.js, sources.js) сохраняются — пересчитываются только
   числа. `methodology: "1.0"` не меняется (все 7 недель одной версии,
   сайт показывает строку смены версии только при расхождении).
9. **Журнал калибровки — `docs/calibration-journal.md`**: до/после,
   метод (rolling-origin, сетка k), попадания якорей, чувствительность
   ±20 %, что осталось экспертным и открытым вопросом №1 методологии.

## Границы и швы

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `calc/engine.js` | формулы методологии | `driverScore(criteria, α)`, `aggregateDrivers(drivers, params)`, `applyInertia(value, prev, opts)`, `regionalIndex(global, regionSignals, params)` → чистые объекты `{index, state, delta, internal}` | нормировки шкал, защиту от деления на ноль, округление |
| `calc/params.js` | снапшот численных параметров версии | `PARAMS` (веса, α, λ, ρ, U_abs, k, β, пороги) + `list()` | значения по умолчанию |
| `calc/input/*.json` | закодированные сигналы недель и якорей | схему валидации (`validate(input) -> errors[]`) | — |
| `calc/calc.js` | запуск расчёта недели | CLI: `node calc/calc.js <week>` — печать результата | чтение/парсинг входов |
| `calc/calibrate.js` | подбор k, якорные прогоны, sensitivity | CLI: `node calc/calibrate.js` — печать таблицы для журнала | сетку перебора |

Швы для тестов — ровно один: чистые функции `calc/engine.js` (+ валидация
входов). Поведение проверяется только через него; CLI — тонкая обвязка
без собственной логики.

## Открытые места

Пользовательских фактов, которые ждали бы подстановки, нет — нет ни цен,
ни текстов, ни адресов. Исторические якорные профили кодируются по публично
известным событиям (Википедия/открытые обзоры); это модельные профили для
калибровки шкалы, а не архивные реконструкции — оговорка фиксируется
в журнале.
