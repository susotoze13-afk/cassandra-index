# 06 — Сайт: блок «Как выбираются источники» + граница в method.gaps + пометка sensitivity

**Требования:** R05, R02 (пометка на сайте)
**Blocked by:** 02 (поле `sensitivity` в контракте снапшота)
**Зона:** `js/i18n.js` · `js/sections/methodology.js` · `js/sections/*` (quality-блок) · `js/bundle*.js` (через `node build.js`)
**Волна:** 3
**Status:** ready

## Что должно заработать

1. Секция «Методология»: новый блок `method.sources.title` + 3 пункта
   `method.sources.1–3` (выбор → проверка → устойчивость), подключается в
   `LIST_KEYS` (`js/sections/methodology.js`). Черновик Q19 с правками Q21/Q22:
   - 1 (Отбор): 45 критериев фиксированы заранее; правило «минимум два
     независимых кластера либо один первичный источник»; входы недели публикуются
     открыто — URL, даты, классификация каждого источника.
   - 2 (Проверка): ссылки проверяются автоматически; выбор источников проходит
     чек-лист красной команды, итоги — в журнале аудита.
   - 3 (Устойчивость): **как метод** (Q21): «чувствительность считается по
     каждому домену и кластеру недели; раскрываем результат, если он превышает
     5 пунктов» — без обещания «≤5 = идеально».
2. `method.gaps.5` (Q22): честное признание — «нет репрезентативной выборки: это
   граница метода, а не изъян; поле инфополе не пылесосится» (формулировка в тоне
   `method.gaps.1–4`, без табу-лексики PRD §11.5).
3. Quality-модалка: при `sensitivity > 5` п.п. — пометка «неделя чувствительна к
   источникам» (ключ `quality.modal.sensitive`), значение ≤ 5 не показывается.

## Из брифа, дословно

> «у тебя нет достоверной выборки, а для достоверной выборки надо пылесосить все инфополе, у тебя просто мощностей таких нет» — граница метода публикуется в method.gaps

Протокол Q12, Q19, Q21, Q22; ADR 0020.
