# Границы, решённые в спецификации

## Правила проекта (из «Договорились» прошлой сборки)

- Цитаты живут полем `quotes: [{criterion, text}]` в записи источника R55; опционально.
- Публикуются цитаты только там, где есть корпус текстов; у остальных недель цитат нет.
- Цитата принимается только дословная (ADR 0042); нет корпуса — запись отклоняется.
- `events[]` в якорях — только при точном воспроизведении значения (ADR 0043).
  Числа опубликованных недель не меняются — «Без сдвига чисел».
- Скалярная/ковариационная калибровка k×severity — вне рамок.
- Пуш в master — за пользователем. Коммиты этого прогона — локальные, путями.

## Жёсткие правила репозитория

- Стек: чистый Node ≥ 18 + браузерный JS, ESM, ноль зависимостей (import npm/CDN — ошибка).
- Проверка одной командой: `node --test` (из корня, без аргументов). Один файл:
  `node --test tests/<имя>.test.js`.
- После любой правки `js/**` — `node build.js`; `js/bundle.js` и `js/bundle-privacy.js`
  коммитятся. Руками бандлы не править.
- `data/**` не пересчитывается этим прогоном; недели 08-30…10-18 не трогаются.
- `calc/input/**` в этом прогоне не меняется: флаг добавляется в схему, но ни одна неделя
  его не получает.
- Не трогать: `cassandra-index-prototype.html`, `PRD_Casandra_Index.md`, `.autopilot/`
  (кроме своей папки — её не трогает исполнитель), чужие правки в рабочем дереве.
- Текст для пользователя — только через `js/i18n.js`; DOM — только
  `document.createElement` + `textContent`.
- Коммит и пуш — за оркестратором; исполнитель не коммитит.

## Границы модулей

### `calc/engine.js` — семантика `intersection`

Владеет: объявлением `CRITERIA`, нормировкой критерия, скором драйвера, Д8, Д9,
валидацией входа.

Открывает наружу (имена не меняются, кроме перечисленного):

- `normalizeCriterion(entry, params)` — без изменений поведения;
- `buildDriversCore(criteriaIn, confidenceLevels, params)` — в записи каждого критерия
  драйвера появляется поле `intersection: true` (только когда оно истинно во входе;
  иначе поле отсутствует — тесты и потребители, читающие `{value, covered}`, не ломаются);
- `driverScore(driver, params)` / `d8Strength(group, params)` / `aggregateD9(group, params)` —
  критерий с `intersection === true` **не входит ни в числитель, ни в знаменатель** скора,
  но сохраняет `covered: true` для счётчика покрытия;
- `validate(input, params, regionIds)` — `intersection` допускается только как
  `boolean`; `intersection: true` на критерии, который не покрыт (`covered !== true`),
  либо на `null` — ошибка входа.

Скрывает: как именно считается `E/N − α·B/N` (не меняется), порядок обхода.

Шов тестов: `buildDriversCore` + `driverScore` + `validate` — чистые функции, без DOM и сети.

### `calc/calc.js` — отчёт о пересечениях

Владеет: прогоном недели, покрытием, печатью.

Открывает: `runWeek` кладёт в результат `intersections: string[]` — отсортированные id
критериев с `intersection === true`; `printWeek` печатает одну строку
`пересечения: N (D1.2, …)` только когда N > 0. Снапшот не меняется.

Скрывает: формат файлов `data/`.

### `METHODOLOGY.md` — единственный источник правил

§4.1.5 описывает правило и поле; §1.2 — формальные критерии «глобального» и границу
с порогами состояний. Код ссылается на документ, не наоборот.

### `js/risk.js` — только комментарий и паритет

Пороги (`SCALE`) не меняются. Шапка файла ссылается на METHODOLOGY §1.2/§9.
Паритет-тест читает таблицу §9 из `METHODOLOGY.md` и сверяет с `SCALE`.

### `js/i18n.js` — одна уточняющая фраза

Новых ключей нет; правится существующий `method.definition.4` (или `.3`), чтобы публичный
текст явно называл пороги состояний границей публикационной шкалы, а не критерием конфликта.
