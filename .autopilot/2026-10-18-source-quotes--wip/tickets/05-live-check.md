# 05 — Проверка живого сайта после выката

**Требования:** R02, R02.1, R06i, R07i
**Зависит от:** 02, 03, 04
**Зона:** `calc/live-check.js` · `tests/live-check.test.js`
**Волна:** 3
**Ревью:** нет
**Модель:** обычная

## Что должно заработать

После выката можно одной командой убедиться, что прод отдаёт то, что собрано:
`node calc/live-check.js` скачивает `data/latest.js` и по неделе `week.js` с `cassindex.ru`,
выполняет их в `vm` (как это делает `loadSnapshotPart`), прогоняет контракт `js/data.js`
и печатает отчёт: сколько недель загрузилось, у каких есть цитаты источников, проходит ли
витрина доверия. Ненулевой код выхода — если прод отдаёт не то.

Истории 12–13, 15; Решение §5.

## Критерии приёмки

- [ ] `calc/live-check.js` — CLI без зависимостей, ESM, сеть только через переданный
      `fetchImpl` (по умолчанию `fetch`), база по умолчанию `https://cassindex.ru`,
      переопределяется `--base`
- [ ] скрипт проверяет: `data/latest.js` грузит 12 недель; каждая неделя проходит
      `js/data.js validate`; `week.js` недель 09-20 и 09-27 несут `quotes` у источников;
      `trustFacts` даёт `quoted.count > 0` для этих недель
- [ ] `tests/live-check.test.js` гоняет скрипт на поддельном `fetchImpl` с локальными
      файлами `data/` — без сети; падение контракта и отсутствие цитат ловятся тестом
- [ ] `node calc/live-check.js --base http://localhost:<порт>` проходит на локальной
      раздаче `data/` (статический сервер), отчёт читаем человеком
- [ ] `node --test` зелёный; скрипт не входит в бандл сайта и не публикуется
      (`deploy.yml` публикует только `index.html`, `privacy.html`, `icon.svg`, `css/`, `js/`, `data/`)
