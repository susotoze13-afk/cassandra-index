# Спецификация: Cassandra Index (сборка v1.3)

Источник: `2026-09-20-brief.md` → `PRD_Casandra_Index.md` v1.3. Решения брифинга от 2026-09-20:
весь сайт по PRD; первый визит имитирует IP-детект по часовому поясу браузера (выбор не сохраняется);
эталон — `cassandra-index-prototype.html` и нормативные токены PRD.

## Задача

Человек открывает сайт и за 3 секунды понимает, насколько мир близок к глобальному военному
конфликту, насколько это касается его региона и города, ухудшилась ли ситуация за неделю и насколько
свежи данные — без паники, без обратного отсчёта, с возможностью за один клик увидеть источники
по каждой причине изменения. Через 10–15 секунд он может назвать три главные причины изменения.

## Решение

Полностью статический двуязычный сайт (RU/EN) без бэкенда и без сборки: `index.html` с пятью
разделами навигации (Обзор, Регионы, Тренд, Методология, История и источники), отдельная
страница политики приватности, предвычисленные недельные снапшоты как JS-файлы (работают
и с `file://`, и с любого статического хостинга), SVG-графика без библиотек. Демо-данные —
согласно PRD «в прототипе — demo-данные». Существующий прототип — референс реализации,
сайт строится заново по структуре ниже.

## Решения по реализации

1. **Стек**: чистый HTML/CSS/ES-модули, ноль зависимостей, ноль сборки. Почему: PRD требует минимум JS и статику; прототип уже доказал, что всё реализуется без библиотек.
2. **Данные — JS-файлы, не fetch**: снапшоты подключаются `<script src="data/.../global.js">`, кладут данные в `window.CI_DATA` (отступление от буквы R63, где пути названы `*.json`; обоснование ниже). Почему: сайт должен работать по двойному клику (`file://` блокирует fetch, а `.json` нельзя подключить script-тегом) и оставаться «предвычисленными недельными данными» по §9.
3. **Контент первого экрана в HTML**: дефолтная русская разметка hero идёт в исходном HTML (мгновенный LCP), JS заменяет данными снапшота и переключает язык. Почему: «core index доступен без ожидания клиентского JS» (§13).
4. **i18n — словари RU/EN + ключи `data-i18n`**; плюрализация RU правилом 1/2–4/5+ в коде, даты — `Intl.DateTimeFormat`. Почему: §11.2 требует плюрализацию и форматы без ручных исключений (открытый вопрос §19.24 закрыт правилом).
5. **Регион по часовому поясу**: `Intl.DateTimeFormat().resolvedOptions().timeZone` → таблица маппинга IANA-префиксов → регион. Почему: решение брифинга; честная замена IP-детекту для статики, ничего не сохраняет и никуда не отправляет.
6. **Справочник**: 6 регионов (Европа·Амстердам, Восточная Азия·Токио, Ближний Восток·Бейрут, Северная Америка·Вашингтон, Южная Азия·Нью-Дели, Африка·Найроби) + ~30 городов для автокомплита. Почему: расширяет прототип до полноценного ranked-листа; таксономия §19.13 остаётся демо.
7. **Статус риска** — чистая функция порогов §10 (0–20…97–100) → ключ словаря + тон палитры §14.4. Почему: одно место для порогов, версионируемое поле методологии в снапшоте.
8. **Графика — инлайн-SVG**, генерируется из данных. Почему: §13 запрещает тяжёлые библиотеки; SVG доступен скринридерам и клавиатуре.
9. **Share** — canvas 1200×630 → PNG → download; Web Share API с файловой шарой где поддерживается. Почему: без бэкенда нечем иначе отдать картинку.
10. **Крит-режим — функция данных**: рендерится, когда global.index ≥81 текущего снапшота; демо-панель (A01) подменяет данные только в сессии. Почему: режим должен срабатывать от реальных данных, а не от кнопки.
11. **Структура**: одна `index.html` с якорными разделами (как в прототипе) + отдельная `privacy.html`. Почему: IA §3 сохраняется, навигация — якоря; многостраничность не нужна и дублировала бы i18n.
12. **Тесты**: `node --test` для чистых модулей (`i18n`, `risk`, `region`, схема данных) — без DOM, без зависимостей. Почему: единственный стабильный шов статического фронта; Node ≥18 предполагается, проверка — в начале сборки.

## Границы и швы

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `data` | снапшоты, указатель latest, схема | `latest()`, `week(date?)`, `listWeeks()`, `validate(snapshot)` | загрузку script-тегов, дефолты при битых файлах |
| `i18n` | словари RU/EN, плюрализация, форматы | `t(lang,key,vars)`, `plural(lang,n,forms)`, `date(lang,iso,short?)` | правила склонения, Intl-настройки |
| `risk` | шкала §10, тона палитры | `status(index)`, `tone(statusId)`, `deltaTone(change)` | пороги, границы диапазонов |
| `region` | справочник регионов/городов, детект, хранение | `detect(tz)`, `current()`, `choose(id,{persist})`, `search(q)` | маппинг tz→регион, ключи localStorage |
| `render` | вся DOM-разметка всех секций | `renderAll(appState)`, `renderSection(name,appState)` | aria-атрибуты, svg-геометрию, состояния контролов |
| `app` | оркестрация, data-state, URL `?week=` | `init()` | связывание событий, демо-подмену |

Швы для тестов (Phase 5 тестирует только здесь): `i18n`, `risk`, `region.search/detect`, `data.validate` — чистые функции без DOM.

проработка; владелец справочника городов; UX-измерение заголовка; поведение заголовка
в других языках; минимальный набор полей источника; порядок сортировки источников;
запоминание раскрытия аккордеона; панель тренда на мобильных; выбор города-представителя;
порог уверенности IP-детекта; доверие без блока уверенности; сложная плюрализация
(закрыта в сборке правилом 1/2–4/5+); aria-live для тренда (в сборке данные дублируются
в aria-label точек — решение §19.25 на уровне сборки).
