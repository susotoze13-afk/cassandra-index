# Спецификация: Пересчёт индексов за 3 месяца с расширенными источниками + публикация

## Задача

Сервис публикует еженедельный индекс конфликтного риска, но три недели из
пересчитываемой цепочки (30.08, 06.09, 13.09) построены на покрытии 5 из 45
критериев без источников — числа висят в воздухе. Дата покрытия данных на
неделе 20.09 указана как «по 13.09», хотя анализ должен заканчиваться днём
публикации. Раздел «Методология» на сайте не показывает, из каких 45 критериев
собирается индекс. Документ предпродакшен-вопросов утоплен в уже решённом.

## Решение

Три недели цепочки получают полные входы: реальные источники по схеме R55
внутри окна своей недели, покрытие критериев доведено до максимума (ориентир —
уровень недели 20.09: 42/45, слепыми остаются только критерии Д9 без
наблюдаемых сигналов в окне). Вся цепочка 30.08 → 20.09 пересчитывается
пайплайном и публикуется. Поле «Данные по» каждой пересчитанной недели —
конец окна анализа включительно (= дата публикации). На сайте, в разделе
«Методология», появляется полный список 45 критериев по драйверам D1–D9 —
названия и содержание, без формул. Документ «Открытые вопросы перед
продакшеном» перестраивается: сверху — только нерешённые вопросы (фактически
это пять пунктов P2 «после запуска»), решённые — в архивный раздел «Решено».

## Решения по реализации

- **Окно анализа.** Публикация недели W покрывает W−7…W включительно;
  `through` (дата покрытия) = W. Меняется только в пересчитываемой цепочке
  (30.08–20.09); демо-история 02.08–23.08 непересчитываема и не трогается.
  Почему: прямое требование брифа, обобщённое на цепочку для согласованности.
- **Расширение входов** идёт по образцу недели 20.09 (коммит be044ca): рой
  исследовательских агентов ищет реальные статьи по каждому непокрытому
  критерию внутри окна недели; результат — поле `sources` (R55) во входе,
  `criteria[].covered/value/sources` (inline-записи с url/date/cluster/type),
  обновлённый `driverConfidence`. Почему: формат уже принят пайплайном и
  воротами R55/linkcheck.
- **Редакционные сиды.** Перед `--write` для каждой недели обновляются
  `data/<неделя>/drivers.js` (ровно 3 драйвера) и `region-*/drivers` —
  verbatim-записи источников из входа по id (требование ворот validate).
  Почему: без сидов контракт отклонит запись.
- **Список критериев на сайте** — новый статический модуль `js/criteria.js`
  (данные: 45 id, драйвер, названия и короткие описания RU/EN, без формул),
  рендерится разделом «Методология» (`js/sections/methodology.js`) через
  словарь i18n. Движок сайта не импортирует calc/ (конвенция), поэтому
  список дублируется; тест-паритет с `engine.CRITERIA` страхует от рассинхрона.
- **Публикация** — по конвейеру AGENTS.md: commit за оркестратором, push в
  master, GitHub Actions выкатывает Pages; живой URL проверяется после выката.
  Публикация явно заказана брифом (ASSUMPTION A-R01).

## Границы и швы

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `calc/input/<неделя>.json` | входные сигналы и источники недели | схему уже фиксируют `validate`/`validateInputSources` (calc.js) | editorial-оценки значений |
| `calc/calc.js` + `calc/engine.js` | пересчёт, классификация, рендер снапшотов | `runWeek`, `classifyPublication`, `renderGlobal` (through = дата недели) | формулы §4–§7 |
| `js/criteria.js` (новый) | статический список 45 критериев (id, драйвер, RU/EN название и описание) | один массив констант; нет функций | ничего |
| `js/sections/methodology.js` + i18n | рендер раздела «Методология» | регистрация секции в app.js (существующий шов) | DOM-строение |
| `js/data.js` | контракт снапшотов | `validate` — ворота перед записью | — |
| `docs/preproduction-decisions.md` | редакционный статус вопросов | — | — |

Швы для тестов (существующие, новых не добавляем кроме паритетного):
- `validateInputSources` / `collectSourceItems` / `classifyPublication` из calc.js;
- `engine.CRITERIA` ↔ список в `js/criteria.js` (паритет 45 id);
- чистый рендер раздела методологии (по аналогии с существующими тестами секций).
