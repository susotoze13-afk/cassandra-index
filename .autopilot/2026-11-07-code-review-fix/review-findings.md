# Ревью кода диффа сборки 4.0 (b2bca23..b60089c)

Дата: 2026-11-07. Объём: кодовые пути `calc/`, `js/`, сборщики, правленые тесты.
Каждый файл диффа прочитан целиком вместе с неизменённым контекстом стыковки.
Проверочный прогон: `node --test` по 11 затронутым тест-файлам → 157 pass / 0 fail.

## Находки

### calc/calc.js

**F1. Молчаливый парсинг `signals` в `renderWeekCombined` — calc/calc.js:362–385.**
Сигналы достаются regex'ом `^\s*s\.regions = (\{[\s\S]*\});?\s*$` и `JSON.parse` из
текста части `regions`; при несовпадении regex или битом JSON `signalsTail` остаётся
пустым — **без ошибки**, week.js записывается без signals. Сейчас не проявляется:
часть генерируется самим пайплайном (`renderRegions`) в совместимой форме, а потеря
signals ловится пином `tests/week-combined-parity.test.js` («week.js цепочки несёт
signals») и диск-пином `tests/regional-deviation.test.js:62–80`. Риск — только при
ручной правке формы части (мёртвый код обходится молча до зелёного прогона тестов).
Класс: **заметка**. Проверка: в синтетике `tests/week-combined.test.js` записать
regions-часть в однострочной форме без пробела вокруг `=` — signals исчезнет без
исключения; защита — только parity-тест.

### tests/regional-deviation.test.js

**F2. Мёртвое исключение сторожа n0 с устаревшим обоснованием — tests/regional-deviation.test.js:105–110.**
Страж `\bn0\b` по `calc/` пропускает `public-contract.js` со ссылкой на «зону
тикета 02», но в этом же диффе n0 удалён из `methodologyDoc` (public-contract.js:125 —
теперь там только комментарий со словом «n0»). Исключение стало мёртвым, а его
комментарий недействителен: именно public-contract.js — публикующий файл, и
возврат n0 в раскрытие методологии страж не поймает. Класс: **заметка**.
Проверка: вернуть `n0: PARAMS.n0` в methodologyDoc — тест останется зелёным.

### calc/public-export.js

**F3. Удаление старого каталога схем захардкожено на v1 — calc/public-export.js:~497.**
`rmSync(publicDir/schema/v1)` удаляет каталог прежней версии, но литерал `v1` не
связан с `PUBLIC_SCHEMA_VERSION`: при следующем бампе (v3) устаревшая `schema/v2`
останется на диске рядом с v3 — ровно та ситуация двух сосуществующих форм, которую
комментарий называет целью удаления. Класс: **заметка**. Проверка: в тесте поднять
PUBLIC_SCHEMA_VERSION до 3 — `schema/v2` не удаляется.

### article-build.js + js/article.js

**F4. Точность «одна десятичная» не enforced на границе конвертера — article-build.js:41–44, js/article.js:59–64.**
`NUM = '\d+(?:\.\d+)?'` принимает две и более десятичных (`64.44`), а
`validateArticle` требует только `Number.isFinite`. Редакционный выпуск с индексом
региона `64.44` пройдёт обе воротины, хотя ADR 0069 фиксирует слой с одной
десятичной. Проявления нет (выпуски пишет редактор по форме 4.0), пины чисел в
`tests/article.test.js` зелёные. Класс: **заметка**. Проверка: `validateArticle`
с `regionRows:[{index:64.44,delta:6.9}]` → `[]`.

### calc/engine.js (не дифф, контекст кандидатов прошлой сборки)

**F5. `stateOf` без нижней границы: `stateOf(-1)='calm'`, тогда как `risk.status(-1)=null` — calc/engine.js:30–36 vs js/risk.js:23–26.**
`status()` режет `index < 0` и `> 100`, `stateOf()` — только `<= max`; отрицательный
индекс классифицируется как 'calm'. Латентно: опубликованные индексы ∈ [0,100],
пины границ (`tests/regions.test.js` statusLabel 0/101) зелёные. Класс: **заметка**
(симметрично кандидату из списка; «чинить без данных» спецификация относит в
«Вне рамок»). Проверка: `stateOf(-1, PARAMS)` → 'calm'; `status(-1)` → null.

**F6. `stateOf` зависит от восходящего порядка `PARAMS.states` по `max` — calc/engine.js:34.**
`states.find(index <= s.max)` корректен только при сортировке max по возрастанию;
порядок сейчас верен (params.js:155–162), но нигде не зафиксирован ни тестом, ни
assert'ом — перестановка двух строк в params.js молча переклассифицирует граничные
индексы (например, `[very, danger]` дал бы `stateOf(50)='very'`). Поля `min` при этом
движком не читаются вообще (мёртвые, но публикуются в `state_scale`). Класс:
**заметка**. Проверка: в тесте подать `states` в обратном порядке — классификация
меняется без ошибки.

## Вердикты по кандидатам прошлой сборки

1. **Молчаливый парсинг signals в renderWeekCombined** — **подтверждено** как
   хрупкость (regex+JSON.parse, при рассинхроне формы — пустой хвост без ошибки),
   но **не дефект**: форму части порождает сам пайплайн, а потеря signals покрыта
   двумя падающими тестами (week-combined-parity, regional-deviation). Класс —
   заметка (F1), в ремонт не берётся без отдельного решения о форме части.
2. **Зависимость stateOf от порядка PARAMS.states** — **подтверждено** (engine.js:34,
   `find` по восходящему max; защиты порядка нет). Текущий порядок верен, поведение
   недель не меняется → заметка (F6).
3. **Ослабленный сторож grep n0 (исключение public-contract.js)** — **подтверждено**
   и осталось в коде: исключение (regional-deviation.test.js:108) мертво, его
   обоснование устарело в этом же диффе. Риск низкий (возврат n0 поймают другие
   пины данных) → заметка (F2).
4. **Латентная ветка intersection** — **не подтверждено как дефект диффа**:
   `engine.js` не входит в `b2bca23..b60089c`; поведение зафиксировано ADR 0046
   (`counted` исключает intersection из скора, покрытие/q — нет) и пинится
   `tests/intersection.test.js`. Расхождение «глобальная дельта выбрасывает его» —
   свойство модели, не сборки 4.0. Остаётся в «Вне рамок» спецификации.
5. **stateOf(-1)='calm' vs status(-1)=null** — **подтверждено** (engine.js:30–36
   без нижней границы; risk.js:24 с ней). Латентно, данных с отрицательным
   индексом нет → заметка (F5), в «Вне рамок».

## Находки при верификации ремонта (вне объёма ревью)

### article-build.js (не дифф, задокументированная команда)

**F7. `node article-build.js` падает с exit 1 на выпуске 2026-10-25 — предсуществующе.**
Ворото `FORBIDDEN` ('шаг к' — зеркало Avoid-списка PRD §11.5, стр. 658 «шаг к…»,
в файле с 9d0f708) конфликтует со статьёй `docs/articles/weekly/2026-10-25.md:24`
«заметный **шаг к** снижению напряжения на основных театрах» (добавлена faca399).
Воспроизводится на чистом b60089c и b2bca23, существует с faca399 — уже в
origin/master; дифф b2bca23..b60089c не трогал ни FORBIDDEN, ни md. Тесты зелёные,
т.к. CLI-цикл по всем статьям тестом не покрыт (tests/article.test.js проверяет
`lexiconViolations` на фикстуре); `blog-build.js` gate не применяет и статью
собирает — пользовательского вреда нет, кроме неработоспособности задокументированной
команды (`node article-build.js [--write]`, AGENTS.md). Лечение — редакционное:
перефраз опубликованного текста (требует пересборки blog/) либо спецификационное
решение о точности ворота «шаг к» (PRD-миррор, пин теста tests/article.test.js).
Класс: **заметка**, перенесена в PROGRESS прогона (вне рамок R01/R02).
