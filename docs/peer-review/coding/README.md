# Двойное кодирование: процедура

Цель — снять главное методическое возражение до подачи: «46 критериев размечал один
человек, совпадение не измерено». Механика готова (`calc/coding-reliability.js`,
тесты `tests/coding-reliability.test.js`), нужен второй человек.

## 1. Что выбираем

Две недели методологии 3.0 с высоким покрытием:

| Неделя | Покрыто | Источников | Почему |
|---|---|---:|---|
| `2026-09-20` | 43/46 | 77 | Максимальное покрытие: меньше пустых клеток, больше суждений для κ |
| `2026-10-18` | 34/46 | 90 | Первая неделя таксономии v2: 12 регионов, атрибуция расширена |

Если по какой-то неделе источники окажутся недоступны кодировщику (платный доступ,
удалённые страницы) — замена на `2026-10-25` (37/46, 120 источников) допустима, но
тогда это фиксируется в приложении к статье.

## 2. Кто кодирует

Человек **вне проекта**: не автор, не соавтор кода, не участник обсуждений метода.
Требование не формальное: кодировщик должен быть независимым, иначе это снова
самооценка и в статье так и придётся написать.

Ориентир по времени: 40–45 критериев × 2 недели ≈ 4–6 часов, лучше двумя сессиями.

## 3. Что выдаём кодировщику

Листы уже сформированы и лежат в этом каталоге:

- `coding-2026-09-20.json` — 46 критериев, 77 источников;
- `coding-2026-10-18.json` — 46 критериев, 90 источников;
- `coder-brief.md` — одностраничный бриф: окно, шкалы, правила, срок, как сдать.

Перегенерировать листы, если вход недели изменился:

```
node calc/coding-reliability.js template 2026-09-20 --out coding-2026-09-20.json
node calc/coding-reliability.js template 2026-10-18 --out coding-2026-10-18.json
```

Сторож `tests/peer-review.test.js` проверяет, что лежащие в репозитории листы пустые:
ни одного значения автора и ни одной привязки «источник → критерий». Если в шаблоне
появится значение — тест упадёт.

В листе:

- `definitions` — все 46 критериев: драйвер, шкала (`count` / `ordinal` / `binary`),
  направление (`esc` / `deesc`), название и описание наблюдаемого сигнала;
- `sources` — корпус недели (id, заголовок, домен, URL, дата, тип, кластер) **без**
  привязки «источник → критерий»;
- `values` — пустые поля: `null` или число 0…1;
- `instructions` — краткая памятка.

Чего в листе **нет** и не должно быть: значений первого кодировщика, списка
«какой источник к какому критерию отнесён», итогового индекса недели.

## 4. Что объясняем словами (памятка кодировщику)

1. Окно недели: события с датой публикации в пределах недели `W−7 … W`.
2. «Покрыт» = в окне есть источник, подтверждающий сигнал. Нет источника — `null`.
   Покрытие не дотягивается: оценка по памяти или по общим соображениям запрещена.
3. Ordinal-шкала: 0 / 0,33 / 0,67 / 1. Binary: 0 или 1. Счётные: вес события
   0,2 / 0,5 / 1 / 2, сумма нормируется на CAP = 5 (то есть 5 событий веса 1 → 1,0).
4. Деэскалационные критерии (`deesc`) кодируются так же: 0 = деэскалации нет,
   1 = выраженная деэскалация.
5. Перенос из прошлой недели разрешён только для критериев Д2 (ядерная сфера) и
   обязан быть помечен в `notes`; для остальных критериев это ошибка.
6. Цитаты и точные формулировки не нужны — нужны значения и, если сигнал спорный,
   одна строка «почему» в `notes`.

## 5. Как считаем

Лист автора не собирается руками — он выводится из опубликованного входа той же
нормировкой, что и движок (`engine.normalizeCriterion`, включая счётную шкалу
`events → min(1, Σsev/capCount)`):

```
node calc/coding-reliability.js author 2026-09-20 --out author-2026-09-20.json
node calc/coding-reliability.js compare author-2026-09-20.json coding-2026-09-20.json
```

Отчёт содержит:

- согласие по **покрытию** (критерий покрыт / не покрыт) — номинальная κ;
- согласие по **значениям** обоюдно покрытых критериев — линейно взвешенная κ;
- разбивку по драйверам: где расхождение сосредоточено.

Вырожденные случаи (все суждения в одной категории) дают `κ = н/д` с причиной —
это честнее, чем ноль или единица.

## 6. Что делаем с расхождениями

1. Расхождения по покрытию разбираются первыми: они дороже, чем разница между
   0,33 и 0,67, потому что меняют число покрытых критериев и `q`.
2. Спорные клетки разбирает автор и фиксирует решение (кто прав и почему).
3. Если после разбора значения изменились — неделя пересчитывается штатным
   `node calc/calc.js --write <неделя>`, событие попадает в `data/audit.jsonl`.
   Молча «подкрутить» вход нельзя: это изменит опубликованные числа.
4. В статью идут: κ по покрытию, взвешенная κ по значениям, таблица по драйверам,
   число разобранных расхождений и факт пересчёта (если был).

## 7. Что в статье будет сказано честно

- Перекодировались **значения критериев**, а не классификация источников по
  кластерам: `cluster_id` кодировщик получал готовым. Это ограничение, а не
  достижение, и оно идёт в раздел ограничений.
- Две недели из девяти — не весь ряд.
- Кодировщик независим от проекта, но не является рецензентом статьи.

## 8. Состояние

Кодировочные листы сформированы (`coding-2026-09-20.json`, `coding-2026-10-18.json`),
бриф написан (`coder-brief.md`). Второй кодировщик не привлечён — это единственное, что
осталось. Пока его нет, в статье стоит «межкодировочная надёжность не измерена»;
`tests/peer-review.test.js` проверяет пустоту шаблонов и схему записи, но не факт
наличия второго человека.
