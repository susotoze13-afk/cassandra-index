# Cassandra Index — аудит безопасности

- **Версия документа:** 1.0
- **Дата:** 2026-10-11
- **Область:** весь репозиторий `susotoze13-afk/cassandra-index` — сайт (`index.html`,
  `privacy.html`, `js/`, `css/`, `data/`), расчётный пайплайн (`calc/`), CI
  (`.github/workflows/`), вспомогательные каталоги (`docs/`, `.autopilot/`,
  `calc/input/drafts/`).
- **Метод:** чтение исходников и артефактов, сканирование трекаемых файлов и
  истории git на секреты и PII, проверка веб-поверхности (XSS/инъекции, заголовки),
  разбор CI-воркфлоу и локальных CLI. Динамического пентеста и проверки
  опубликованного домена не выполнялось.
- **Статус:** изменения в рабочее дерево по итогам аудита не вносились; коммит и
  push — за оркестратором.

## Резюме

Публикуемая поверхность (статический сайт) **не содержит эксплуатируемых
уязвимостей уровней Critical/High**. Секретов, ключей и паролей в репозитории нет;
пользовательский ввод нигде не отражается обратно в DOM. Найденные проблемы —
гигиена публичного репозитория, публикация внутренних артефактов и отсутствие
защитных заголовков (Low/Medium).

| Тяжесть | Кол-во | Находки |

## 1. Секреты и конфиденциальные данные

**Секретов нет.** Проверено:

- `.gitignore` закрывает `.env`, `.env.*`, `node_modules/`, `__pycache__/`,
  `.autopilot/serve.*`; `.env.example` отсутствует и не трекается (запись
  `!.env.example` в `.gitignore` безвредна).
- Сканирование всех трекаемых файлов и ~50 коммитов истории на паттерны
  AWS (`AKIA…`), Google (`AIza…`), GitHub (`ghp_…`, `gho_…`), OpenAI (`sk-…`),
  Slack (`xox…`), `-----BEGIN … PRIVATE KEY-----`, `apiKey`/`api_key` — совпадений нет.
- `deploy.yml` не использует собственных секретов: только встроенные
  `github.token`/OIDC.

### F-01 — [Medium] Скрейп-черновики с PII сторонних лиц в публичном репозитории

**Где:** `calc/input/drafts/texts-2026-09-27/*.html` — 77 файлов, ~5.4 МБ.

**В чём риск:** сырой HTML сторонних изданий (Anadolu/`aa.com.tr`, The Guardian,
Yonhap) содержит персональные данные журналистов (например, `sookim@yna.co.kr`),
а также встроенные конфигурации сторонней аналитики и трекинга. Каталог **не
публикуется** (`deploy.yml` стейджит только `index.html`, `privacy.html`,
`icon.svg`, `css/`, `js/`, `data/`), но лежит в публичном репозитории
`susotoze13-afk/cassandra-index` и доступен через web/`git clone`.

**Рекомендация:** исключить каталог из git (`git rm -r --cached calc/input/drafts`
+ запись в `.gitignore`), хранить только извлечённый текст. Если PII уже
неприемлема — переписать историю; иначе хотя бы прекратить дальнейшее накопление.
Скрейп-дампы после извлечения текста удалять.

### F-02 — [Medium] `data/audit.jsonl` публикуется как часть сайта

**Где:** `.github/workflows/deploy.yml` — шаг `cp -r css js data _site/`.

**В чём риск:** журнал аудита `data/audit.jsonl` попадает на `cassindex.ru`,
хотя ни одна страница его не читает (ссылок на `audit.jsonl` в `index.html`,
`privacy.html`, `js/**` нет). Он раскрывает внутренние метрики качества,
причины пересчёта (вплоть до формулировок «превью для редакции») и роли
(`changed_by`: `calc-pipeline`/`methodology-editor`, `approved_by`:
`Editor-in-Chief`). Персональных данных в журнале нет, но это раскрытие
внутреннего governance-следа не оформлено как осознанное решение.

**Рекомендация:** исключать `data/audit.jsonl` при стейджинге (явный whitelist
файлов вместо `cp -r data`) **либо** намеренно объявить журнал публичным
audit-трейлом и задокументировать это.

### F-03 — [Low] Email владельца в клиентском коде

**Где:** `js/sections/feedback.js:29` (`ENDPOINT`), дублируется в собранном
`js/bundle.js:3726`, а также в `docs/`, `AGENTS.md`, `.autopilot/`.

**В чём риск:** адрес `Zasik2008@yandex.ru` виден в исходниках и на странице —
на статическом сайте его нельзя скрыть. Раскрытие намеренное
(`privacy.feedback.text` его фиксирует), но адрес открыт парсерам спама.

**Рекомендация:** использовать неочевидный FormSubmit-алиас или прокси через
serverless-функцию; либо принять как осознанный компромисс.

## 2. Веб-поверхность (XSS и инъекции)

Проверены все места с `innerHTML` (15 шт. в `js/`). Каждый шаблон интерполирует
только статические строки словаря `t(lang, …)` либо данные, прогнанные через
`escapeHtml`; рендер источников идёт через `textContent`.

- `js/sections/history.js:106-110,143-185` — единственное место, где в `innerHTML`
  попадают внешние данные (заголовок/URL/домен источника): всё экранируется
  `escapeHtml`; внешние ссылки несут `rel="noopener noreferrer"` и `target="_blank"`
  (то же — `js/sections/drivers.js:126-143`, через `el()`/`textContent`).
- Пользовательский ввод формы обратной связи никуда не возвращается в DOM
  (`js/sections/feedback.js`).
- `?week=` строго валидируется регуляркой `/^\d{4}-\d{2}-\d{2}$/`
  (`js/ui.js:37-41`).
- `js/i18n.js:332 evalBlock` — не `eval()`: это парсер подстановок `{var}` /
  `{n, plural, …}` / `{x, select, …}`, код из данных не исполняет.

Итог: отражаемых/хранимых XSS не выявлено. Остаточный риск — Low (F-07, F-05).

### F-05 — [Low] Отсутствуют CSP и защитные заголовки

**В чём риск:** в разметке нет `Content-Security-Policy`, `Referrer-Policy`,
`X-Content-Type-Options`. GitHub Pages не даёт задавать заголовки ответа, но
защита достижима через `<meta>`.

**Рекомендация:** добавить в `<head>` `index.html`/`privacy.html`
`<meta name="referrer" content="strict-origin-when-cross-origin">` и
`<meta http-equiv="Content-Security-Policy" …>`. При построении CSP учесть, что
`data/latest.js` грузит скрипты через `document.write` (см. F-07) — понадобится
`script-src 'self'`.

### F-07 — [Low] `document.write` в `data/latest.js`

**Где:** `data/latest.js:13`.

**В чём риск:** `<script src>` собирается конкатенацией из констант `CI_WEEKS`.
Сегодня значения статичны (безопасно), но это заложенная мина: любая
динамизация недель превратит `document.write` в DOM-XSS.

**Рекомендация:** оставить `CI_WEEKS`/`CI_LATEST` строго константами; не подавать
в `latest.js` ничего извне. Отмечено на будущее, а не дефект сегодня.

## 3. Форма обратной связи (`js/sections/feedback.js`)

Валидация полей корректна: белый список тем (`FEEDBACK_TOPICS`), длина сообщения
5–4000, строгий regex для обратного адреса, простая подмена скрытого токена
срезается. CSRF неприменим (нет аутентификации/серверного состояния). Инъекций нет.

### F-04 — [Low] Антиспам полностью клиентский и обходится

**В чём риск:** `honeypotCheck`, `timingCheck`/`tokenValid`, `rateLimit`,
`originAllowed` выполняются в браузере. Злоумышленник может слать POST напрямую
на `https://formsubmit.co/ajax/…` в обход страницы, а `rateState` (в памяти
модуля) сбрасывается перезагрузкой. Реального серверного лимита/капчи нет.

**Рекомендация:** ограничение уже честно задокументировано в коде. При росте
злоупотреблений — прокси (serverless) с серверной проверкой либо Turnstile.
Считать текущий антиспам защитой «от дешёвых ботов», не от целенаправленного флуда.

### F-08 — [Low] Соль токена времени публична

**Где:** `js/sections/feedback.js:35` (`TOKEN_SALT = 'ci-feedback-token-v1'`),
значение попадает и в собранный `js/bundle.js`.

**В чём риск:** подпись воспроизводима любым, кто прочитал код. Это заявлено в
комментарии модуля («от простой подмены, не от целенаправленного обхода») и не
является секретом по определению. Требует лишь явного признания ограничения.

## 4. CI/CD и цепочка поставок

`.github/workflows/deploy.yml` соблюдает принцип наименьших привилегий:
`permissions: contents: read, pages: write, id-token: write`; триггер только на
push в `master`; публикуются лишь разрешённые пути. Секретов в воркфлоу нет.

### F-06 — [Low] Actions не закреплены по коммиту

**Где:** `actions/checkout@v4`, `actions/upload-pages-artifact@v3`,
`actions/deploy-pages@v4` — по мажорному тегу. Тег переустанавливаем, что даёт
теоретический supply-chain вектор.

**Рекомендация:** закрепить actions по полному SHA и включить Dependabot.

Сопутствующее (без отдельного номера): стейджинг копирует `data/` и `js/`
целиком — именно это публикует `data/audit.jsonl` (F-02). Явный whitelist файлов
устранит класс проблемы «появление внутреннего файла → автоматическая публикация».

## 5. Локальные инструменты (`calc/`)

- `calc/linkcheck.js` — исходящие GET только по заранее выверенному списку URL
  (без user-controlled адресов), браузерный User-Agent, таймаут 10 c, ретраи на
  429/5xx. Риск SSRF сведён к нулю; запускается локально/в CI.
- `calc/calc.js:49` — `vm.runInContext` над снапшотами `data/*.js`: исполняется
  JS из файлов репозитория (доверенный сгенерированный контент), не из сети.
- Path traversal отсутствует: `week` валидируется (`calc/prepare-week.js:14-20`),
  запись — только по белому списку `RECALC_WEEKS`.
- `calc/audit.js` — SHA-256 hash-цепочка записей журнала: tamper-evident,
  усиливает целостность governance-следа. **Плюс.**

Эксплуатируемых проблем не выявлено.

## 6. Соответствие заявлениям приватности

`privacy.html` и словарь (`js/i18n.js`) согласованы с кодом:

- регион определяется по часовому поясу
  (`Intl.DateTimeFormat().resolvedOptions().timeZone`), строгий opt-in

  (`js/sections/hero.js:108-123`), координаты не покидают устройство;
- в `localStorage` только `cassandra.region` и `cassandra.region.consent`;
- заявления закреплены тестами (`tests/privacy.test.js`).

Расхождений «текст ↔ код» не найдено. Раскрытие передачи через FormSubmit
присутствует (`privacy.feedback.text`).
