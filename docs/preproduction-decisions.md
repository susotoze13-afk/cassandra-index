## 2. Решено (архив)

### Блокеры Go/No-Go (бывший раздел 1)

| # | Решение | Где зафиксировано |
|---|---|---|
| B1 | Журнал калибровки с расширенной таблицей якорей (тип кризиса, источник, целевой диапазон) — публичный артефакт, привязан к версии методологии | docs/calibration-journal.md (8 якорей, k = 1.95, sensitivity ±20 %) |
| B2 | Порог `Insufficient data`: суммарный вес `null` > 40 % или `null` по Д1/Д2 → публикация запрещена; 20–40 % — с пониженной уверенностью; `Insufficient` не маскируется инерцией («Historical snapshot») | `PARAMS.dataCoverage` в calc/params.js (breaking), классификация публикации в calc/calc.js (R11–R15), UI-состояния в js/sections/states.js |
| B3 | Регионы — ISO 3166-2; города — GADM/GeoNames через `admin1_code`; владелец — Data Governance Lead; изменение таксономии — breaking change | версионированный справочник data/regions/reference.json/.js (владелец и таксономия внутри файла) |
| B4 | RACI Flash Alert: один Accountable — Editor-in-Chief, SLA 2 часа; отзыв через 24 ч при отсутствии второго кластера; immutable-запись каждого алерта | docs/governance.md §2; детектор триггеров `detectFlashTriggers` в calc/engine.js; журнал data/audit.jsonl |
| B5 | Анонимизация IP: edge-геолокация, сырой IP в инфраструктуру не попадает | в текущей статической сборке IP-геолокации нет в принципе: определение по часовому поясу браузера (ADR 0002), до определения — согласие opt-in (ADR 0010); провайдер MaxMind и edge-паттерн — для этапа с бэкендом |
| B6 | Патчи формул (архив 7.1–7.4 ниже) внесены в методологию и код | METHODOLOGY v2.0, реализация в calc/engine.js |

### Решения P1 (до публичного запуска)

| Решение | Где зафиксировано |
|---|---|
| Immutable audit log для изменённых снапшотов: baseline + delta, обязательные поля записи (`snapshot_id`, `version_before/after`, `changed_by/at`, `reason`, `diff`, `approved_by`); публичная справка «Historical snapshot» | calc/audit.js, data/audit.jsonl (hash-цепочка), js/sections/history.js |
| Whitelist кластеров источников (A–F) + Provenance Matrix; независимость только между кластерами; `state_affiliated` | `PARAMS.clusters` в calc/params.js, `validateInputSources` в calc/calc.js (R55), docs/provenance-matrix.md |
| Пороги IP-точности («никогда не гадать»: город ≥80 %, регион-центр 50–80 %, регион <90 % → страна, любой <50 % → глобальный) + город-представитель по confidence | лестница confidence и `adminCenter` в data/regions/reference.json, `resolveLevel` в js/region.js; к реальному IP-детекту — при появлении бэкенда |
| Bottom sheet тренда на мобильных: закрытие только по тапу вне области или «X», `role="dialog"`, `aria-modal="true"` | js/sections/trend.js |
| Доступность тренда: `aria-label` точек, скрытая HTML-таблица, `aria-live` при клавиатурной навигации | js/sections/trend.js (R63) |
| Блок уверенности упрощён, не удалён: бейдж «Качество данных» (по `q`) на первом экране, детальная математика — в модальном окне | js/sections/states.js (R59–R61) |
| Плюрализация без конкатенации строк: ICU-подмножество, тесты форм | js/i18n.js (ADR 0009, стек «ноль зависимостей»), tests/i18n.test.js |
| Согласие на определение региона при первом визите: EU/UK и Россия — opt-in, US/остальной мир — opt-out; флаг `region_consent` с timestamp, не привязан к IP | js/ui.js, js/app.js; до edge-слоя opt-in для всех (ASSUMPTION A4, ADR 0010) |

### Патчи методологии (бывший раздел 7)

| # | Проблема → патч | Где реализовано |
|---|---|---|
| 7.1 | D8 входил в знаменатель нормировки при `d₈ = 0`, занижая эскалацию → нормировка по `E = {Д1…Д7, Д9}`, `I_agg = max(0, S + U − λ·w₈·d₈)` | METHODOLOGY v2.0 §5, calc/engine.js |
| 7.2 | При `S = 0` короборация Д9 обнулялась → абсолютный потолок `U_max = min(ρ/(1−ρ)·S + U_abs, U_abs)` | METHODOLOGY §4.3.5, calc/engine.js |
| 7.3 | Счётные критерии без различия масштаба событий → severity-веса `sev ∈ {0.2, 0.5, 1.0, 2.0}` | METHODOLOGY §4.2, calc/engine.js |
| 7.4 | Региональная модель давала двойной счёт → модель отклонения `I_region = I_global + e_r·Δ_region`, при отсутствии данных `Δ_region = 0` | METHODOLOGY §7, calc/engine.js |
