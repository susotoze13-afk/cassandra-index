# Спецификация: приложение `indices-audit.html` (передача в отдельную сессию)

**Зачем:** на страницу ссылается тело статьи `docs/articles/habr-indices-audit.md` (последняя строка). Пока страницы нет, публикация на Habr блокирована - мёртвая ссылка нарушает правила площадки.

**Дата среза данных:** 24 октября 2026; повторная проверка и пересчёт - 25 октября 2026. Источники кодировки: `crisis-monitoring-audit-2026-10-24.md`, `competitor-sources-deep-dive-2026-10-24.md`, `habr-indices-audit.md`, `habr-indices-audit-package.md`.

## 1. Что обязано быть на странице

1. **Карточки 12 проектов** (в статье их нет - они вырезаны ради 10 минут чтения). По каждой: конструкт, что подтверждено, что не подтверждено, источник со ссылкой и датой проверки, оговорка о том, что «—» значит «не подтверждено», а не «отсутствует».
2. **Матрица 12 × 10** (Д, Ф, С, Г, Н, В, Л, И, Ст, Р) - без колонки «Балл», без итога в шапке. Итог 69 из 120 и медиана 7,0 - отдельным абзацем с оговоркой «это не рейтинг».
3. **Развёртка 120 ячеек**: по каждой ячейке - чем именно подтверждена (документ, страница, дата) или почему пустая. Это главный смысл приложения: читатель должен проверить любую клетку.
4. **Взвешенная шкала** (25/25/20/15/15) с формулой пересчёта из матрицы, промежуточными значениями по каждому критерию и результатом: UCDP 98, GPR 88, ACLED 73, FSI 71, Cassandra 70, INFORM 69, GPI 69, EWP 69, War Monitor 58, GDELT 48, CrisisWatch 33, BGRI 0. Плюс проверка устойчивости при ±5 п.п. **Правило, без которого балл BGRI расходится:** частота обновления засчитывается, только если она опубликована (у BGRI не раскрыта, иначе получается 8 вместо 0). **Итог устойчивости:** первые два места и два последних неизменны; FSI при +5 к независимости входит в верхнюю тройку, Cassandra ходит в коридоре 3–8; формулировки «первые три места неизменны» и «места с третьего по восьмое не держатся» неверны.
5. **Таблица покрытия по 14 странам** (Россия, Украина, Беларусь, Молдова, Казахстан, Грузия, Армения, Азербайджан, Литва, Латвия, Эстония, Узбекистан, Киргизия, Таджикистан; Туркменистан - по решению, если влезает). Колонки: покрыт ли индексом, разрешение, с какого года, лаг публикации, где смотреть.
6. **Раздел «что не удалось проверить»** с датами попыток и кодами ответов (403, WAF, сброс соединения, пустая разметка).
7. **Условия переиспользования**: данные страницы - CC BY 4.0, атрибуция «Cassandra Index - https://cassindex.ru».

## 2. Пробел, который надо закрыть до вёрстки

Таблица по 14 странам **не собрана**. Ни одной строки не выдумывать: нужен проход по документации 12 проектов с фиксацией «страна есть / нет / только регион» и датой проверки. Если по стране данных нет - пустая клетка с пометкой, а не догадка. Это единственный блок, который блокирует страницу.

## 3. Как страница должна производиться

- **Не писать HTML руками.** Маленький детерминированный генератор по образцу `blog-build.js`: вход - markdown-источники в `docs/articles/`, выход - `indices-audit.html` в корне. Иначе через месяц страница разойдётся с цифрами статьи, а статья - про проверяемость.
- **Публикация:** добавить `indices-audit.html` в `cp`-строку шага «Stage site files» в `.github/workflows/deploy.yml`. Без этого страница не выйдет наружу, и `tests/site-pages.test.js` упадёт (каждый `*.html` корня обязан быть в whitelist).
- **Тест:** пин на паритет сгенерированной страницы с генератором (по образцу `tests/contribution-ui.test.js` / `tests/public-contract.test.js`) + проверка, что все 12 карточек и 120 ячеек на месте.
- **Стиль:** только токены из `css/styles.css`, `document.createElement` + `textContent` (никакого innerHTML со строками), видимый фокус, контраст ≥ 4.5:1, reflow до 320 px, таблицы в скроллируемом контейнере с подписью.
- **Лексика:** без «на грани», «на пороге», без прогнозов и оценок сторон; «боевые действия на территории Украины» вместо конструкций с предлогом, который задаёт политическую позицию.

## 4. Порядок работ

1. Собрать таблицу 14 стран (единственный факт-гэп).
2. Написать markdown-источник приложения с карточками и развёрткой.
3. Генератор → `indices-audit.html`.
4. Строка в `deploy.yml` + тест-пин.
5. `node --test` зелёный, `node build.js` не нужен (нет правок `js/**`).
6. Проверить ссылку из статьи в локальном браузере.
7. Только после этого - публикация статьи на Habr.

## 5. Что менять в статье после готовности приложения

Ничего, кроме проверки, что ссылка открывается. Все цифры статьи (6 из 12, 69 из 120, 70 баллов) должны совпасть с приложением - если не совпадут, правится приложение, а не статья: статья уже прошла факт-чек и решённые формулировки зафиксированы в `habr-indices-audit-package.md` §4.
