# Еженедельный автозапуск расчёта по расписанию (GitHub Actions cron)

Дата: 2026-10-04
Статус: approved (дизайн согласен, ожидает плана реализации)

## Цель

Каждое воскресенье в 08:00 МСК автоматически запускать расчёт индекса Кассандры
по уже подготовленному входу, чтобы сайт на cassindex.ru актуализировался без
ручного участия. Подготовка входа (45 критериев, цитаты, отбор источников) и
редакционные сиды остаются ручными — §10.1 governance не меняется.

## Решения (зафиксированы с пользователем)

1. **Объём** — только расчёт по готовому входу `calc/input/<неделя>.json`.
   Автоподготовка входа не делается.
2. **Платформа** — GitHub Actions, отдельный workflow `.github/workflows/weekly-calc.yml`
   с `schedule: cron: '0 5 * * 0'` (05:00 UTC = 08:00 МСК; MSK не переходит на
   летнее время, смещение стабильно) + `workflow_dispatch` с опциональным input
   `week` для ручного прогона любой недели.
3. **Если вход не готов** — тихий зелёный skip (job не краснеет), следующее
   воскресенье попробует снова.
4. **Коммит и пуш** — workflow сам коммитит и пушит в `master`; это явное
   исключение из правила «пуш только за оркестратором», фиксируется в AGENTS.md.
5. **Механику недели добирает workflow** — добавление даты в `RECALC_WEEKS`
   (calc/calc.js) и обновление `data/latest.js` (`CI_WEEKS`/`CI_LATEST`) делаются
   автоматически, только если вход существует. Редакционные сиды workflow НЕ генерирует.
6. **Триггер деплоя** — после push workflow явно вызывает
   `gh workflow run deploy.yml` (push от `GITHUB_TOKEN` не триггерит другие
   workflow по умолчанию); нужен `permissions: actions: write`.

## Архитектура

Новые файлы: workflow `.github/workflows/weekly-calc.yml` и чистый шов
`calc/prepare-week.js` (+ `tests/prepare-week.test.js`) — механика недели
(addRecalcWeek/addLatestWeek) живёт в тестируемых чистых функциях, а не в
node-скриптах внутри YAML (конвенция репо: «каждый новый файл обязан иметь
чистый тестируемый шов»). `deploy.yml` меняется только добавлением триггера
`workflow_dispatch:` — без него `gh workflow run deploy.yml` не запустит
деплой (это следствие решения №6).

Порядок шагов job'а:

1. Checkout `master`.
2. Определить целевую неделю: `TZ=Europe/Moscow date +%F` (для `workflow_dispatch`
   с input `week` — переданное значение).
3. **Ворота тихого пропуска** (все через `if` с выводом причины в лог, job зелёный):
   - нет `calc/input/<week>.json` → skip;
   - нет одного из сидов `data/<week>/drivers.js`, `data/<week>/region-*.js` (все 6) → skip;
   - `data/<week>/global.js` существует (неделя уже пересчитана) → skip, чтобы не
     плодить коммиты с одним лишь новым `recalc.at`.
4. Механика: `node calc/prepare-week.js --write <week>` (чистые швы
   `addRecalcWeek`/`addLatestWeek`, CLI — тонкая обвязка в стиле calc.js):
   - если недели нет в `RECALC_WEEKS` — вставить дату в конец массива;
   - `data/latest.js` — дописать дату в `CI_WEEKS`, поставить `CI_LATEST`
     (не старше уже самой новой недели — защита при ручном dispatch старой недели).
5. `node calc/calc.js --write <week>` — ворота linkcheck (broken → отказ, диск не
   тронут) и контракта `validate`.
6. `node --test` — все тесты зелёные.
7. `node build.js` — бандлы в актуальном состоянии (на случай правок `js/**` в неделе).
8. Коммит: идентичность `github-actions[bot]`, сообщение в стиле репо, например
   `расчёт недели <дата>: published, index NN (delta ±N)` (числа берутся из
   `data/<week>/global.js`).
9. `git push origin master` — без force; при отклонении (master ушёл вперёд) → красный фейл.
10. `gh workflow run deploy.yml` (permissions `actions: write`).

## Обработка ошибок

| Ситуация | Исход |
|---|---|
| Нет входа / нет сидов / неделя уже посчитана | зелёный skip с пометкой в логе |
| Битая ссылка-источник (linkcheck broken) | 🔴 фейл, запись отклонена, коммита нет |
| Тесты упали | 🔴 фейл, коммита нет |
| push отклонён (master ушёл вперёд) | 🔴 фейл, повтор в следующее воскресенье |
| Блокированные ссылки (401/403/406) | предупреждение, не фейл (как в calc.js) |

## Permissions

```yaml
permissions:
  contents: write   # коммит и пуш в master
  actions: write    # gh workflow run deploy.yml
```

## Идемпотентность

- Пропуск уже пересчитанной недели гарантирует не более одного коммита от cron на неделю.
- `workflow_dispatch` с `week` уже посчитанной недели отрабатывает как skip —
  безопасная проверка workflow вживую.

## Тестирование

- Прогон `node --test` локально перед коммитом изменения (29 файлов).
- Первая живая проверка: `workflow_dispatch` с week уже посчитанной недели → skip.
- Вторая: `workflow_dispatch` с week новой подготовленной недели (ручной прогон до cron).
- Первый живой cron — наблюдение.

## Документация

- AGENTS.md: строка в «Командах» про расписание; исключение из правила
  «коммит и пуш — только за оркестратором» (автопуш — только workflow weekly-calc);
  подводный камень: cron тихо пропускает неделю без входа/сидов — актуальность
  зависит от подготовки входа заранее.

## Не входит в объём

- Автоподготовка `calc/input/<неделя>.json` (LLM-разметка, отбор источников).
- Генерация редакционных сидов `drivers.js`/`region-*.js`.
- Изменения `deploy.yml`, `calc/engine.js`, `calc/params.js`.
- Внешние нотификации (issue/email) о пропуске.
