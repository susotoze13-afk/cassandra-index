# Журнал пилота машинной разметки (LLM-черновики)

Аудиторский след пилота по §10.1 governance.md: LLM готовит черновик разметки
45 критериев по отобранным человеком источникам (обязательная цитата + ссылка),
редактор верифицирует. Критерии успеха пилота (зафиксированы до старта):
итоговый index ±2 и тот же state, экономия времени редактора ≥ 50 % на
2–3 подряд форвард-неделях. Ретро-пилот — только быстрый отсев, решение о
`calc/classify.js` принимается по форвард-неделям.

## Ретро-прогон 1: неделя 2026-09-27 (2026-10-XX, вслепую)

**Условия.** Классификатор — LLM-агент без доступа к человеческому входу
(`calc/input/2026-09-27.json`) и опубликованным снапшотам. Вход — только
список из 19 источников недели (`calc/input/drafts/pilot-sources-2026-09-27.json`).
Тексты скачаны curl с браузерными заголовками: 18/19 ok, 1 failed
(`aa-oman-hormuz-navigation`, JS-rendered страница, пустое тело — не использован).
Черновик: `calc/input/drafts/2026-09-27.llm-draft.json` (каждое value > 0 —
с дословной цитатой); конвертирован в прогоняемый вход
`calc/input/pilot-llm-2026-09-27.json` (not_found → null, источники по id →
R55-записи). Прогон — через штатный `runWeek` calc.js с реальной цепочкой
состояния 08-30 → 09-20, без записи на диск.

**Итоговый эффект (главная метрика).**

| | Опубликовано | LLM-черновик |
|---|---|---|
| index | 47 | 53 |
| delta | −9 | −3 |
| q | 0.907 | 0.744 |
| классификация | published | **insufficient** |

Расхождение index = **6 пунктов** (порог ±2 — не пройден); классификация
ушла в insufficient (не пройдено). Ретро-пилот **не подтверждён**.

**Покрытие.** Человек: 26/45 покрыто (19 null). LLM: 21 value + 24 not_found.
Совпадение покрытия по критериям: 25/45 (14 точных совпадений значений,
11 «оба слепые»). LLM пропустил 14 покрытых человеком критериев (концентрация
в Д1.1–Д1.3, Д2.*, Д5.2, Д7.3, Д8.4) и добавил 8 «лишних» (Д3.4, Д4.4, Д4.5,
Д6.3, Д7.1, Д8.3, Д9.4 — там, где человек поставил null).

**Драйверы (score human → llm).** Д1: 0.207→0.335 · Д2: 0.193→null ·
Д3: 0.290→0.050 · Д4: 0.253→0.275 · Д5: 0.215→null · Д6: null→0.665 ·
Д7: 0.050→0.330 · Д8: 0.220→0.110 · Д9: 0.165→0.165.

**Диагностика (где LLM ошибается).**
1. *Пропуски из жёсткого правила цитаты*: Д1.1–Д1.3, Д2.* человек покрыл по
   источникам, но LLM не нашёл дословной формулировки в скачанных текстах и
   честно ушёл в not_found. Правило работает как задумано (нет галлюцинаций),
   но цена — потеря покрытия и падение q ниже порога публикации.
2. *Счётные критерии (события → severity)*: LLM выдавал скалярное value там,
   где человек кладёт events[] с весами (Д1.4, Д3.3, Д7.2) — шкалы несовместимы,
   это системная, а не случайная ошибка. Исправляется форматом черновика
   (LLM должен эмитить events[]).
3. *Различие «событие окна» / «тянущийся фон»*: Д6.3=1.0 по польским
   госзаказам (событие вне окна), Д7.1 — лишнее покрытие. Нужно усилить
   промпт по окну W−7…W.
4. *«Одно событие — один сигнал»*: санкции против иранских авиалиний засчитаны
   трижды (Д3.3/Д4.1/Д9.3) — спорное дублирование, сам классификатор
   отметил как сомнительное.

**Выводы и следующие шаги.** Ретро-отсев провален по обеим метрикам, но
диагностика показывает исправимые системные причины (формат events[],
окно, дедупликация), а не беспредельную галлюцинацию: все value > 0
подкреплены проверяемыми цитатами, выдуманных фактов не обнаружено.
Прежде чем тратить форвард-недели: (а) доработать схему черновика —
events[] для счётных критериев по §4.2; (б) добавить в промпт жёсткие
правила окна и дедупликации; (в) повторить ретро-прогон на 2026-09-20.
Решение о форвард-пилоте — после второго ретро-прогона.

Время редактирования на этом прогоне не измерялось (ретро-режим).

## Ретро-прогон 2: неделя 2026-09-20 (2026-10-04, вслепую, промпт v2)

**Условия.** Та же слепая схема, но с исправлениями по итогам прогона 1:
счётные критерии (D1.4, D2.3, D3.1, D3.3, D3.5, D4.1, D4.4, D5.2, D7.1, D7.2)
эмитятся как events[] с весами {0.2/0.5/1.0/2.0} и цитатой на событие; жёсткие
правила окна (W−7…W = 2026-09-14…09-20, дата события ≠ дата статьи),
дедупликации (одно событие — один критерий) и короборации Д9 (≥2 кластера).
Вход — 74 источника недели. Черновик: `calc/input/drafts/2026-09-20.llm-draft.json`.

**Скачивание — узкое место прогона.** Из 74 URL: полноценные тексты ~15,
только заголовок ~12, blocked 12 (reuters ×7 401, euractiv/bloomberg/nytimes
403…), failed 35 (DNS/timeout — kyivpost, ISW, dw, meduza…; JS-шеллы).
То есть ~64 % отобранных человеком источников машине недоступны из этой среды.

**Итоговый эффект.**

| | Опубликовано | LLM-черновик v2 |
|---|---|---|
| index | 56 | 39 |
| delta | +15 | −2 |
| q | 1.0 | 0.421 |
| классификация | published | **insufficient** |

Расхождение index = **17 пунктов** — хуже прогона 1. Причина не в качестве
разметки, а в покрытии: LLM 16/45 против 42/45 у человека.

**Покрытие и точность.** Общие покрытые критерии: 16; пропущено 26;
лишних — **0** (ни одной выдумки, ноль галлюцинированных покрытий на двух
прогонах подряд). Драйверы (human → llm): Д1: 0.492→null · Д2: 0.193→null ·
Д3: 0.078→0.187 · Д4: 0.435→null · Д5: 0.233→0.215 · Д6: 0.553→null ·
Д7: 0.433→0.170 · Д8: 0.083→null · Д9: 0.534→0.000. Там, где тексты были
(Д5, Д7, Д3), оценки того же порядка; null — почти всегда «нет текста»,
а не «неверная оценка».

**Исправления v2 сработали:** events[] эмитятся корректно (все 10 счётных —
в формате §7.3, с цитатой на событие); правило окна соблюдено (отрезаны
Лукашенко 11.09, IAEA Update 366 11.09 и пр.); дедупликация соблюдена;
сомнительные решения (D9.6b без второго кластера, D7.1 по одному кластеру)
честно помечены на ревью, а не спрятаны.

**Выводы.**
1. Правило «нет цитаты → not_found» + слабая сетевая среда = недопустимое
   покрытие. Блокирующий фактор пилота — **доставка текстов**, а не
   классификация. Это подтверждает выбранную гибридную схему (Q5б):
   заблокированные/недоступные статьи обязан докидывать человек; для
   reuters/apnews/bloomberg и DNS-мертвых доменов машинная доставка
   из этой среды невозможна принципиально.
2. Качество разметки на доступных текстах — рабочее: 0 ложных покрытий,
   согласованные скоры драйверов, проверяемые цитаты.
3. Дополнительный фактор расхождения, выявленный между прогонами:
   человеческая конвенция переноса D2.1–D2.5 из предыдущей недели при
   отсутствии сигналов в окне (задокументирована в AGENTS.md, применена в
   09-27 и 10-04). LLM её не знал и ставил D2=null. В промпт v3 добавить:
   «если по Д2 нет событий окна — пометить carryover-candidate, решение
   о переносе принимает редактор».

**Решение о форвард-пилоте.** Ретро-пилоты не дают чистой проверки: машина
не имеет доступа к тому же корпусу текстов, что был у человека, — сравнение
структурно нечестное в части покрытия. Рекомендуется один форвард-прогон
в гибридном режиме (человек докидывает тексты недоступных статей) — только
он измерит и реальное качество, и реальную экономию времени. Без него
критерий «экономия ≥ 50 %» неизмерим в принципе.
