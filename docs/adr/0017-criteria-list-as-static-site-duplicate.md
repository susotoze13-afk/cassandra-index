# 0017. Список 45 критериев на сайте — статический дубль `engine.CRITERIA` в js/criteria.js, страхуемый тестом-паритетом

## Контекст

Раздел «Методология» на сайте не показывал, из каких 45 критериев D1–D9
собирается индекс. Бриф требует полный список на сайте, но без формул, а
сайт по конвенции архитектуры не импортирует `calc/` — читает только `data/`.
Канонический список критериев живёт в `calc/engine.js` (`CRITERIA`).

## Решение

Создаётся новый модуль `js/criteria.js`: один статический массив из 45 записей
(id, драйвер, название и короткое описание RU/EN, без формул), без функций.
Раздел «Методология» (`js/sections/methodology.js`) рендерит его через словарь
i18n. Рассинхрон с движком страхуется тестом-паритетом: набор id в `js/criteria.js`
и `engine.CRITERIA` — одни и те же 45.

## Почему

Отвергнут импорт `CRITERIA` из `calc/engine.js` на сайт: сайт не знает про
calc/ — это принятая граница модулей (сайт работает с file:// на собранных
бандлах, а методология-словарь должна рендериться через i18n, чего чистый
массив calc/ не даёт). Отвергнута генерация js/criteria.js при сборке из calc/:
усложняет `build.js` (появляется билд-шаг, зависящий от двух миров) ради
устранения дубля, который и так ловится одним тестом. Отвергнуто вычисление
списка на лету из демо-снапшотов: снапшоты не несут описаний критериев, а
добавлять их в контракт данных ради одного раздела — раздувание снапшотов.

## Последствия

Дублирование — осознанная плата: добавление или переименование критерия требует
правки в двух местах, и забывшуюся правку поймает только паритетный тест
(красный сьют, а не баг на сайте). Добавление формул на сайт остаётся прямо
запрещённым брифом — если методология изменит формулировки критериев, тексты в
`js/criteria.js` придётся синхронизировать вручную.
