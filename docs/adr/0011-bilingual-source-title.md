# 0011. Двуязычный title источника {ru, en}

## Контекст

Бриф (решение 5.4 «Поля источника») фиксирует обязательное поле `title` как
скалярную строку. Сайт двуязычный (RU/EN локали уже в продукте): подписи
источников показываются в обоих языках, и одна строка неизбежно оказывается
чужим языком для половины аудитории.

## Решение

`title` в схеме источника — объект `{ru, en}` с обязательными обоими ключами.
Остальные обязательные поля по брифу не меняются: `id, domain, url,
publication_date, accessed_date, source_type (primary|secondary|OSINT),
cluster_id (A–F), state_affiliated (bool)`; опциональные: `author, archive_url,
archive_date, confidence, notes`. Отсутствие любого обязательного поля —
ошибка пайплайна на ingestion.

## Почему

Двуязычие продукта важнее скалярной строки брифа: UI-строки проекта обязаны
идти через словарь i18n (PRD §5), и имя источника — часть UI, а не данных
расчёта. Отвергнут один title + перевод по словарю — имена собственные
(агентства, издания) не переводятся правилами, а варианты написания различаются
по языкам. Отвергнут скалярный title + языковой суффикс в id — двоит сущность
и ломает сортировку/дедупликацию. Расхождение с буквой брифа зафиксировано
в отчёте прогона как осознанное (история 21 спецификации).

## Последствия

Валидация ingestion требует объект `title` с ключами `ru` и `en` (оба
непустые строки). Ручные демо-источники мигрируют на новую схему вместе со
всеми демо-снапшотами (таск 09 зоны данных). Рендер выбирает ключ по текущей
локали, при отсутствии ключа — отказ со сбоем валидации снапшота, а не
угадывание. Схема источника — breaking-параметр (запись в §10 методологии).
