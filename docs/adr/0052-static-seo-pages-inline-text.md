# 0052: Статические SEO-страницы держат текст в разметке

**Контекст**
Страницы «Как читать», changelog, дайджест и сравнения должны находиться поиском и читаться без JS. При этом правило проекта требует все строки интерфейса держать в словаре, а политика безопасности страниц запинена тестом.

**Решение**
Текст этих страниц живёт прямо в разметке: без рантайма словаря, без бандла и без структурированных данных в скрипте. Метаданные — title, description, canonical, OG — тоже пишутся в разметке; вместо структурированных данных — семантическая разметка и видимый FAQ. Это осознанное исключение из правила словаря: для приложения правило остаётся.

**Почему**
Краулер без JS и читатель без JS видят только разметку: текст, собранный словарём на клиенте, для них пустая страница. Отвергли рендер из словаря с предгенерацией на сборке — это новый шаг сборки ради текста, которого проект избегает. Отвергли структурированные данные инлайном: они требуют послабления политики безопасности, а выигрыш не стоит ослабления. Внешний скрипт разметки запрещён конвенцией нуля зависимостей и всё равно не виден без JS.

**Последствия**
Один смысл теперь существует в двух местах — в словаре приложения и в тексте страниц — и расходится при правке. Лексическая проверка обязана сканировать и страницы, иначе запрещённые слова пройдут мимо теста. Правка текста — правка разметки, а не ключа.
