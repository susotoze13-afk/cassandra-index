# 0061. Статический блог «Разбор недели»: отдельные URL, SEO и GEO

**Дата:** 2026-10-18
**Статус:** принято (развитие ADR 0037; заменяет клиентский рендер рубрики)

## Контекст

ADR 0037 сделал поверхность рубрики одной страницей `articles.html`, которая
рендерила выпуск клиентски из `data/<week>/article.js`. Для читателя это работало,
но для поиска и генеративных систем — плохо:

- у всех выпусков один URL, содержимое появляется только после JavaScript;
- краулеры и LLM-поисковики не видят ни текста, ни ссылок на источники без
  исполнения скриптов;
- нет отдельной страницы на неделю для канонической ссылки, цитирования и
  архивной навигации;
- `articles.html` могла попасть в выдачу как пустая оболочка.

При этом редакционный конвейер уже был: Markdown → `article-build.js` →
`data/<week>/article.js`, с воротами лексики, чисел и источников. Не хватало
слоя публикации.

GEO здесь — **Generative Engine Optimization**: страница должна отдавать
машиночитаемые факты и структуру (schema.org, `llms.txt`, статический текст),
а не гео-таргетинг.

## Решение

Рубрика переезжает в статический блог:

1. **`blog/index.html`** — архив всех выпусков, от новых к старым: заголовок,
   дек, индекс/изменение/покрытие и ссылка на полный текст.
2. **`blog/<week>.html`** — отдельная статическая страница каждого выпуска.
   Полный текст, таблица регионов и список источников отрисованы в HTML без JS.
3. **SEO:** уникальные `<title>`/`description`, `canonical`, Open Graph,
   `article:published_time`, хлебные крошки, один `<h1>`, семантические
   заголовки с якорями и оглавление.
4. **JSON-LD:** `NewsArticle` (заголовок, даты, автор-организация, `citation`
   на источники, `isPartOf` блога) и `BreadcrumbList` на выпуске; `Blog` с
   `blogPost[]` на архиве. Данные берутся из опубликованного снапшота.
5. **GEO:** корневой `llms.txt` — краткое описание проекта, ключевые страницы,
   перечень выпусков с dek и машинные данные; `blog/feed.xml` — RSS 2.0 для
   лент и агрегаторов.
6. **`sitemap.xml`** генерируется сборщиком: корневые страницы + `/blog/` +
   все выпуски с `lastmod`. Алиас в карту не входит.
7. **`articles.html`** остаётся алиасом: `canonical` на `/blog/`, meta refresh,
   `noindex,follow` и видимая ссылка. Прежние ссылки не ломаются.
8. **Сборщик** `blog-build.js` (CommonJS, только stdlib) читает
   `docs/articles/weekly/*.md` и `data/<week>/week.js`, пишет blog-страницы,
   RSS, карту и `llms.txt`; `--write` — запись, без флага — проверка. Сборка
   идемпотентна, тест сравнивает байты.
9. **Публикация:** `node blog-build.js --write` после `article-build.js --write`;
   в `weekly-calc.yml` шаг добавлен после публичного слоя и дайджеста.
10. **Выкат:** `deploy.yml` копирует каталог `blog/` и `llms.txt`.
11. **JS рубрики больше не нужен для страниц:** `js/article.js` остаётся
    библиотекой чистых ворот и тестов, `js/bundle-articles.js` не подключается
    к блогу.

## Почему

- **Отвергнуто: оставить клиентский рендер + `?week=`.** Один URL на все
  выпуски, нет статического текста для краулеров, слабая архивная навигация.
- **Отвергнуто: один длинный HTML на все выпуски.** Раздувает страницу,
  размывает заголовок и не даёт канонической ссылки на неделю.
- **Отвергнуто: генерировать страницы в браузере из `week.js`.** То же
  ограничение: без JS контента нет.
- **Отвергнуто: внешний генератор/фреймворк.** Ноль зависимостей — правило
  репозитория; Markdown-парсер и шаблоны уже есть.
- **Отвергнуто: `llms.txt` вместо sitemap.** Они решают разные задачи:
  карта — для классического поиска, `llms.txt` — для генеративных систем.
- **Отвергнуто: отдельный HTML руками.** Источник правды — Markdown; страница
  обязана пересобираться и падать тестом при расхождении.

## Последствия

- `blog-build.js` — новая команда; `blog/`, `sitemap.xml` и `llms.txt` —
  производные файлы, руками не правятся.
- `tests/blog.test.js` пинит идемпотентность, SEO-метаданные, JSON-LD,
  источники, карту, RSS и `llms.txt`; `tests/csp.test.js` — CSP блога;
  `tests/site-pages.test.js` — состав карты с блогом; `tests/page-structure.test.js`
  — точку входа «Блог» в шапке и подвале.
- Новый выпуск = `article-build.js --write` → `blog-build.js --write` → тесты.
  Без второго шага тест блога красный, а не «тихо старая страница».
- Страницы блога — статические: аналитики, формы и внешних скриптов нет.
- Если понадобится картинка для соцсетей, это отдельное решение: сейчас
  `og:image` не задаётся.
