# 0029. Справочник городов и стран: GeoNames, ленивая загрузка, страна как fallback

**Дата:** 2026-10-16
**Статус:** принято (архитектурное решение; реализация — отдельный прогон)

## Контекст

Пользователи жалуются, что не находят в списке свои города и страны. Сейчас
`CITIES` — это **34 города, вшитых прямо в `js/region.js`** (попадают в бандл
`js/bundle.js`), а `search()` ищет только по этим городам и именам регионов;
по странам поиска нет вовсе. `data/regions/reference.json` несёт `countries[]`
по регионам и задел: `cityImport: "Полный импорт городов GeoNames — при
подключении edge-слоя"`.

Ограничения среды: бэкенда нет, зависимостей вводить нельзя, рантайм-сети нет
(сайт работает и с `file://`) — значит справочник должен быть **статическим
файлом, который едет вместе с сайтом**, а не серверным поиском. Полный GeoNames —
~4.8 млн мест — в статику не влезает.

Запрос заказчика — «найти свой регион», а регион и есть единица индекса;
конкретный город — способ выбрать регион и косметика лестницы `representative`.

## Решение

**Источник — GeoNames (CC BY 4.0).** Скрипт-генератор фильтрует дамп
`cities15000` по населению **≥50 000** (у GeoNames нет готового дампа `cities50000`
— фильтрация выполняется генератором) и добавляет поверх **все столицы
суверенных стран (ISO 3166-1) + 12 административных центров регионов** —
независимо от населения. Имена берутся с русскими альтернативами GeoNames
(`alternateNames`, язык `ru`) — они нужны русскоязычной аудитории.

**Данные — два статических классических скрипта:**

- `data/geo/cities.js` → `window.CI_GEO_CITIES` — записи
  `{ name: {ru, en}, country, region_v2, region_v1, pop }`;
- `data/geo/countries.js` → `window.CI_GEO_COUNTRIES` — ISO 3166-1 alpha-2 →
  `{ name: {ru, en}, region_v2, region_v1 }`.

Коммитится **сгенерированный вывод и сам генератор**, не сырой дамп (дамп
скачивается один раз при генерации). На страну хранится **обе версии региона**
(`region_v2` + `region_v1`) — чтобы пикер разрешался и на старых неделях
таксономии v1 (ADR 0028). Страна вне разбиения несёт `region_*: null` — честная
пометка, регион не выдумывается.

**Загрузка — ленивая.** Файлы **не входят в бандл** (`build.js` их не собирает);
они подгружаются динамическим `<script>` при первом открытии пикера (тот же
шов, что и `document.write` в `data/latest.js`, но по требованию), с кэшем в
памяти на время сессии. Стартовая страница не тяжелеет.

**Поиск:** префиксный матч по RU/EN именам городов + русским альтернативам
GeoNames, а также по имени страны и региона. **Минимум 2 символа**; при
широком запросе — **топ-20 по населению** + подсказка «уточните запрос»
(тысячи строк не рендерим — производительность и a11y). Fallback: город не
найден → выбрать страну → регион; страна без региона → пометка.

**Мэппинг в регион — по текущей таксономии.** Найденный город/страна дают id
региона текущей версии (`region_v2`), который дальше идёт в уже существующую
логику личного региона (`detect`/`choose`, ADR 0028); на старых неделях id
может отсутствовать в наборе — тогда подсветки нет (та же конвенция, что для
личного региона).

**Атрибуция.** Строка «© GeoNames, CC BY 4.0» — в **футере**; это UI-строка,
ключ в `js/i18n.js`, сам футер живёт в `js/sections/history.js`
(`[data-role="footer-next"]`).

**Имена городов — это данные** (`{ru, en}` как у заголовков источников), а не
UI-строки; правило «пользовательская строка — только через `js/i18n.js`»
относится к интерфейсу, не к данным справочника.

## Почему

- **Отвергнут полный GeoNames (~4.8 млн).** Порог ≥50k + столицы + админцентры
  даёт несколько тысяч строк и закрывает «найти свой регион»; индекс всё равно
  региональный, точный город — косметика.
- **Отвергнуто включение справочника в бандл.** Постоянная нагрузка на каждый
  просмотр ради функции, нужной лишь при поиске.
- **Отвергнуто ожидание edge-слоя.** Бэкенда нет, edge-слой — гипотеза; жалоба
  существует сегодня. Статический файл закрывает её без инфраструктуры;
  edge-слой потом заменит холодный файл серверным поиском, формат данных тот же.
- **Отвергнута транслитерация (латиница ↔ кириллица) и fuzzy на старте.**
  Префикс + русские альтернативы покрывают основную жалобу; транслитерация —
  вероятный следующий шаг по факту обращений, fuzzy — либо зависимость, либо
  самописный алгоритм, не сейчас.
- **Отвергнуто расширение до admin1-центров.** Десятки тысяч строк ради мест,
  которые пользователю не нужны; поднимем порог/добавим admin1 только при
  подтверждённой нужде.

## Последствия

- Новые файлы `data/geo/cities.js`, `data/geo/countries.js`, скрипт-генератор
  (Node stdlib; сеть нужна один раз при генерации), подключаемые лениво.
- `js/region.js`: `search()` переиспользует ленивый справочник при его наличии,
  иначе — текущий `CITIES` (graceful fallback, тесты без сети).
- `build.js` не собирает `data/geo/*`; `index.html` их статически не подключает.
- Футер: ключ i18n атрибуции; `privacy.html` — при желании ссылка на лицензию.
- `reference.json`: задел `cityImport` про edge-слой закрывается этим решением
  (полный импорт остаётся будущей оптимизацией edge-слоя).
- Тесты: форма сгенерированных данных, поиск (префикс, минимум 2 символа,
  топ-20), страна-как-fallback, ленивый загрузчик, атрибуция в футере.
- Риск: размер репозитория (несколько сотен КБ на сгенерированные файлы);
  качество русских альтернатив GeoNames неодинаково — при жалобах добиваем
  точечно.
