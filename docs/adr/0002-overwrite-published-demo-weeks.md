## Контекст

Три последние недели демо-ряда (2026-08-30, 2026-09-06, 2026-09-13) уже опубликованы в `data/` со значениями, выставленными редактором «на глаз». Методология требует воспроизводимости опубликованных значений и фиксирует параметры с аудиторским следом (§10).

## Решение

Глобальные и региональные значения трёх недель перезаписываются расчётными (`global.js`, `regions.js`, `region-*.js` — значения и Δ); `trend.js` хвоста пересобирается из новых значений. Наблюдения и источники (`drivers.js`, `sources.js`) сохраняются — пересчитываются только числа. `methodology: "1.0"` не меняется. Стартовые недели 08-02…08-23 не тронуты; инерция для 08-30 берётся из опубликованного значения 08-23 с реконструкцией внутреннего float (§5.4: округление только при публикации).

## Почему

Отвергнуто оставить ручные значения и применять расчёт только к будущим неделям — навсегда закрепило бы в ряде «неговорящие» числа и двойной стандарт: читатель не смог бы отличить, где расчёт, а где ощущение. Отвергнут пересчёт всех семи недель — стартовые недели заявлены как опубликованная «история» демо-ряда; без исходных внутренних float-значений их пересчёт всё равно опирался бы на реконструкцию из округлённых, то есть на ту же ручную опору. Отвергнут выпуск `methodology: "1.0.1"` под пересчёт — все 7 недель остаются одной версии, иначе строка смены версии в UI демонстрировала бы расхождение, которого по смыслу нет.

## Последствия

Демо-ряд становится методологически неоднородным: три недели расчётные, четыре — ручные, и это различие нигде в данных не помечено. При смене версии методологии расчётные недели пересчитаются, а ручные — нет, и хвост ряда опять станет смешанным. Решение опирается на статус «предзапусковый демо-ряд»: после реального запуска перезапись опубликованных значений станет недопустимой — этот ADR не прецедент для боевых недель.
