# 0045. Граница раскрытия: шкала и направление публичны, агрегация и пороги закрыты

**Дата:** 2026-10-18
**Статус:** реализовано (2026-10-18): схема `uncovered`, чипы шкал, число
sensitivity, правки METHODOLOGY §1.2/§4.1; неделя 10-18 перезаписана с полем
(27/46, 19 непокрытых), `node --test` — 520/520
**Номер:** 0045 — 0041–0044 заняты записями параллельного прогона source-quotes

## Контекст

Ревью предложило пять доработок публичной поверхности: показать шкалы и
направления критериев (5), вывести число чувствительности вместо одного факта
«≥ 5» (6), разложить «не покрыто N критериев» по доменам (7), ввести явный флаг
`intersection` (8) и формализовать границу «глобального конфликта» (9).

Проверка репозитория перед решением:

1. **Шкала и направление уже есть в движке.** `calc/engine.js` держит у каждого
   критерия `dir: 'esc' | 'deesc'` и `scale: 'count' | 'ordinal' | 'binary'`.
   Сайт `calc/` не импортирует (конвенция), поэтому список критериев в
   `js/criteria.js` дублирует `id`/`driver` и уже пинится паритет-тестом
   `tests/methodology-criteria.test.js`.
2. **Запрет на шкалы — не в коде, а в трёх текстах.** `js/criteria.js:2-3`,
   `js/i18n.js` (`method.criteria.intro`) и комментарий теста утверждают, что
   шкалы в публичный интерфейс не выносятся. При этом `FORMULA_RE` банит слова
   шкал только в полях `name`/`desc`, а не в структуре записи.
3. **Sensitivity считается давно** (`calc/sensitivity.js`), лежит в quality-блоке
   всех восьми недель цепочки и различается: 5.3 у 09-13, 5.4 у 10-04, 0 у 10-11
   и 10-18. Ноль — законный результат, а не сбой: у 10-18 единственный критерий
   с одним доменом (D2.2) имеет `value = 0`, поэтому исключение любого домена
   не меняет индекс. У демо-недель 08-02…08-23 поля нет вовсе.
4. **По-критериального покрытия в снапшоте нет.** Есть только
   `coverageCriteria {covered,total}`, и только у 10-18 (27/46, то есть 19
   непокрытых). Значит пункт 7 — изменение контракта данных, а не строка в
   `js/sections/trust.js`.
5. **Ссылки METHODOLOGY сломаны.** `§4.1.3`, `§4.1.5`, `§4.1.6`, `§4.1.7` и
   `§4.1.9` цитируются, но таких подразделов нет: кластеры происхождения —
   пункт 3 внутри §4.1, матрица пересечений — пункт 5, severity — пункт 6,
   CAP — пункт 7, региональная атрибуция — пункт 9. Кроме того, §4.1 п.5
   говорит «дедупликация выполняется на уровне пайплайна», а в расчётном коде
   её нет.
6. **Определение «глобального конфликта» есть**, §1.2 содержит (а)/(б)/(в) и
   оговорку «конвенция, а не юрквалификация». Не хватает операционализации
   (а) и (б): «несколько театров» и «великая держава» не имеют критериев
   отнесения. `js/risk.js` — шкала уровня индекса, а не классификация события.

## Решение

### 1. Шкала и направление критерия — публичны

В `js/criteria.js` у каждой записи появляются два поля-идентификатора:
`scale: 'count' | 'ordinal' | 'binary'` и `dir: 'esc' | 'deesc'`, скопированные
из `engine.CRITERIA` (сайт по-прежнему не читает `calc/`). Паритет-тест
`tests/methodology-criteria.test.js` расширяется проверкой обоих полей.

В секции «Методология» рядом с названием критерия рендерятся два чипа:
направление («эскалационная» / «деэскалационная») и тип шкалы («счётная» /
«порядковая» / «бинарная»). Подписи — ключи словаря
(`method.criteria.dir.*`, `method.criteria.scale.*`), не строки в `criteria.js`.
Чипы, а не колонка таблицы: переживают 320px, колонка — нет.

Числовой диапазон (`0–1` нормировка) **не показывается**: он одинаков у всех 46
критериев, информации не добавляет, а рядом с ним неизбежно тянется CAP.

Закрытым остаётся: формула агрегации, веса драйверов, CAP, `k`, пороги
состояний, нормировки. Открытым становится: тип шкалы, направление, что именно
наблюдается (уже было).

`method.criteria.intro` переписывается: «формулы агрегации, веса и пороги не
публикуются; тип шкалы и направление критерия — публикуются». То же — в шапке
`js/criteria.js` и в комментарии теста. `FORMULA_RE` сохраняется для
`name`/`desc` (тексты по-прежнему без формул), плюс добавляется проверка, что
чипы не содержат чисел.

### 2. Sensitivity — числом, всегда

В раскрытых деталях панели доверия выводится само значение:
«сдвиг индекса при исключении одного домена: 5.4 п.п.». Правила:

- число показывается всегда, когда оно есть в снапшоте, включая `0`;
- отсутствие поля (демо-недели 08-02…08-23) → «н/д», без домыслов;
- строка-предупреждение «индекс чувствителен к одному из доменов (Δ N п.п.)»
  остаётся только при `N ≥ 5` (`TRUST_SENSITIVITY_THRESHOLD`);
- в основную строку-факт (`factsLine`) число не выносится.

### 3. Непокрытые критерии — списком id в снапшоте

`coverageCriteria` расширяется полем `uncovered: string[]`:

```js
coverageCriteria = { covered: 27, total: 46, uncovered: ['D1.2', 'D1.6', …] }
```

- считается в `runWeek` (`calc/calc.js`) рядом с существующим
  `res.coverage = {criteria, totalCriteria, drivers}`; источник — `criteria[id] == null`;
- порядок — как в `engine.CRITERIA`, не алфавитный: сайт группирует по драйверам
  без пересортировки;
- `writeWeek` остаётся тупым переносом `meta.coverageCriteria` в снапшот;
- `js/data.js` (`validateQuality`) принимает поле опционально и проверяет:
  массив строк, каждый id ∈ 46, длина ровно `total − covered`, без дублей;
  отсутствие поля валидно (старые недели);
- forward-only: у 08-30…10-11 поле появится только при будущем пересчёте,
  задним числом не дозаписывается. Отсутствие поля на сайте — «н/д».

UI (`js/sections/trust.js`): сводка по драйверам («Д1: 0 из 6, Д2: 5 из 5, …»)
сразу, id — раскрытием внутри уже существующей панели. Плоский список 19 id —
стена текста, поэтому по умолчанию не показывается.

### 4. `intersection` — только документация, без поля в схеме

Флаг в схеме входа, который движок игнорирует, создаёт ложную уверенность, что
пересечения учитываются кодом. Поэтому:

- матрица пересечений выносится в пронумерованный подраздел, а заголовки
  получают все цитируемые, но отсутствовавшие узлы: `§4.1.3` (кластеры),
  `§4.1.5` (event taxonomy), `§4.1.6` (severity), `§4.1.7` (CAP),
  `§4.1.9` (региональная атрибуция) — ссылки начинают разрешаться;
- фиксируется факт: дедупликация — редакторская, по event ID, до внесения входа;
  в расчётном коде и схеме входа её нет (формулировка «на уровне пайплайна»
  убирается как неверная);
- поле `intersection` не вводится. Если позже понадобится автоматизация
  дедупликации — это отдельное решение с собственным ADR.

### 5. Граница «глобального конфликта» — операционально, без имён

`§1.2` дополняется операциональным чтением уже существующего определения:

- «несколько театров в разных регионах» = не менее двух регионов действующей
  таксономии (сейчас v2, 12 id), с оговоркой, что это конвенция проекта;
- «великая держава» определяется по способности, а не по списку: государство,
  способное вести самостоятельную военную кампанию за пределами своего региона.
  Примеры — иллюстрация, не исчерпывающий перечень: закрытый список политически
  нагружен и устаревает;
- явно фиксируется: индекс **не классифицирует** событие как «глобальный
  конфликт». В коде такой классификации нет и не будет; `js/risk.js` — шкала
  уровня риска, а не факт войны.

Публичный блок `method.definition.*` получает одну уточняющую фразу в
`method.definition.1`; новых ключей не заводим.

### Разрешение конфликта с правилом «Не трогать METHODOLOGY.md»

`AGENTS.md` относит `METHODOLOGY.md` к неприкосновенным. Для пунктов 8–9
разрешается точечная правка ровно двух мест: §1.2 и подразделов §4.1
(заголовки/ссылки/формулировка о дедупликации). Остальной документ не
трогается. Разрешение зафиксировано здесь, чтобы правка не выглядела нарушением
конвенции.

## Почему

- **Отвергнуто: генерировать `data/criteria.js` из движка.** Ради двух полей —
  новая сущность и шаг сборки; дублирование `driver` уже принято и пинится
  паритет-тестом.
- **Отвергнуто: показывать нормировочный диапазон `0–1`.** Одинаков у всех
  критериев; читатель не получает различия, зато получает повод искать CAP.
- **Отвергнуто: прятать число sensitivity под порог 5.** Тогда «0» и «2.1»
  невидимы, а именно они показывают устойчивость недели. Порог остаётся только
  для предупреждения.
- **Отвергнуто: считать непокрытые id на сайте из статического списка.** Сайт
  не знает, что было покрыто в конкретную неделю; вывод из 46 минус счётчик
  даст список без содержания.
- **Отвергнуто: бэкфилл `uncovered` в архивные недели.** Пересчёт восьми недель
  ради косметики тянет сеть, linkcheck, правку пинов и меняет историю; поле
  additive, старые недели честно показывают «н/д».
- **Отвергнуто: advisory-флаг `intersection`.** Не влияет на расчёт, но
  выглядит как влияние; документация честнее.
- **Отвергнуто: именованный список великих держав.** Политически нагружен,
  устаревает и превращает методологическую конвенцию в заявление о странах.

## Последствия

- Публичная поверхность меняется без изменения расчёта: `PARAMS.methodology`
  остаётся `3.0`. Неделя 10-18 перезаписана штатным `--write` только чтобы
  добавить additive-поле; числа индекса/дельты не изменились, остальные недели
  не пересчитывались.
- `coverageCriteria.uncovered` — additive-расширение контракта; недели без поля
  валидны, сайт показывает «н/д».
- METHODOLOGY.md правится в двух местах; ссылки `§4.1.3`/`§4.1.5` начинают
  разрешаться, утверждение о дедупликации в пайплайне исправляется на факт.
- `js/criteria.js` перестаёт быть «списком без шкал»: его шапка, вводный текст и
  комментарий теста формулируют новую границу раскрытия.
- После правок `js/**` обязателен `node build.js`; бандлы коммитятся.
- Демо-недели 1.0 не пересчитываются: у них не будет ни числа sensitivity, ни
  `uncovered` — это ожидаемое «н/д», не регресс.

## План реализации (порядок обязателен)

1. **Контракт (7).** `runWeek` собирает `uncovered` в порядке `CRITERIA`;
   `meta.coverageCriteria` несёт три поля; `validateQuality` валидирует форму;
   тесты: `tests/data.test.js` (форма/инвариант длины), новый кейс на битые id и
   дубли; `tests/trust.test.js` — сводка по драйверам и «н/д» без поля.
2. **Шкалы (5).** Поля в `js/criteria.js`, ключи словаря, чипы в
   `js/sections/methodology.js` (через `criteriaModel`), паритет-тест и
   обновлённые `FORMULA_RE`-комментарии/вводный текст.
3. **Sensitivity (6).** Строка в `buildDetails`, ключи
   `trust.details.sensitivity` / `.na`, обновление `tests/trust.test.js`.
4. **Документация (8, 9).** Точечные правки METHODOLOGY §1.2 и §4.1,
   `method.definition.1`, этот ADR — единственный источник решений.
5. **Сборка.** `node build.js`, `node --test` зелёный; коммит и пуш — за
   оркестратором.

Вне рамок: автоматическая дедупликация событий в коде; бэкфилл покрытия и
sensitivity в архивные недели; публикация весов, CAP и порогов; именованный
список великих держав.
