# ADR 0069 — Региональное отклонение по драйверам, дробная точность слоя, снятие объёмного сжатия

**Дата:** 2026-11-04
**Статус:** предложено. Реализация — после утверждения владельцем; данные
(`calc/input/**`, `data/**`) до утверждения не трогаются.
**Затрагивает:** §7 методологии (региональное отклонение), точность числового
слоя регионов и стран, публичную схему (`PUBLIC_SCHEMA_VERSION`), версию
методологии (3.0 → 4.0).

## Контекст

### Наблюдение

Владелец увидел на неделе 2026-11-01 таблицу регионов, где девять из двенадцати
строк показывали **73 из 100** при разных дельтах (+4, +5, +6, +7, +8). Читается
это как «все регионы одинаковые, значит в методологии ошибка».

### Что на самом деле в данных

Одинакового числа нет: внутренние значения разные — 72.4, 72.6, 72.9, 73.2,
73.4, 74.0, 74.5, 74.6, 80.0. Целое округление (`roundHalfUp`) слипает
72.5…73.49 в «73». Предыдущие недели v2 того же не показывают: 10-18 — разброс
61…69, 10-25 — 64…78. Залипшей константы или копипасты нет.

### Два реальных дефекта

**1. `Δ_region` измеряет разрежённость, а не отклонение.** §7 считает
`index = gInternal + e_r · m · Δ_region`, где `Δ_region = iWith − iWithout`,
`iWith` — индекс §5, посчитанный **только по сигналам региона**, `iWithout` —
по всей неделе без них. У региона с одним атрибутированным критерием `iWith`
— это индекс, посчитанный по **одному критерию**, и он выходит 100 (Средняя
Азия, Южная Азия), 86.8 (Балканы), 92.1 (Россия). Разность «индекс из 1
критерия минус индекс из 34» не является региональным отклонением: она
измеряет, насколько подмножество разрежено. У двух регионов с одним сигналом
получился побитово равный `Δ = 26.71` — отсюда одинаковые 73 после `m = 0.167`
и `e_r ≈ 0.26`.

**2. Целочисленная шкала и сортировка по |Δ| прячут, что дифференциация мала.**
Разница уровней 0.5–1.5 п.п. невидима в целом; при этом список отсортирован по
`|delta|`, а `delta = index − prevIndex` тянет отклонение **прошлой** недели:
у Северной Америки 72 → 74 (Δ +2), у Восточной Азии 64 → 74 (Δ +10). Рейтинг
читается как «где горячее», хотя это «где сильнее изменилось с прошлой недели».

### Прототип меры (неделя 2026-11-01, до правки кода)

Считалось по правилам ниже: отклонение по драйверам, знаменатель — постоянный,
эпсилон-порог ADR 0065, веса §5.

| регион | Δ (п.п.) | вклад после `e_r ≈ 0.35` |
|---|---|---|
| russia-belarus | −1.28 | −0.45 |
| ukraine-moldova | −2.56 | −0.90 |
| baltic | +0.85 | +0.30 |
| balkans | 0.00 | 0.00 |
| eu-north-europe | +0.84 | +0.29 |
| south-caucasus | +1.93 | +0.68 |
| central-asia | 0.00 | 0.00 |
| east-asia | −0.23 | −0.08 |
| middle-east | +2.13 | +0.74 |
| north-america | +2.34 | +0.82 |
| south-asia | 0.00 | 0.00 |
| africa | −1.92 | −0.67 |

Разброс уровней ≈ 1.6 п.п. — **честная** мера даёт **меньше** дифференциации,
чем текущая, потому что прежние 8–14 п.п. делал артефакт. Три региона получают
ровно 0: их единственный сигнал лежит в драйвере, где регион покрывает все
покрытые критерии, — региональный скор тождественно равен глобальному. Это
не дефект формулы, а отсутствие данных.

## Решение

### 1. Мера регионального отклонения — по драйверам

```
Δ_region = 100 · Σ_d w_d · shrink_d · (s_d^region − s_d^global) / Σ_d w_d
```

- `d` — допустимые драйверы: Д1, Д3, Д5, Д6, Д7, Д8 и Д9 **только D9.3**
  (ADR 0022 сохраняется без изменений: Д2, Д4 и остальные подгруппы Д9 несут
  экспозицию, а не сигнал; регион их не получает).
- `s_d` — скор драйвера §4.2 (`engine.driverScore`) на подмножестве критериев
  этого драйвера.
- `shrink_d = n_cov_region,d / n_cov_global,d` — доля покрытых критериев
  драйвера, представленных у региона. Это надёжностный вес: регион с одним
  критерием из шести не может заявить полный сдвиг драйвера. Не новый
  калибруемый параметр — доля считается из данных недели.
- **Знаменатель — константа**: сумма весов всех допустимых драйверов
  (`0.1175·6 + 0.06 = 0.765`). Отсутствующий у региона драйвер входит нулём
  («нет регионального свидетельства отклонения»), а не исключается из
  нормировки. Иначе один сигнал в одном драйвере делится на вес одного
  драйвера и даёт 8.5-кратное усиление: у Южного Кавказа прототип давал
  `Δ = +12.6`, сдвиг +4.4 — ровно тот класс артефакта, который устраняется.
- **Порог покрытия — эпсилон ADR 0065** на обеих ногах (`s_region` и
  `s_global`): глобальные 50 % на региональном подмножестве обнуляют почти все
  драйверы. Следствие принимается осознанно: если регион покрывает все
  покрытые критерии драйвера, вклад драйвера равен 0 — регион не может
  «отклониться» от того, что уже совпадает с глобальным набором.
- `clamp ±40` (`PARAMS.regionClamp`) сохраняется как страховка шкалы.
- `iWith`/`iWithout` и приватная `hypotheticalIndex` **удаляются** — после
  смены меры у них нет потребителей. `regionalHypothesisParams` остаётся:
  эпсилон теперь применяется к региональной ноге скора драйвера.

### 2. Уровень региона и снятие объёмного сжатия

```
internal = clamp(gInternal + e_r · Δ_region, 0, 100)
e_r = γ · eStruct + (1 − γ) · eDyn
```

- `m = nReg/(nReg + n0)` **снимается**, `PARAMS.n0` удаляется из `params.js`.
  Объёмное сжатие существовало ровно для гашения разрежённых подмножеств;
  после `shrink_d` оно наказывает за объём данных дважды, а мёртвых параметров
  в `PARAMS` не остаётся.
- `e_r` сохраняется: экспозиция остаётся множителем, `eStruct` — по-прежнему
  нейтральный плейсхолдер `0.5` (квартального реестра экспозиций нет,
  ADR 0022), и это раскрывается в тексте методологии, а не маскируется.
- Слепая ветка (`nReg = 0`, сохранение прошлого отклонения, `background: true`)
  не меняется.

### 3. Точность: одна десятичная у регионов и стран

- `attributedIndex` округляет уровень и дельту **до одной десятичной** для
  регионов и стран (`round1`); глобальный индекс и его дельта остаются
  целыми (`roundHalfUp`). Причина: глобальный ряд прошит в тренде, дайджесте,
  внешней сверке (ADR 0063), реестре прогнозов (ADR 0064) и тексте шеринга —
  дробление ломает сопоставимость опубликованного ряда без причины.
- `delta` региона/страны — тоже одна десятичная: иначе строка «73.4, +1»
  противоречит сама себе (73.4 против 72.0 — это 1.4).
- Контракт сайта не меняется: `js/data.js isIndex`/`isDelta` принимают любое
  конечное число, дробь валидна.
- Публичный слой **меняется**: `regions[].index`, `regions[].delta`,
  `countries.rows[].index`, `countries.rows[].delta` — `integer → number`;
  `PUBLIC_SCHEMA_VERSION = 1` → `2`; `docs/api.md` описывает точность и
  правило «глобальный индекс целый, региональный и страновой — с одной
  десятичной».

### 4. Наблюдаемость вместо косметики

- В блок региона добавляется `signals: n` (= `nReg`, паритет с
  `countries.rows[iso].signals`). Регион с `signals < 2` помечается в UI и в
  тексте методологии как «мало региональных сигналов»; редакционное поле
  `confidence` не переиспользуется — оно про уверенность драйверов.
- Секция регионов сортируется **по индексу убыванию**; личный регион
  пиннится первой строкой (`region-row--pinned`), порядок остальных — строгий.
  Дайджест уже так сортирует (`calc/digest.js`, `topRegions`).
- Демо-недели 08-02…08-23 (методология 1.0) остаются целыми и отображаются
  целыми: точность берётся из данных, `.0` не навязывается.

### 5. Версия методологии и пересчёт

- `PARAMS.methodology` → `4.0`. Правка меняет §7, то есть является
  breaking-решением и фиксируется до кода.
- Пересчитывается вся цепочка **08-30…11-01 (13 недель)** — по прецеденту
  O11 (ADR 0065): региональный слой заявлен как несущий смысл, оставлять
  известный дефект в опубликованных неделях нельзя. Демо-недели 1.0 вне
  `RECALC_WEEKS` и не пересчитываются.
- **Глобальные числа не меняются** — это доказывается пином в
  `tests/data.test.js` по всем 13 неделям, а не «на глаз». `q`, покрытие,
  `sensitivity`, `precursor` и состояние публикации не двигаются.
- Производные пересобираются штатным путём: `public-export.js --write`,
  `digest-export.js --write`, `backtest.js --write`, `ledger.js --write`,
  `node build.js`; в `changelog.json`/`changelog.html` добавляется запись
  «4.0: региональное отклонение по драйверам, дробная точность слоя, снятие
  объёмного сжатия».

### 6. Ветка зеркалирования шока — сохраняется

`kappa` и `regionShockDelta = 15` (§7) остаются: единственная защита от
«регион отстал от резкого глобального скачка». На реальной истории порог ни
разу не достигнут (максимальная недельная дельта глобального индекса — +13);
это пинится тестом, чтобы «мёртвая» ветка не была удалена как неиспользуемая.

### 7. Критерий приёмки (переписан)

1. Отклонение из подмножества < 2 сигналов раскрывается `signals`, а не
   маскируется формулой.
2. Разброс региональных индексов опубликованной недели **≥ 1.5 п.п.** (прежний
   бар ≥ 4 п.п. отменяется как недостижимый без искусственного усиления).
3. Равные индексы **допустимы**, если вклады сигналов равны (три региона
   11-01 с нулевым отклонением) — раскрывается через `signals`, а не
   «чинится» подгонкой.
4. Глобальные числа всех 13 пересчитанных недель не изменились.

## Почему так

- **Отвергнуто: оставить `iWith/iWithout`, но считать обе ноги на одном наборе
  драйверов.** Зависимость от `q`, порога покрытия и кривой сохраняется:
  разность индексов остаётся разностью величин с разной нормировкой.
- **Отвергнуто: нормировать веса по «сопоставимым» драйверам.** Прототип дал
  8.5-кратное усиление одного сигнала (Южный Кавказ +4.4 п.п. из одного
  критерия Д3) — тот же класс дефекта, что устраняется.
- **Отвергнуто: усилить (`e_r = 1`, без `shrink`).** Разброс доходит до 6–8
  п.п., но один критерий двигает регион на ~10 п.п. Это шум под именем
  дифференциации.
- **Отвергнуто: самостоятельный региональный индекс (не отклонение).** Он
  смешивает «нет данных» с «стабильно»: разрежённый регион садится на своё
  прошлое значение и выглядит спокойным.
- **Отвергнуто: публиковать интенсивность региональных сигналов вместо
  индекса.** Интенсивность различается честно (23 сигнала у Ближнего Востока
  против 1 у Кавказа), но это не индекс и не входит в него; `signals`
  раскрывает то же самое без нового объекта публикации.
- **Отвергнуто: оставить целые индексы.** Округление прячет реальные 1–2 п.п.;
  именно оно создало наблюдаемую картину «девять раз по 73».
- **Отвергнуто: дробная точность глобального индекса.** Ломает сопоставимость
  опубликованного ряда, тренд, внешнюю сверку и реестр прогнозов без причины.
- **Отвергнуто: forward-only.** Опубликованный региональный ряд остался бы с
  известным дефектом (артефакт `iWith` из одного критерия) — это публикация
  известной кривизны.

## Последствия

- Региональные индексы и дельты 13 недель перезаписываются, версия методологии
  — 4.0. Глобальный ряд, `q`, покрытие, `sensitivity`, `precursor` не двигаются.
- **Ожидаемые значения — по прототипу** (11-01: сдвиги ±0.9 п.п., разброс
  ≈1.6 п.п.); фактические числа после пересчёта фиксируются в журнале
  калибровки и в пинах. Расхождение прототипа и результата — повод разобраться,
  а не подогнать.
- Три региона на 11-01 (Балканы, Средняя Азия, Южная Азия) получат **равные**
  индексы с точностью до 0.1 — это принимается (п. 3 критерия) и раскрывается
  `signals`, а не устраняется.
- Страновой слой наследует ту же формулу автоматически (`attributedIndex`
  один на обе размерности, ADR 0067): строки стран получают дробную точность
  и новую шкалу отклонения; `signals` в строках уже есть.
- Смешанная точность архива: v1/v2-недели цепочки — одна десятичная, демо-недели
  1.0 — целые. Сайт форматирует по данным.
- Удаляются: `PARAMS.n0`, `hypotheticalIndex`, `iWith`/`iWithout` в
  `attributedSignals`. Обновляются тесты: `tests/regional-signals.test.js`,
  `tests/calc-engine.test.js` (юниты `regionalIndex` с `iWith`/`iWithout`),
  `tests/engine-attribution*.test.js`, `tests/data.test.js` (пины глобальных
  чисел + новый пин неизменности глобала), `tests/region-country-consistency.test.js`,
  `tests/public-contract.test.js` (схемы `number`, версия 2), `tests/digest.test.js`
  (формат чисел в тексте).
- Новый сторож представительности: тест на опубликованной неделе проверяет
  разброс ≥ 1.5 п.п., отсутствие насыщенных `iWith` (их больше нет) и то, что
  равные индексы сопровождаются равными `signals`-вкладами.
- `docs/api.md`, `docs/architecture.md`, `AGENTS.md`, `docs/calibration-journal.md`
  получают запись о 4.0 и новой мере; ADR 0022 и 0065 не переписываются —
  0069 их дополняет.
- Реестр прогнозов (ADR 0064) и внешняя сверка (ADR 0063) опираются на
  глобальный индекс — не затронуты.

## Что не входит в это решение

- Квартальный реестр структурных экспозиций регионов (`eStruct`) — остаётся
  плейсхолдером `0.5`; отдельная задача, отдельный ADR.
- Расширение набора допустимых драйверов за счёт Д2/Д4 — меняет смысл слоя,
  не входит.
- Бэкфилл региональных источников ради большей дифференциации — это работа с
  данными (`docs/source-proposals/**`), а не с формулой.
- Дробная точность глобального индекса.
