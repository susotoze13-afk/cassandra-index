# 0057. Публичное ядро — этот репозиторий, коммерческий модуль — отдельный

**Контекст**
Проект публичный: сайт, расчётный пайплайн, данные недель и документация лежат в одном репозитории под Apache-2.0 и CC BY 4.0. Впереди — коммерческий модуль: платные функции поверх того же индекса, приватные интеграции, бизнес-правила и клиентские данные. Если он появится в этом же дереве, публичный репозиторий перестанет быть публичным: закрытый код попадёт в историю и в архив Zenodo, лицензия перестанет быть правдой, а читатель потеряет возможность проверить числа. Решение нужно записать до появления модуля, а не в момент, когда первый закрытый файл уже лежит в рабочем дереве.

**Решение**
Этот репозиторий — **публичное ядро**: сайт, расчётный пайплайн, опубликованные данные, публичный слой для машинного чтения, тесты и документация. Коммерческий модуль — **отдельный приватный репозиторий**. Направление зависимости одно: закрытое зависит от открытого. Публичный код не импортирует закрытый и не знает о его существовании. Подключение ядра в закрытом репозитории — копия релиза или подмодуль на тег `v<VERSION>` (версия из корневого `VERSION`). Отдельного каталога под закрытые части здесь не заводится.

**Почему**
Граница проходит по лицензии, а не по папкам: всё, что читатель может проверить и переиспользовать, остаётся здесь вместе с историей; всё, что нельзя показывать, живёт там, где лицензия это разрешает. Одно направление зависимости делает публичное ядро самодостаточным — его можно склонировать, собрать и протестировать без доступа к закрытому. Обратное направление отвергнуто: публичный тест, тянущий приватный пакет, не запустится у читателя и у форка, а «публичный» репозиторий начнёт требовать секретов. Отвергнуто разделение по каталогам внутри одного репозитория (`commercial/`, `private/`): приватность в git не выражается папкой — история, форки и архив её не уважают. Отвергнуто и зеркалирование всего дерева в приватный репозиторий: две копии расходятся при первой правке, а расчёт чисел обязан оставаться в одном месте.

**Последствия**
Новая функция сначала появляется в публичном ядре, если её можно открыть; закрытая надстройка приносит только то, чего в ядре нет. Любая правка `calc/`, `js/`, `data/` и тестов остаётся здесь — таксономия регионов (ADR 0028) и схема публичного слоя (ADR 0050, 0051) не переезжают. Обновление закрытого модуля начинается с релиза ядра: тег `v<VERSION>` — точка, на которую он ссылается. Процедура переноса, два списка «остаётся здесь» и «обязано уехать» — в `docs/repo-boundaries.md`. Создание приватного репозитория — действие владельца вне этого прогона; здесь записана граница и правило, по которому модуль уезжает.
