# 0018. Jev как классификатор источников для входа недели

## Контекст

Сбор входа недели (45 критериев × десятки статей) — самое узкое место
недельного цикла. Governance §10.1 разрешает подготовку черновиков разметки
LLM по отобранным человеком источникам; ретро-пилот (`docs/llm-pilot-journal.md`,
два прогона вслепую на 09-27 и 09-20) показал: на доступных текстах качество
рабочее (0 ложных покрытий, проверяемые цитаты), но упёрся в доставку текстов
и формат счётных критериев. Требуется классификатор, выдающий проверяемые
атомарные суждения, а не связный текст.

## Решение

Классификатором входа недели назначается **Jev** (TypeSafe System One) —
модель типизированных суждений, подключаемая по MCP (`jev_classify`,
`jev_score`, `jev_check`, `jev_gate`, `jev_decide`). Полная логика —
`docs/jev-classification.md`: окно W−7…W, обязательная дословная цитата
(нет цитаты → `not_found`), `events[]` для счётных критериев, дедупликация
«одно событие — один критерий», короборация Д9 ≥ 2 кластеров, carryover-кандидаты
Д2. Jev готовит только черновик (`calc/input/drafts/*.llm-draft.json`); вход
публикуется после построчной верификации редактором и проходит штатные ворота
(linkcheck, `validate`, `validateInputSources`) без исключений.

## Почему

Отвергнута автономная машинная разметка без верификации: ответственность за
вход — Methodology Editor, а правило «нет цитаты → not_found» без human-in-the-loop
давало на прогонах покрытие ниже порога публикации (q 0.421–0.744 против
0.907–1.0 у человека). Отвергнута замена Jev на обычный LLM-генератор длинного
текста: задача — классификация и оценки по шкале, формат суждений с доверием
и схемой проверяется кодом, генерация прозы — нет. Отвергнуто отнесение
классификации к воротам публикации (вместо порогов `classifyPublication`):
классификатор готовит данные, а не принимает решение о публикации — это
сломало бы детерминизм R11–R15.

## Последствия

- Классификатор вне репозитория (MCP, снаружи): в коде остаётся ноль
  npm-зависимостей; сбой/недоступность Jev тормозит подготовку черновика,
  но не расчёт и не публикацию уже подготовленного входа.
- Отбор источников и `covered:false` остаются за человеком — менять это
  можно только новой версией governance §10.1.
- Критерии успеха пилота (index ±2 и тот же state, экономия ≥ 50 %)
  зафиксированы до старта; решение о промышленном режиме — по форвард-прогону,
  результаты — в `docs/llm-pilot-journal.md`.
- Правила классификации (§4 `docs/jev-classification.md`) — производные от
  METHODOLOGY: изменение шкал и окна обязано синхронно править и логику
  классификатора, иначе черновик расходится с движком на воротах `validate`.
