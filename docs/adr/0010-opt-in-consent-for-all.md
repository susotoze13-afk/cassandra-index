# 0010. Согласие на регион: opt-in для всех до появления edge-слоя

## Контекст

Бриф различает юрисдикции: EU/UK и Россия — opt-in (регион не определяется до
согласия), US/остальной мир — opt-out (определяется автоматически, с
возможностью отключить). Сайт полностью статический: нет бэкенда, нет
edge-слоя, нет IP-геолокации — детект региона идёт по часовому поясу
(ADR 0002), а юрисдикцию визита сервер определить не может.

## Решение

До появления edge-слоя действует **opt-in для всех посетителей**: регион не
определяется и не сохраняется до явного согласия. При первом визите показывается
неблокирующий toast «Мы определили ваш регион для удобства [Изменить]»;
согласие (`region_consent: granted/denied` + timestamp) хранится в localStorage
без привязки к IP. Отказ или отсутствие согласия — глобальный вид, toast
повторяется на следующем визите. Ветка opt-out для юрисдикций вне EU/UK/РФ
зафиксирована в `docs/governance.md` §5.4 как обязательное поведение
будущего edge-слоя.

## Почему

Без бэкенда невозможно отличить EU-визит от US-визита, а гадать по часовому
поясу юрисдикцию — неверно в обе стороны. Реализовать
opt-out «для остального мира» честно нельзя, значит единственное поведение,
не нарушающее бриф ни для одной юрисдикции, — opt-in для всех; это строже, чем
требует бриф для US (допущение A4). Отвергнуто сохранение согласия в cookie —
проект без cookie-аналитики, localStorage достаточно и прозрачнее. Отвергнуто
определение региона до согласия «только в памяти» — нестабильно и непроверяемо.

## Последствия

Посетитель без согласия видит глобальный индекс — это осознанная потеря
персонализации ради приватности. Toast обязан быть неблокирующим и
доступным (a11y-правила проекта). При появлении edge-слоя потребуется
дополнение справочника регионов детектом юрисдикции и включение ветки opt-out;
согласие пользователя при этом сохраняется.
