# 0003. Одностраничная структура с якорной навигацией и шестью модулями

## Контекст

IA PRD §3 требует пять разделов навигации (Overview, Regions, Trend, Methodology, Sources & history) плюс отдельную страницу политики приватности. Варианты: многостраничный сайт или одна `index.html` с якорными секциями. Референс — прототип `cassandra-index-prototype.html`, собранный одной страницей.

## Решение

Сайт — одна `index.html` с якорными разделами + отдельная `privacy.html`. Код делится на шесть модулей с явными границами: `data` (снапшоты, схема), `i18n` (словари, плюрализация, даты), `risk` (пороги §10, тона палитры), `region` (справочник, детект, хранение), `render` (вся DOM-разметка), `app` (оркестрация, URL `?week=`, демо-подмена). Чистые функции `i18n`, `risk`, `region.search/detect`, `data.validate` — единственные швы для `node --test`.

## Почему

Рассмотрена многостраничность: отвергнута — дублировала бы i18n (словари и языковое состояние пришлось бы разделять и синхронизировать между страницами), усложнила бы мгновенное переключение языка без перезагрузки (R67) и состояние «текущая неделя» между переходами. Навигация якорями сохраняет IA без роутинга. Шесть модулей выбраны вместо одного большого скрипта, потому что требование «тесты без DOM и зависимостей» (node --test) требует изолированных чистых функций; модуль `render` специально отделён от `app`, чтобы логика оставалась тестируемой.

## Последствия

Одна страница растёт со всеми секциями в одном DOM — компенсируется content-visibility/lazy ниже фолда (R72), но бюджет первого HTML остаётся под давлением. Переход на многостраничность позднее потребует выноса общего шелла (header/i18n/данные) и ломки шва `app ↔ render`. Любая новая логика, попадающая в `render` или `app`, автоматически оказывается вне покрытия тестов — правило «тестируем только чистые модули» надо защищать ревью.
