# 0062. Публичный API-контракт и числовая развёртка «почему индекс такой»

**Дата:** 2026-10-18
**Статус:** реализовано (2026-10-18): `calc/contributions.js`,
`calc/public-contract.js`, `docs/api.md`, `data/public/{regions,criteria,methodology}.json`,
`data/public/weeks/<неделя>.json`, `data/public/schema/v1/*.json`; тесты
`tests/public-contract.test.js`, обновлён `tests/public-export.test.js`
**Номер:** 0062

## Контекст

Публичный слой `data/public/` отдавал ряд недель (`index.json`, `latest.json`,
CSV, `trend.svg`), changelog и дайджест, но не отвечал на два вопроса.

1. **«Почему индекс такой?»** У недели были только редакционные драйверы —
   три сюжета с `contribution: high|medium|low`. Числа вклада в пунктах индекса
   не было, критериев внутри драйвера тоже; журналист получал «индекс 64» без
   объяснения, аналитик — не мог войти в модель.
2. **«Что это за источник?»** Не было справочников регионов и критериев, не
   было схемы данных, не было понедельных файлов для кеша и embed. Потребитель
   разбирал `index.json` эвристикой.

Данные для обоих ответов уже есть: `calc/engine.js` считает скоры девяти
драйверов, `js/criteria.js` держит 46 критериев, `data/regions/reference.json` —
обе таксономии, `calc/params.js` — веса и пороги.

Отдельный конфликт: ADR 0045 закрывал веса, CAP, `k` и пороги состояний —
для **публичного интерфейса**. Пункт «methodology.json — веса, пороги»
требует раскрытия для **машинного потребителя**.

## Решение

### 1. Модельная развёртка — отдельным полем

Редакционные `drivers` (три сюжета) не трогаются: их `contribution` —
категория, а не число. Рядом появляется `driver_breakdown` — девять драйверов
движка Д1…Д9:

```json
{
  "id": "D1",
  "name": { "ru": "…", "en": "…" },
  "score": 0.574,
  "confidence": "medium",
  "weight": 0.1175,
  "weight_effective": 0.13,
  "covered": { "criteria": 5, "total": 6 },
  "contribution_pp": 11.3,
  "top_criteria": [{ "id": "D1.4", "value": 1, "contribution": 0.2, "share": 0.348, "…": "…" }]
}
```

- `contribution_pp` — вклад драйвера в опубликованный индекс в п.п.; сумма
  девяти вкладов равна `index`, остаток округления до 0.1 отдан драйверу с
  наибольшим модулем вклада.
- `top_criteria` — до трёх покрытых критериев драйвера по модулю вклада;
  `share` нормирован внутри драйвера.
- Пересечения (`intersection`, ADR 0046) в top-3 не попадают — движок их тоже
  не считает.

**Как считается вклад.** Не второй расчёт: `aggregateDrivers` дополнительно
возвращает `shares` (вклад каждого драйвера в агрегат до насыщающей кривой,
`Σ shares = I_agg`) и `weights` (эффективные веса). Публичная развёртка
масштабирует `share` на опубликованный индекс: `share × index / I_agg`. Д8
входит отрицательным членом, Д9 — уже ограниченным `U` (§4.3.5). Так
`contribution_pp` — это разложение опубликованного числа, а не гипотеза о нём.

### 2. Водопад «прошлая неделя → вклады → эта неделя»

```json
{
  "from": { "week": "2026-10-11", "index": 56 },
  "to": { "week": "2026-10-18", "index": 64 },
  "steps": [{ "driver": "D1", "contribution_pp": -7.2 }, "…"],
  "residual_pp": 2,
  "residual_reason": "saturation-inertia-coverage-rounding"
}
```

Шаги — разница `shares` двух недель, пересчитанная в п.п. через насыщающую
кривую. Остаток **не** размазывается по драйверам: инерция (§5.4), q-сжатие
(§5.3), лимит прироста Д9 (§4.3.4) и округление — механика модели, и
приписывать её драйверу было бы ложью. Сумма шагов плюс `residual_pp` равна
`to.index − from.index` по построению.

Водопад не строится через границу версий методологии (демо-недели 08-02…08-23 —
1.0) и при отсутствии архива `calc/input/<неделя>.json`: `null`, а не нули.

### 3. «Что бы изменило оценку»

`what_would_change` — ближайшие пороги шкалы и до трёх критериев с наибольшим
плечом. Метод `criterion-zeroed`: сигнал одного покрытого критерия обнуляется,
прочие равны, прогон без контекста цепочки. `impact_pp` — сдвиг внутреннего
значения; `crosses_state` — приближение по `index + impact_pp`;
`breaks_driver` — потеря критерия делает драйвер слепым (покрытие ниже 50 %).

### 4. Справочники, понедельные файлы и схемы

- `regions.json` — обе таксономии (id, названия, ISO-страны, админцентр),
  источник — `data/regions/reference.json`;
- `criteria.json` — 46 критериев (драйвер, шкала, направление, ru/en
  название и описание), источник — `js/criteria.js`; паритет с движком уже
  пинит `tests/methodology-criteria.test.js`;
- `methodology.json` — версия, веса, параметры агрегации, шкала состояний;
- `weeks/<date>.json` — одна неделя в конверте `cassandra-index-week`;
- `schema/v1/*.json` — JSON Schema draft 2020-12; `index`/`latest` ссылаются на
  `week.schema.json#/$defs/week`, а не дублируют его;
- `docs/api.md` — эндпоинты, поля, версии, лицензия, примеры.

Все файлы — производные: пишутся `node calc/public-export.js --write`, руками
не правятся, детерминированы (без timestamp).

### 5. Отношение к ADR 0045

ADR 0045 остаётся в силе для **UI**: страница «Методология» не показывает
формулы, веса, CAP и `k`. ADR 0062 открывает их в **машинном контракте**:
воспроизводимость расчёта — законная потребность API, а не баннер на главной.
Граница раскрытия сдвигается только для JSON, не для HTML.

## Почему

- **Отвергнуто: добавить `contribution_pp` в редакционные `drivers`.** Три
  сюжета недели не соответствуют девяти драйверам модели; число рядом с
  сюжетом выглядело бы как вклад в индекс, но им не было бы.
- **Отвергнуто: размазать `residual_pp` по шагам водопада.** Тогда водопад
  сходится всегда, но инерция и q-сжатие молча превращаются в «вклад Д4».
- **Отвергнуто: считать развёртку на сайте.** Сайт не знает `calc/` по
  конвенции; повторная реализация формул на клиенте разошлась бы с движком.
- **Отвергнуто: генерировать `criteria.json` из движка.** Описания и переводы
  живут в `js/criteria.js`; дублирование уже принято и пинится паритет-тестом.
- **Отвергнуто: публиковать `week.js` как контракт.** Внутренний формат сайта
  меняется вслед за рендером; контракт — только `data/public/*`.
- **Отвергнуто: отдельный REST-сервер.** Статические файлы на CDN дешевле,
  кешируются и не создают точек отказа; `Access-Control-Allow-Origin: *` уже
  отдаёт GitHub Pages.

## Последствия

- `calc/public-export.js --write` пишет 27 файлов вместо 6; `weekly-calc.yml`
  коммитит их тем же `git add -A`, отдельного шага не нужно.
- `buildDataset` получает третий необязательный аргумент `analyzeWeek`;
  старые вызовы без него дают пустую развёртку, а не ошибку.
- `aggregateDrivers` возвращает `shares`/`weights`, `buildDriversCore` кладёт
  `corr` в драйвер Д9 — additive, расчёт индекса не меняется.
- `contribution_pp` и `waterfall` считаются из архивных входов, поэтому
  пересчёт недели меняет и развёртку; фикстуры-пины обновляются вместе с
  публичным слоем (как и раньше для `index.json`).
- `tests/public-export.test.js` обновлён: `writePublicData` пишет больше файлов,
  паритет `index.json` идёт с `loadAnalysisFromDisk`.
- Новый `tests/public-contract.test.js`: справочники, развёртка, водопад,
  контрфактика и валидация всех файлов минимальным JSON-Schema-валидатором.
- UI не меняется: блок «почему индекс изменился» на сайте — отдельная задача,
  данные для неё уже в контракте.
