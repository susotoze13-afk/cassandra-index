## Контекст

В репозитории не было расчётного кода; требовался пайплайн, который редактор запускает из CLI, который воспроизводит неделю через полгода (R01.3), и который тестируется без DOM и сети (R07i). Сайт (`js/`) при этом живёт по своим правилам: бандлы, window, браузер.

## Решение

Расчётное ядро выделяется в отдельный каталог `calc/` с жёсткими границами: `engine.js` — чистые формулы методологии (единственный тестовый шов); `params.js` — единственный источник численных параметров (PARAMS + `list()`); `calc/input/<неделя>.json` — закодированные сигналы недель и якорей, каждый файл несёт снапшот параметров; `calc.js` и `calibrate.js` — тонкие CLI без собственной логики. Маппинг входа → драйверы (`buildDrivers`) живёт в `calibrate.js` и переиспользуется `calc.js`, а не дублируется. Стек — Node ≥ 18, ноль зависимостей, ESM; `calc/` не публикуется на сайте.

## Почему

Отвергнут «всё в одном calc.js» — формулы неотделимы от парсинга и печати, тестировать можно только всё сразу, шов для тестов исчезает. Отвергнуто размещение формул в `js/` рядом с сайтом — модули сайта завязаны на `window`/DOM и бандлер; расчётному коду это чуждо, а перенос чистых формул в бандл-код запутал бы границы «сайт не знает про calc/». Отвергнуто хранение параметров внутри engine или только во входных файлах — без единственного `params.js` правка числа требовала бы синхронной правки в коде и в каждом входном снапшоте; снапшот параметров во входе нужен сам по себе для воспроизводимости (§10), но как копия, а не как источник. Отвергнута публикация `calc/` — читателю сайта расчётный код не нужен, а выкат ограничен `index.html/privacy/css/js/data`.

## Последствия

Смена любого числа — правка в двух местах: `params.js` (источник) и снапшот во входных файлах недель (воспроизводимость); забытое второе место — расхождение исторического следа. Дисциплина «вся логика в engine, CLI — тонкие» поддерживается вручную: соблазн добавить ветвление в `calc.js` при расширении (например, региональная атрибуция во входах) размывает шов для тестов. Якорные профили лежат в том же `calc/input/` — входы недель и калибровки единообразны, но смешение боевых и модельных данных требует дисциплины именования.
