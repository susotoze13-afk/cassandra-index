# ADR 0066 — Различение причин `verified:null` в forecast-ledger без нового поля

## Контекст

В `forecast-ledger.json` (ADR 0064) запись редактора несёт `verified: null` при двух разных ситуациях: неделя ещё не опубликована (`outcome.cluster = 'pending'`, `actualIndex = null`) либо git-история недели недоступна (gitProbe/дата не парсится — при этом outcome уже hit/miss, значения фактов есть). Прогон 2026-10-24-known-bugs-batch чинил документацию контракта и столкнулся с вопросом: как сделать причины различимыми для машинного потребителя.

## Решение

Различие кодируется парой `(outcome.cluster, actualIndex)` без изменения схемы: `outcome.cluster === 'pending'` + `actualIndex === null` → неделя не опубликована; любой иной outcome при `verified: null` → git-история недели недоступна. Трактовка документируется текстом: строка в `docs/api.md` (раздел forecast-ledger.json) и `description` поля `verified` в `FORECAST_LEDGER_SCHEMA` — только текст описания, структура схемы не меняется. `PUBLIC_SCHEMA_VERSION` остаётся 1.

## Почему

Рассмотрен вариант нового поля-перечисления причины (`unverifiedReason`) — отвергнут: он нарушает действующую договорённость «новых полей в существующих публичных файлах нет» (PUBLIC_SCHEMA_VERSION = 1, зафиксировано прогонами публичного слоя и пинится сторожами контракта), а польза от явного поля — косметическая: информация уже лежит в записи, достаточно её прочитать парой. Рассмотрен вариант «новое поле и подъём версии схемы» — отвергнут ещё и потому, что бамп версии ради одного nullable-поля стоит дороже, чем стоит проблема (внешних потребителей, читающих ledger, пока нет; смысл поля совпадает с уже читаемой парой). Зафиксировано решение пользователя (2026-10-24): чинить внутри существующей схемы, иначе отложить. Вышло — парой.

## Последствия

Машинный потребитель обязан трактовать `verified: null` через пару `(outcome, actualIndex)`, а не через само поле — это документированное, а не очевидное соглашение; описание схемы — единственное место с этой трактовкой. Если появится третья причина `null` без различимой пары, документирование сломается и потребуется новый ADR (или, наконец, поле с бампом версии). Пары `(outcome, actualIndex)` достаточно только пока причины остаются этими двумя — неприятное ограничение, принято сознательно.
