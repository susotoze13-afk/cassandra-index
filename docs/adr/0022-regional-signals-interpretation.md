# 0022. Трактовка входов агрегации региональных сигналов (engine.regionalSignals)

## Контекст

Бриф (2026-10-11): «у каждого региона свой набор событий… изменение должно от
региона к региону отличаться». Диагностика зафиксирована: у слепых регионов
(нет региональной атрибуции во входах — все 6 регионов всех пересчитанных
недель) дельта по построению равна глобальной: `delta = gInternal − prevGlobal`
— константа по всем регионам (engine.regionalIndex, ветка nReg ≤ 0). Формула
осознанная (сохраняет последнее отклонение от фона), ложь — в подаче дельты
как региональной. Задел (R03): редактор будущей недели размечает у критериев
`regions: ["europe", …]`, и регионы с атрибуцией считаются по сигналам.

Спека поручает агрегацию новому чистому шову `engine.regionalSignals(criteria,
regionIds, params) → { [regionId]: {nReg, eStruct, eDyn, hasDeescSignals,
iWith, iWithout} }` «строго по §7 METHODOLOGY.md». Однако §7 определяет модель
отклонения (формулы, экспозиция, зеркалирование, слепые регионы), но **не
определяет однозначно**, как из недельного входа критериев получить входы
агрегации. Этот ADR фиксирует трактовку; изменение трактовки потом — отдельное
решение. Пин тестов — `tests/regional-signals.test.js`.

## Решение

**Сигнал региона.** Покрытая (`covered: true`) запись критерия с непустым
`regions[]`, включающим регион. `nReg` — число таких записей за окно. Сигнал
с нормированным значением 0 считается (объём данных: зафиксированное наблюдение
«событий не было» — не отсутствие данных). «Независимость» сигналов на уровне
недели гарантируют ворота `validateSourceIndependence` (calc.js, ≥2 кластеров
или ≥1 primary|OSINT на покрытый критерий), действующие с той же даты
(2026-10-11), с которой возможна атрибуция, — а не эта функция.

**Глобальные по построению критерии.** §7: «Д2 и Д4 считаются в основном
глобальными; их региональный эффект идёт через экспозицию, а не через
дублирование сигнала. Д9 по умолчанию глобален, кроме Д9.3». Трактовка:
записи драйверов Д2, Д4 и подгрупп Д9 (кроме D9.3) в региональную агрегацию
**не входят**, даже если редактор проставил им `regions[]` — их эффект идёт
через `eStruct`/`eDyn`, а не через дублирование сигнала. Регион, у которого
только такие записи, остаётся слепым. Валидация входа их допускает (§7 говорит
«в основном», не «строго запрещено»), агрегация игнорирует.

**`hasDeescSignals`.** Есть покрытый сигнал региона по критерию с направлением
`deesc` (по CRITERIA) и нормированным значением > 0 — «подтверждённые
деэскалационные сигналы» §7 (подтверждение = покрытие с источниками, что требует
validate у любой покрытой записи).

**`eStruct`.** Структурная экспозиция (альянсы, границы, торговля, базы,
доктрины) недельный вход не несёт: §7 относит её к медленно меняющемуся
квартальному реестру, которого в пайплайне пока нет. До его появления —
нейтральное стартовое значение `PARAMS.regionEstructDefault = 0.5` для всех
регионов (нейтрально относительно γ = 0.5). Квартальный реестр экспозиций —
задел методологии 3.0.

**`eDyn`.** §7: «доля региональных сигналов в общем потоке за окно и близость
к активным событиям». Трактовка: `eDyn = nReg / N_covered`, где N_covered —
число всех покрытых критериев недели (общий поток). Компонента «близость к
активным событиям» из входа недели не выводится (география событий во входе не
несётся) — осознанное упрощение; при появлении событийной геоатрибуции
трактовка пересматривается отдельным решением.

**`iWith` / `iWithout`.** §7: «гипотетический индекс, рассчитанный по сигналам
региона тем же пайплайном §5» и «по всем сигналам без региона (тот же пайплайн
на оставшемся наборе)». Трактовка:

- `iWith` — шаги 2–6 §5 (агрегат драйверов + насыщающая кривая с
  калиброванным k) по набору «только сигналы региона» (остальные критерии
  считаются непокрытыми). Региону со слабым профилем сигналов соответствует
  низкий `iWith` — отклонение от контрфактического глобального фона уходит
  вниз; насыщенному региону — высокий.
- `iWithout` — тот же прогон по всем покрытым критериям недели **без** сигналов
  региона; сигналы других регионов в наборе остаются.
- Шаги 7–8 §5 (q-сжатие, инерция, Structural Break Override) **не
  применяются**: контрфакты внутри одной недели, предыдущего значения у
  гипотетики нет, а инерция §5.4 — свойство реального недельного цикла.
- Маппинг критериев → драйверы в гипотетических прогонах — то же ядро
  `buildDriversCore` (engine.js), что и у глобального пайплайна: тот же
  `normalizeCriterion`, порог покрытия драйвера и короборация Д9. Уверенность
  гипотетических драйверов — 'medium': `driverConfidence` входа относится к
  глобальной атрибуции недели, а не к контрфактическим наборам.
- Возвращаются внутренние float-значения (округление — только на выходе
  публикуемого индекса); клэмп ±regionClamp и зеркалирование шока остаются в
  `engine.regionalIndex`.

## Почему

- **Отвергнуто считать `iWith` по глобальному набору** (глобальные + региональные
  сигналы): тогда `iWith` совпадает с глобальным индексом и Δ_region вырождается
  в ноль — против буквы §7 («по сигналам региона»).
- **Отвергнуто применять инерцию/q-сжатие к гипотетикам**: у контрфакта нет
  предыдущего значения; протаскивать контекст цепочки в шов сломало бы его
  чистоту (сигнатура без ctx) без методологического выигрыша.
- **Отвергнуто отклонять `regions` у Д2/Д4/Д9 в validate**: §7 формулирует роль
  («в основном глобальные»), а не запрет; жёсткая ошибка ломала бы совместимость
  при будущем квартальном реестре экспозиций. Молчаливое игнорирование
  задокументировано здесь и пинится тестом.
- **Отвергнуто выводить eStruct из частоты атрибуции**: структурная экспозиция
  по определению §7 меняется медленно и не является функцией одной недели;
  подмена её недельной статистикой давала бы шум вместо структуры.

## Последствия

- Недели без атрибуции считаются байт-в-байт как раньше: `regionalSignals`
  возвращает `{}`, все регионы идут в слепую ветку, числа цепочки 08-30…10-04
  (и опубликованные снапшоты) не меняются.
- Флаг `background` доводится до `regions.js`/`region-*.js` и до контракта
  сайта (опциональное поле, дефолт false); сайт при `background:true` не подаёт
  дельту как региональную (подача — таск 03).
- Валидация входа требует `regions ⊆ REGION_IDS` (6 идентификаторов из
  js/data.js, единый источник — engine.js импортирует его оттуда); неизвестный
  id — ошибка с полным whitelist в сообщении.
- При появлении квартального реестра структурных экспозиций и событийной
  геоатрибуции трактовки `eStruct`/`eDyn` пересматриваются отдельным ADR;
  тесты `tests/regional-signals.test.js` тогда меняются осознанно.
