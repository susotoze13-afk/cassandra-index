# 0025. Версия точки тренда = версия записанного снапшота недели

## Контекст

Тренд строит серию из недельных точек и уже умеет отсекать несопоставимые
версии: `selectMethodology` показывал только точки методологии, на которую
ссылался жёстко. При перевыпуске всей цепочки 08-30…10-11 под 3.0 все
существующие точки становятся «2.0», и жёсткое совпадение скрыло бы серию
целиком.

## Решение

Точка тренда принадлежит **той версии, с которой записан снапшот этой недели**
(версия — свойство недели, а не серии). `selectMethodology(points, version)`
получает текущую версию (по умолчанию из `PARAMS`) и сравнивает точки с ней;
`summaryTextV2` и подпись «за N недель» считают точки текущей версии.
`trendSegments` (маркер разрыва методологии) остаётся версионно-агностичным.

## Почему

- **Отвергнуто жёсткое сравнение с '2.0'**: после перевыпуска цепочки под 3.0
  все точки — «3.0», фильтр вернул бы пустую серию — визуальный регресс.
- **Отвергнута «версия всей серии целиком»** (одна версия на тренд, а не на
  точку): стёрла бы реальный разрыв v1.0/v2.0/v3.0, тогда как несопоставимость
  редакций — факт, который тренд обязан раскрывать сегментами, а не прятать.
- **Отвергнуто считать «за N недель» по календарному спану**: спан включает
  демо-недели v1.0, которые в серию не входят; счёт по опубликованным точкам
  текущей версии честнее.

## Последствия

- Подпись «за N недель» зависит от числа точек текущей версии, а не от окна —
  при неполной серии (пропущенная неделя) число меньше календарного.
- Разрыв версий виден маркером `trendSegments`, но не через отсечение всей
  серии; при появлении v4.0 дефолт версии надо будет менять так же явно, как
  кноб методологии (ADR 0024).
- Демо-недели 08-02…08-23 (v1.0) на тренде по-прежнему не показываются —
  поведение сохраняется.
