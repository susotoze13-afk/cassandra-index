# Классификация источников Jev — логика пайплайна

**Версия:** 0.2 (проектная)
**Дата:** 2026-10-04 (обновлено 2026-10-11 — схема черновика v2, шов `calc/classify.js`)
**Статус:** пилот. Подключён как классификатор входа недели; первое решение
о промышленном использовании — после форвард-прогона (критерии зафиксированы
заранее, см. §7).
**Связанные документы:** `docs/governance.md` §10.1 (правила машинной разметки),
`docs/llm-pilot-journal.md` (результаты ретро-прогонов и формат записи форварда),
`METHODOLOGY.md` (формулы и шкалы), ADR `docs/adr/0018-jev-source-classification.md`
(границы роли Jev и механический шов).

## 1. Назначение и границы

**Что классифицируется.** Источники недели — тексты статей, отобранные
человеком для расчётного окна (список R55 в `calc/input/<неделя>.json`).
Jev относит каждый текст к критериям D1…D9 (45 критериев) и готовит черновик
значений (`value`/`events[]`) с обязательной дословной цитатой; слепоту
критерия (`covered:false`) решает редактор, а не классификатор.

**Зачем.** Ручная разметка 45 критериев по десяткам статей — самое узкое
место еженедельного цикла. Цель — экономия времени редактора ≥ 50 % без
потери качества входа.

**Чего Jev не делает (жёсткие границы):**

| Запрещено | Почему |
|---|---|
| Отбирать или добавлять источники самостоятельно | Защита от ИО: отбор источников — только человек (`governance.md` §3, §10.1) |
| Решать слепоту критерия (`covered: false` + аттестация) | Решение и аттестация — только редактор (`governance.md` §10.1) |
| Менять формулы, параметры, пороги | Математика — `calc/engine.js` + `calc/params.js`, владелец — Methodology Editor |
| Писать/публиковать снапшоты, обходить ворота | Запись — только `calc/calc.js --write` после linkcheck и контракта `validate` |
| Заменять верификацию редактора | Публикуемый вход верифицируется построчно человеком |

Jev не двигает индекс ни на пункт: он готовит черновик разметки. Считает по
прежнему детерминированный движок на чистых функциях.

## 2. Роли

| Шаг | Кто | Что делает |
|---|---|---|
| 1. Отбор источников | Редактор | Формирует список R55 недели (id, URL, кластер A–F, `state_affiliated`, даты) |
| 2. Доставка текстов | Редактор / загрузка | Скачивает тексты; недоступные (401/403/406, JS-шеллы, DNS) докидывает сам — см. §5 |
| 3. **Классификация** | **Jev** | По каждому тексту: релевантные критерии, `value`/`events[]`, цитата, ссылка (без `covered` — правило 7) |
| 4. Верификация | Редактор | Построчно подтверждает/правит/отбрасывает; решает `covered:false`; решает carryover по Д2 |
| 5. Ворота | Код | `linkcheck` (ok/blocked/broken) + контракт `validate` из `js/data.js` |
| 6. Расчёт | Код | `buildDrivers` → `aggregateDrivers` → снапшот (`calc/calc.js --write`) |

## 3. Схема черновика v2

Вход классификатора — один текст + список критериев недели; выход — записи
черновика (`calc/input/drafts/<неделя>.llm-draft.json`, `schema_version: 2`),
по одной на пару `(criterion, source)`:

```jsonc
{
  "schema_version": 2,
  "week": "2026-10-18",
  "generated_by": "jev",
  "items": [
    {
      "criterion": "D3.3",
      "source_id": "euractiv-sanctions-extend",   // id из набора R55 недели
      "url": "https://…",
      "kind": "event",                            // event | background | not_found
      "events": [0.2],                            // только для счётных (§4.2); иначе поля нет
      "quote": "дословная цитата из текста",
      "event_date": "2026-09-14",
      "cluster": "A-mainstream",
      "review": { "flag": true, "reason": "одно событие в трёх критериях" },
      "carryover": false                          // только D2.*, кандидат на перенос
    }
  ]
}
```

Правила схемы:

- `events[]` **не** сворачивается в `value` в черновике — нормировку
  `value = min(1, Σ sev / CAP)` выполняет движок (ADR 0007);
- `not_found` — единственная форма «не нашёл»; `covered:false` в черновике
  не встречается (правило 7) — слепоту дописывает редактор;
- `review.flag: true` и `carryover: true` — долг редактора, а не значение;
- `cluster` обязан быть из whitelist A–F; `quote` и `url` обязательны для
  любого `kind`, кроме `not_found`.

Инструменты Jev (MCP, типизированные суждения):

- `jev_classify` — релевантность текста критерию и его тип (событие окна /
  тянущийся фон / нерелевантно);
- `jev_score` — значение критерия на шкале из `METHODOLOGY.md` (для счётных
  критериев — составление `events[]`, см. правило 3);
- `jev_check` — самопроверка: подтверждает ли цитата выставленное значение;
- `jev_gate` — сводный вердикт по записи перед уходом черновика редактору;
- `jev_decide` — спорные случаи (дублирование события, кластер Д9) с явным
  указанием сомнения для ревью, а не скрытого выбора.

Форма ответа у всех одна: типизированное суждение + доверие. Ответ без схемы
или без цитаты в черновик не принимается.

## 4. Правила классификации

1. **Окно W−7…W включительно.** Считается дата события, а не дата публикации
   статьи. Событие вне окна → нерелевантно.
2. **Дословная цитата обязательна.** Нет проверяемой цитаты в тексте →
   запись `not_found`, а не значение. Правило работает как отсев от
   галлюцинаций; его цена (потеря покрытия) осознана и компенсируется
   доставкой текстов (§5).
3. **Счётные критерии эмитятся как `events[]`** с весами `{0.2, 0.5, 1.0, 2.0}`
   и цитатой на каждое событие — не скалярным `value` (шкалы несовместимы;
   системная ошибка прогона 1, исправлено в промпте v2).
4. **Дедупликация: одно событие — один критерий.** Одно событие, засчитанное
   в трёх критериях, помечается спорным и уходит на ревью, а не засчитывается
   молча.
5. **Д9 — короборация ≥ 2 кластеров** из whitelist A–F (`governance.md` §3).
   Решение по одному кластеру — только с пометкой «на ревью».
6. **Д2 — `carryover-candidate`.** Если событий окна по Д2 нет, классификатор
   помечает критерии D2.1–D2.5 как кандидаты на перенос с прошлой недели;
   решение о переносе принимает редактор (конвенция AGENTS.md, применена в
   неделях 09-27 и 10-04).
7. **`covered:false` не эмитится Jev.** Не нашёл подтверждение → `not_found`;
   слепота критерия и аттестация — поля редактора.
8. **Источник вне набора не используется.** Цитата и ссылка обязаны указывать
   на запись входного списка R55.
9. **Дословность цитаты проверяется машинно.** Конвертер (§6.1) находит
   `quote` в тексте источника из предоставленного корпуса; не нашёл — запись
   **отвергается** (не «на ревью»), вход не эмитится. Нормализация
   пробелов/дефисов/кавычек — компаратором; усечённые цитаты и перефраз
   воротами не решаются, это граница редактора.
10. **Неразрешённая пометка блокирует конвертацию.** Пока в черновике есть
    хоть один `review.flag: true` или `carryover: true`, вход не эмитится:
    «на ревью» — долг редактора, а не значение.

## 5. Доставка текстов — известное узкое место

Ретро-прогон 2 (неделя 2026-09-20, 74 URL): полноценные тексты получены
примерно по трети источников; reuters.com отвечает 401 даже на главной,
часть доменов закрыта Cloudflare (403), у части DNS среды не резолвится.
Схема гибридная: **недоступные тексты докидывает редактор** — без этого
правило «нет цитаты → not_found» даёт покрытие, недостаточное для публикации.
Блокер пилота — доставка текстов, а не качество классификации на доступных
(0 ложных покрытий на двух прогонах подряд).

**Разделение труда (зафиксировано).** Сетевой фетч — не задача классификатора
и не часть пайплайна: он источник недетерминизма (401/403/мёртвый DNS) и
провалов ретро-прогонов. Jev — **чистый потребитель предоставленного корпуса**:
человек скачивает тексты в `calc/input/drafts/texts-<неделя>/`, классификатор
не ходит в сеть вообще. Это даёт детерминированный вход, воспроизводимый пилот
и честный замер «сколько текстов дал человек». Нет текста → `not_found`.

## 6. Ворота: черновику нет поблажек

Черновик Jev конвертируется в штатный вход `calc/input/<неделя>.json` и
проходит **те же** ворота, что и ручной ввод, без исключений:

1. `linkcheck` — классификация исхода каждой ссылки (`ok` / `blocked` /
   `broken`), запись отклоняется при `broken` (ADR 0012);
2. контракт `validate` из `js/data.js` — 45 критериев, ровно 3 драйвера,
   12 точек тренда, корректные состояния;
3. `validateInputSources` — схема R55 (cluster_id по whitelist,
   `state_affiliated`, обязательные даты).

При провале любого ворота диск не тронут. Ускорение не покупается
ослаблением проверок.

### 6.1. Механический шов `calc/classify.js`

Jev — внешний MCP, у репозитория ноль зависимостей, поэтому `classify.js`
сам Jev не вызывает: он **чистый конвертер** «черновик v2 → штатный вход»,
вызывается вручную (агент/редактор), в CI не встроен. Вызов `jev_*` — отдельный
внешний шаг, порождающий черновик. Публикуемый вход эмитится только при
прохождении ворот §6 + правил 9–10.

Чистые функции (по образцу `engine.js`/`renderGlobal`, тестируемо без сети и
без Jev):

- `normalizeText(s)` — нормализация пробелов/дефисов/кавычек для поиска цитаты;
- `quoteFound(quote, text, opts)` — дословная проверка (правило 9);
- `validateDraft(draft)` → `errors[]` — схема v2 (`schema_version`, обязательные
  поля, `cluster` из whitelist, `events` из `{0.2,0.5,1.0,2.0}`);
- `reviewQueue(draft)` → неразрешённые `review.flag`/`carryover` (правило 10);
- `toInput(draft, r55Sources, corpusDir)` → `{ input, report, errors }` — ворота
  §6 + правила 9–10, слияние записей по критерию, источники из набора R55;
- `loadDraft(path)` + тонкий CLI.

Артефакты одной недели:

| Артефакт | Путь | Роль |
|---|---|---|
| Черновик v2 | `calc/input/drafts/<неделя>.llm-draft.json` | pre-review, append-only по неделям |
| Корпус текстов | `calc/input/drafts/texts-<неделя>/` | предоставлен человеком |
| Сырой вход | `calc/input/pilot-llm-<неделя>.json` | для замера ±2 (прогон без записи) |
| Верифицированный вход | `calc/input/<неделя>.json` | после построчного ревью; идёт в `--write` |

Тест — `tests/classify.test.js`: неразрешённая пометка → вход не эмитится;
`quote` не найден в корпусе → отказ; `events[]` не нормируется в `value`;
`not_found` → `null`; merge нескольких записей одного критерия.

## 7. Статус пилота и критерии успеха

Зафиксировано заранее (`docs/llm-pilot-journal.md`):

- итоговый index — расхождение с ручной разметкой **±2** и **тот же state**
  публикации;
- **экономия времени редактора ≥ 50 %** на 2–3 подряд форвард-неделях;
- ретро-прогоны (09-27, 09-20) — отсев по покрытию, диагностика в журнале
  (формат events[], окно, дедупликация — исправлены в промпте v2);
- решение о промышленном использовании — после первого форвард-прогона
  в гибридном режиме; результаты — в журнале пилота.

**Как меряется форвард-прогон (зафиксировано).** Прогон — на ближайшей ещё
не посчитанной неделе, гибридно: один редактор, Jev читает предоставленный
корпус, редактор верифицирует построчно. Замеры:

- **index/state ±2** — сырой черновик (`pilot-llm-<неделя>`) прогоняется через
  `runWeek` **без записи** и сравнивается с верифицированным входом той же
  недели (та же методология, что в ретро «черновик vs опубликованное»);
- **экономия времени** — посегментный хронометраж редактора
  (фетч → ревью-классификация → ворота/расчёт) на пилотной неделе против одной
  контрольной ручной недели; цифра берётся с одной и той же рукой, иначе
  недействительна;
- начинать с одной недели; при непройденном ±2 — правки в промпт/схему,
  а не в метрики.

Отчёт по факту, а не по обещаниям: до форвард-прогона числа экономии
и совпадения не публикуются. Формат записи — шаблон в
`docs/llm-pilot-journal.md`.

## 8. Аудиторский след

- Черновики классификации — `calc/input/drafts/*.llm-draft.json` (append-only
  по неделям, alongside входа);
- корпус текстов — `calc/input/drafts/texts-<неделя>/`; сырой исполняемый вход
  пилота — `calc/input/pilot-llm-<неделя>.json` (для замера ±2, без записи);
- журнал пилота — `docs/llm-pilot-journal.md`;
- публикуемые пересчёты — `data/audit.jsonl` (штатный след `calc/audit.js`);
- спорные решения классификатора попадают в черновик с пометкой «на ревью»,
  а не в принятые значения.
