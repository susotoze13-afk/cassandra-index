# Журнал калибровки — Cassandra Index, параметр k

- **Дата прогона:** 2026-09-21, Autopilot-прогон (таск 03 «Якорные сценарии и калибровка»)
- **Кто:** исполнитель таса 03 расчётного пайплайна (субагент Autopilot)
- **Что:** первый рабочий проход калибровки параметра насыщающей кривой k (§5.2) на якорных профилях §9 по протоколу §10.1
- **Почему:** стартовые параметры «до калибровки» (§10.1) не давали аудиторного следа; методология требует подобрать k на якорях и зафиксировать результат
- **Воспроизведение:** `node calc/calibrate.js` (детерминировано, ноль зависимостей)

## Метод

1. **Якорные профили** — `calc/input/anchors/*.json`, 6 штук, каждый проходит `validate` таска 01. Это **модельные профили для калибровки шкалы, не архивные реконструкции**: сигналы закодированы по публично известным событиям (открытые обзоры, Wikipedia), шкалы — по градациям методологии (порядковые 0 / 0.33 / 0.67 / 1, бинарные 0/1, счётные кратны 0.2).
2. **Rolling-origin** (§10.1, история 10): ранние якоря **выбирают** k, поздние — **только проверка** (в выборе не участвуют):
   - select: рутина 2010-х [0–20], санкционные/прокси 2018 [21–40], Крым-2014 [41–60], Грузия-2008 [61–80]
   - verify: февраль-2022 [81–96], Карибский-1962 [97–100]
3. **Сетка k:** 1.00–4.00, шаг 0.05 (61 точка). Каждый профиль прогоняется через `calc/engine.js` (`aggregateDrivers`) с перекрытым k, базовые параметры — `calc/params.js`.
4. **Критерий выбора:** среди k, где все select-якоря попали в кластеры, выбирается максимум минимального запаса (запас = расстояние до ближайшей границы кластера, пункты индекса); при равенстве — меньший k. Правило максиминной робастности, не подгонка под конкретные точки.

| Санкционные/прокси 2018 (`proxy-sanctions-2018`) | select | 0.132 | **32** | 21–40 | попадание (запас 8) |

| Февраль-2022 (`feb2022`) | verify | 0.775 | **91** | 81–96 | попадание (запас 10) |
| Карибский-1962 (`cuban-1962`) | verify | 0.994 | **99** | 97–100 | попадание (запас 2) |

- Выбор на ранних якорях: все select-якоря попадают при k ∈ [1.15, 2.90]; максиминный запас 8.0 п. достигается при k = 1.95 (равный запас при 2.00 — по правилу tie-break выбран меньший k). При k ≥ 2.95 Крым-2014 выходит за 60, при k ≤ 1.10 Грузия-2008 не достаёт 61.
- Верхний кластер 97–100 при k = 1.95 достигается **только** Карибским профилем (февраль-2022 — 91). Рутина — 8, не выше 20. Выполнены оба ограничения §5.2.
- Карибский профиль упирается в лимит прироста от Д9 (§4.3.4): без лимита индекс был бы ~99.9, с лимитом — 99.4 → публикуется 99. Верх кластера 97–100 намеренно достижим только экстремальной комбинацией (§5.2).

## Допущения и открытые места (аудиторский след)

1. **Якорные профили — модельные**, закодированные по публично известным событиям; это не архивная реконструкция наблюдений. Полный исторический бэктест 1962–2022 на реальных архивных входах **остаётся открытым вопросом №1 методологии** — этот прогон его не закрывает, а фиксирует первую калибровку шкалы.
2. **Профили — одиночные недели.** Инерция (§5.4) и q-сжатие к предыдущему внутреннему значению (§5.3) применяются только при наличии прошлой недели; якоря прогоняются без контекста (`prevInternal = null`), то есть измеряют «мгновенную» картину недели. Это сознательное допущение модельных профилей.
3. **Д8.4 (интенсивность деэскалации, §4.2)** по методологии опирается на независимый счётчик «≥ 3 окон снижения интенсивности». Для одиночной недели якоря счётчик окон неприменим: Д8.4 закодирован по интенсивности самой недели профиля. Многооконная персистентность — состояние недельного цикла и должна поддерживаться в calc.js (как персистентность Structural Break Override).
4. **Воспроизводимость пересчёта.** Входные файлы недель (включая якоря) несут поле `params: "calc/params.js"` — **ссылку на снапшот параметров, а не инлайн-копию** (решение спецификации, R01.3). Поэтому пересчёт старых входов новыми параметрами невоспроизводим без фиксации версии params.js; воспроизводимость обеспечивается git-историей и версией методологии в снапшоте, а не самим файлом входа.
5. **q и null-драйверы.** В знаменателе глобального коэффициента покрытия q (§5.3) для драйверов без записи уверенности используется c = 0.7 («medium») по умолчанию. В якорных профилях уверенность задана явно для всех драйверов (Д9 — medium по §4.3.1, остальные high), так что q = 1 и на результат калибровки это не влияет; оговорка важна для будущих входов с пробелами.
6. Драйвер Д9 в engine агрегирует подгруппы без учёта направления (§4.3); в профилях деэскалационная подгруппа Д9.7 потому закодирована 0, чтобы не смешивать направления.
7. Калибровано только k. Прочие калибруемые по §10.1 параметры (порог резервного триггера critical mode, пороги покрытия, гистерезис, коэффициенты corr Д9, порог severity) в этом прогоне не затрагивались и остаются стартовыми — до отдельного исследования.

α = 0.5, λ = 0.6, ρ = 0.25, U_abs = 0.025, γ = 0.5, κ = 0.85, β↑ = 0.9, β↓ = 0.5, override 0.8/0.2 на 2 недели, шкала уверенности cᵢ (1.0 / 0.7 / 0.4), веса драйверов, пороги состояний §9. Все они проверены на устойчивость ±20 % (таблица выше) и признаны не критичными для якорных попаданий.
