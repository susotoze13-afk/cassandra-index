# Региональные гипотетики §7: порог 50 % обнуляет iWith у покрытых регионов

**Подготовлено:** 2026-10-19
**Статус:** решение принято (2026-10-24): вариант E реализован — в региональных
гипотетиках §7 драйвер покрыт при ≥1 покрытом критерии (`PARAMS.regionHypothesisThreshold
= 1e-9`), forward-only с `PARAMS.regionHypothesisFrom = '2026-10-25'`; глобальный
индекс и опубликованная история не меняются. Записано в
`docs/adr/0065-regional-hypothesis-coverage.md`, пункт O10 закрыт (пересчёт истории
— O11 в `docs/preproduction-decisions.md`). Коммит — autopilot-прогон 2026-10-24.
Числа §4 получены одноразовым
прототипом (перегонка `calc/input/<неделя>.json` через функции движка с
подменой порога; после написания этого документа прототип удалён, шаги
воспроизведения описаны в §4). Исследование не переписывалось — реализация
проверяется `tests/regional-hypothesis.test.js`.

Вопрос владельца (2026-10-19): почему на неделе 2026-10-18 региональные
индексы russia-belarus (56) и ukraine-moldova (58) **ниже** остальных
регионов при идущей войне — вплоть до того, что middle-east (71) выше их
на 13–15 п.п.?

Ответ коротко: региональные сигналы этих регионов действительно учтены — но
вычисленная по ним гипотетика `iWith` схлопывается в 0 из-за порога покрытия
50 %, унаследованного от глобального расчёта §4.2. Регион получает штраф под
глобальный фон −8 и −7 п.п. Документ фиксирует механику на реальных числах,
два варианта решения и рекомендацию.

## 1. Симптом (реальные данные 2026-10-18, v2, 12 регионов)

Глобальный индекс 64 (Δ +8). Публикованные региональные значения:

| Регион | Опубл. индекс | Δ | Регионов с сигналами? |
|---|---|---|---|
| **russia-belarus** | **56** | **0** | да (7 сигналов, background: false) |
| **ukraine-moldova** | **58** | **2** | да (5 сигналов, background: false) |
| baltic, balkans, eu-north-europe, south-caucasus | 61 | 5 | да (по 2 сигнала) |
| south-asia | 60 | 6 | да (3 сигнала) |
| central-asia, north-america, africa | 63 | 7–11 | да (по 1 сигналу) |
| east-asia | 61 | −1 | да (2 сигнала) |
| middle-east | 71 | 4 | да (18 сигналов) |

То есть два региона с крупнейшей концентрацией боевых действий —
именно самые низкие; сильнее всех отстаёт регион, чьи сигналы входят в
расчёт (background: false, т.е. слепой веткой §7 не считается).

## 2. Корень: механика на числах russia-belarus (§7, calc/engine.js)

Региональная гипотетика `iWith` — индекс, посчитанный «как если бы мир был
только этим регионом»: `regionalSignals` (engine.js:602) собирает
`withMap` из регионально атрибутированных критериев и зовёт
`hypotheticalIndex(withMap, …)` (:649). Тот идёт тем же пайплайном §5 —
`buildDriversCore` → `driverScore` → `aggregateDrivers`.

Атрибуты russia-belarus на 10-18 — 7 критериев: D1.2 (0.67), D1.4 (1),
D3.3 (0.6), D3.4 (деэск, 0.67), D5.1 (0.67), D6.3 (1), D7.4 (деэск, 0.33).
Разложено по драйверам (в скобках — доля покрытия от полного набора
драйвера, всего 4–6 критериев):

| Драйвер | Покрытие регионом | ≥ 50 % (`coverageThreshold`)? |
|---|---|---|
| Д1 | 2/6 = 33 % | нет → **null** |
| Д3 | 2/5 = 40 % | нет → **null** |
| Д5 | 1/4 = 25 % | нет → **null** |
| Д6 | 1/4 = 25 % | нет → **null** |
| Д7 | 1/4 = 25 % | нет → **null** |

`scoredCriteria` (engine.js:33–39) отбрасывает драйвер, если
`covered/total < PARAMS.coverageThreshold` (params.js:51, 0.5). Все пять
драйверов — null → `aggregateDrivers` даёт `I_agg = 0` → **iWith = 0**.

Дальше §7: `Δ = iWith − iWithout = 0 − 59.9 → clamp(±40) = −40`;
`shift = e_r · m · Δ`, где `e_r = 0.5·(eStruct + eDyn) = 0.5·(0.5 + 7/34) =
0.353`, `m = nReg/(nReg+5) = 7/12 = 0.583`. Итог: `shift = 0.353 · 0.583 ·
(−40) = **−8.2 п.п.**` — индекс региона на 8 пунктов ниже глобального фона.
Тот же ход для ukraine-moldova (5 сигналов): `−6.5 п.п.` (published 58 при
глобальном 64).

Порог 50 % в глобальном расчёте оправдан: там драйвер сверяется с полным
набором своих критериев (46-критериальный контекст), и «покрыт меньше
половины» = «данных нет». В региональном подмножестве подмножество по
построению разреженное (атрибуты — 1–7 критериев), и тот же порог делает
«часть данных» неотличимой от «нет данных», пока сигналы не сгустятся в
одном драйвере.

### Парадокс: больше сигналов — глубже штраф

`e_r = 0.5·(0.5 + nReg/nCovered)` и `m = nReg/(nReg+5)` растут с числом
сигналов региона. Пока `iWith` вырожден в 0, `Δ` сидит на клэмпе −40, и
рост nReg **увеличивает** |shift|: 2 сигнала → ~−6.5, 7 сигналов → −8.2.
Пересечение порога резко разворачивает знак. Штраф maximal именно у регионов
с умеренным, размазанным покрытием — то есть у регионов с реальными, но
распределёнными по драйверам данными (russia-belarus, ukraine-moldova,
baltic…), а middle-east (18 сигналов, драйверы выше 50 %) — выстреливает
вверх (iWith 68 > iWithout 52 → +6.5).

## 3. Почему это дефект переиспользования, а не свойство методологии

- METHODOLOGY §7 («Региональная модель») говорит лишь «тем же пайплайном
  §5» — порог для гипотетик явно не прописан; он приезжает молча из
  `buildDriversCore`. Следствие переиспользования, не задуманное правило.
- Д9 артефакт не задет: `aggregateD9` порог 50 % не применяет вовсе (null
  только при 0 покрытых) — вырождение возникает только в D1–D8.
- Глобальный индекс, q, классификация публикации, чувствительность — порог
  получают в своём, полном контексте и работают штатно. Артефакт живёт
  только в двух гипотетиках `regionalSignals` (engine.js:649–650 — единственные
  вызовы `hypotheticalIndex` в коде).
- Порог не прописан и в ADR 0022: трактовки «сигналы региона → сравнение с
  остальным миром» не задают, как считать гипотетику по разреженному
  подмножеству.

## 5. Варианты

### E (рекомендован): в гипотетиках порог = «≥1 покрытого критерия»

В двух вызовах `hypotheticalIndex` порог заменяется на эпсилон:

```js
// calc/engine.js, regionalSignals — только две гипотетики, больше ничего
const pRegion = { ...p, coverageThreshold: p.regionHypothesisThreshold ?? 1e-9 };
iWith: hypotheticalIndex(withMap, pRegion),
iWithout: hypotheticalIndex(withoutMap, pRegion),
```

+ `PARAMS.regionHypothesisThreshold = 1e-9` (единственный источник числа,
комментарий «в региональных гипотетиках драйвер покрыт, если есть хотя бы
один покрытый критерий»). Семантика: `covered = 0 → 0 < 1e-9 → driver null`
— драйверы без региональных сигналов остаются null, драйверы «из одного
критерия» начинают считаться. Обе ноги Δ (`with` и `without`) получают
одинаковое правило — сопоставимость сохраняется.

Почему безопасно:

- Шумозащиту уже делают сжатие `m = nReg/(nReg+5)` и `e_r ∝ nReg`: при
  одиночном сигнале `e_r ≈ 0.265`, `m ≈ 1/6` → |shift| ≤ ~2 п.п.
- D9 порог не задет; глобальная агрегация §5, q, k — не трогаются вообще.
- Никаких новых зависимостей, чистая подмена параметра.

Известные свойства E (зафиксировать в ADR 0065):

1. Одиночный сигнал value=1 → iWith=100 (africa, north-america), но сдвиг
   держится ≤ ~2 п.п. — m гасит.
2. central-asia: iWith=0 **легален** — единственный сигнал D3.4 деэскалационный
   (score 0 после α-клэмпа), гипотетика региона честно равна 0; результат
   63 = опубликованному. Не артефакт.
3. north-america при 4 сигналах имеет nReg=1: D2.5/D4.2/D4.3 исключены
   ADR 0022 (Д2/Д4 не агрегируются).
4. ukraine-moldova в E ≈ 64 (чуть ниже глобального): сигналы 10-18 включают
   деэскалацию (D3.4, D7.4, D8.3) → iWith < iWithout. Свойство данных недели,
   не артефакт.

### D (отклонён): вырождение iWith=0 → слепая ветка

При `iWith == 0` считать регион слепым (сохранять прошлое отклонение от
фона). В прототипе: russia-belarus, ukraine-moldova, baltic, balkans,
eu-north-europe, south-caucasus, central-asia → 65, т.е. **все схлопываются
в глобальный фон** (новые v2-регионы без истории отклонения не имеют);
east-asia 71, north-america 61, south-asia 63, africa 62 — держат только
старый офсет. Слабая ветка сделана для регионов **без данных**, не для
разреженных: она убивает дифференциацию ровно там, где данные есть.
Отклонён.

### Статус-кво (отклонён)

Артефакт остаётся: russia-belarus/ukraine-moldova продолжают публиковаться
на 7–8 п.п. ниже честного результата при любых будущих неделях с размазанным
покрытием.

## 6. Радиус и влияние на тесты

Правка — только `regionalSignals` (единственный потребитель
`hypotheticalIndex`; `regionalIndex` зовётся из week-step.js:128 на
региональной ветке). Глобальный индекс всех недель цепочки, q, states,
публикация, sensitivity, debt — не меняются.

- `tests/regional-signals.test.js:94` — пин `eu.iWithout === 0` в E станет
  ≈ 37.7 (D1.3 покрыт 1/6 ≥ эпсилон → S=0.2 → кривая ≈ 37.65); обновить пин
  и комментарий.
- `tests/regional-signals.test.js:100` — пин `af.iWith === 0` **останется**:
  D5 нет в весах теста (`weights = {D1: 1}`), нормировка даёт S=0.
- `tests/regions.test.js` — синтетические фикстуры `regionalIndex` с явными
  iWith/iWithout, не задеты.
- `tests/data.test.js` — точные пины реальных недель: при forward-only не
  трогаются; при региональном пересчёте обновляются региональные значения
  (это конвенция пинов, см. подводные камни AGENTS.md).

2. **Версия и охват** — выбор между:

## 8. Критерии приёмки

1. Перегонка 10-18: iWith russia-belarus и ukraine-moldova > 0 (прототип:
   77 и 60, ±1).
2. central-asia остаётся с iWith=0 — это легальный деэскалационный
   результат, а не вырождение; комментарий в ADR.
3. `af.iWith === 0` в юните не меняется; `eu.iWithout` пересчитан с
   комментарием.
4. Глобальный индекс каждой недели цепочки неизменен (51/42/43/56/47/46/56/64).
5. `node --test` зелёный.
6. При выборе пересчёта: записи в `data/audit.jsonl` по неделям, `data/public/*`
   пересобраны, паритет week.js ↔ части зелёный.
7. ADR 0065 написан со ссылкой на этот документ; строка O10 в
   `docs/preproduction-decisions.md` закрыта решением.
